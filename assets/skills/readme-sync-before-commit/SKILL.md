# readme-sync-before-commit — 커밋 전에 README 를 따라오게 한다

## 왜 만들었나

2026-10-16 확인: 10-06 ~ 10-16 의 기능 커밋 10개가 README 를 건드렸지만 **전부 `+1/-1`** — R-doc 이
테스트 수 한 줄을 고친 것뿐이었다. R-struct 를 13개 언어로 넓힌 날에도 README 에는
"R-struct — 컴포넌트 폴더/배럴 규칙" 이 그대로 남았다. 숫자는 기계가 지키는데 **설명은 지키는 장치가 없다.**
README 는 사람이 이 공장을 처음 볼 때 읽는 유일한 문서라서, 설명이 낡으면 새 기능은 없는 것과 같다.

## 절차 — 셋

### 1. 판정: README 에 적힐 변경인가

`git diff --cached --stat` 과 커밋 제목을 보고 아래 표로 가른다. 하나라도 "예" 면 2 로 간다.

| 예 — README 를 고친다 | 아니요 — 건너뛴다 |
|---|---|
| 게이트(R-*)를 더하거나, 차단/경고를 바꾸거나, 검사 범위(언어·확장자)를 넓힘 | 문서에 적힌 동작을 바꾸지 않는 버그 수정 |
| 훅·판정 모듈을 더하거나 빼거나 하는 일이 바뀜 | 내부 리팩터, 이름 정리 |
| 프리셋·스킬·에이전트를 더하거나 뺌, 설치 목록이 바뀜 | 시험만 고친 커밋 (시험 실행 방법이 그대로면) |
| `setup.sh`·`update-all.sh`·`uninstall.sh` 사용법이나 옵션이 바뀜 | `docs/exec-plans/`·`docs/audits/` 문서만 |
| 사용자가 켜고 끄는 스위치(`.harnessrc` 변수, 환경변수)가 생기거나 바뀜 | 소우주 전파 커밋 (공장 README 가 아니다) |
| 시험 실행 방법·러너가 바뀜 | |

애매하면 "처음 이 저장소를 보는 사람이 이 변경을 모르면 잘못 쓰게 되는가" 로 가른다. 그렇다면 "예" 다.

### 2. 고친다: 어디에, 얼마나

먼저 이번 변경의 이름(규칙 ID, 파일 이름, 스위치 이름)으로 README 를 찾는다 — 옛 설명이 이미 있으면 그 줄을 고치는 것이 새 문단을 다는 것보다 낫다. 옛 설명이 남은 채로 새 설명을 더하면 README 가 자기 자신과 어긋난다.

```bash
grep -n "R-struct\|check-structure\|STRUCT_LANGS" README.md
```

없으면 변경 종류로 절을 고른다 (README 의 실제 절 이름):

| 변경 | 넣을 곳 |
|---|---|
| 게이트 | `### harness 프리셋` 의 차단 표 / 경고 표 (한 줄 = 게이트 하나) |
| 세션 중 훅 | `#### 세션 중 실행 훅` 표 |
| 훅이 부르는 공용 코드 | `#### 판정 모듈` 표 |
| harness 스킬·에이전트 목록 | `### harness 프리셋` 머리의 목록 (DS:COUNTS 블록 위) |
| 헤르메스 기능 | `### hermes 프리셋` |
| 프리셋 추가·삭제 | `## 프리셋 목록` |
| 설치·갱신·제거 명령 | `## 빠른 시작` · `## 전체 프로젝트 일괄 업데이트` · `## 언인스톨` |
| 설치 방식(복사·공존·gitignore) | `## 동작 원리` 아래 해당 소절 |
| 시험 | `## 테스트` |

분량은 **한 줄에서 한 문단**이다. 왜 그렇게 정했는지·실측은 설계 문서나 계획서에 이미 있으니
README 에서는 무엇이 되는지와 어떻게 켜고 끄는지만 쓰고 근거 문서 경로를 단다. README 에 설계를 옮겨 적으면
두 곳이 갈라지기 시작한다.

**숫자는 손대지 않는다.** `<!--===DS:COUNTS:BEGIN===-->` 블록과 그 안의 "N종 · N개" 는 `doc_counts.py` 가
소스에서 계산하고 커밋 때 R-doc 이 고친다. 블록 **밖**에 같은 숫자를 쓴 곳이 있으면(예: "스킬 5종") 숫자를 지우고
이름 목록만 남기거나 블록 값과 맞춘다 — 블록 밖 숫자는 아무도 갱신하지 않아 반드시 낡는다.

### 3. 같은 커밋에 넣고, 판정을 남긴다

README 를 코드와 **같은 커밋**에 스테이지한다(`git add README.md`). 따로 커밋하면 "기능은 있는데 README 에 없는" 구간이 히스토리에 생긴다.

커밋 메시지 본문에 한 줄 남긴다 — 판정이 기록에 있어야 빠뜨림과 "해당 없음" 이 구분된다.

```
README: harness 프리셋 차단 표 R-struct 줄 · 판정 모듈 표 iface 확장자 갱신
```
```
README: 해당 없음 — 내부 리팩터, 문서에 적힌 동작 불변
```

## 하지 않는 것

- **소우주 README 를 고치지 않는다.** 이 스킬은 공장 README 만 본다. 소우주의 README 는 그 프로젝트의 것이다.
- **README 를 백과사전으로 만들지 않는다.** 표에 한 줄, 혹은 짧은 문단. 상세는 링크.
- **R-doc 이 할 일을 하지 않는다.** 숫자 블록 안을 손으로 고치면 다음 커밋에서 기계가 덮는다.

## 관련

- `pre-commit-measure` — 같은 자리(커밋 직전)에서 **동작 주장을 잰다.** 이 스킬은 **설명을 맞춘다.** 둘 다 걸리면 둘 다 한다.
- `assets/hooks/doc_counts.py` · `scripts/sync-doc-counts.sh` — README 숫자 블록 담당 (R-doc).
