# 문서 → 시안 명세표

시안의 왼쪽 메뉴와 오른쪽 화면은 둘 다 `docs/prototypes/<이름>/spec.md` 한 장에서 나온다. 그래서 그리기 전에
이 표를 확정받는다 — 그려 놓고 "이 화면이 왜 있지" 를 묻게 되면 되돌리는 비용이 화면 수만큼 든다.
양식과 기계 판독 규약은 `assets/spec-table.md`.

## 1. 입력 수준 판정

가진 문서를 훑고 아래 넷 중 하나로 판정해 **한 줄로 보여 주고 확인받는다**.
예: `수준 A+B — 화면 흐름 문서에 고객 앱 51화면은 있으나 관리자 화면은 PRD 요구만 있음`.

| 수준 | 조건 | 할 일 |
|---|---|---|
| A | 범위 후보 화면 모두가 문서에 번호·행동(다음 화면)까지 있음 | 범위만 고르고 문서를 표로 옮긴다 |
| A+B | 화면 흐름 문서가 일부 화면만 있음, 또는 문서끼리 충돌·낡음 | 있는 화면은 옮기고 없는 화면은 B 방식 + `가정`. 충돌은 따른 쪽을 근거 칸에 적고 목록으로 확인받는다 |
| B | 기획서·PRD·계획서만 (화면 정의 없음) | 아래 2절의 다섯 걸음 |
| C | 한두 줄 아이디어뿐 | 아래 3절의 보강 → 브리프 확정 → 수준 B |

판정에 쓸 문서 찾기: `docs/design-docs/`, `docs/exec-plans/`, `docs/` 아래 PRD·화면 흐름·기획서, 사용자가 이름을 댄 파일.
"낡음" 은 날짜로 본다 — 화면 흐름 문서보다 나중에 고쳐진 기획서가 있으면 그 사이 바뀐 요구가 있는지 대조한다.

## 2. 수준 B — 요구에서 화면 만들기

1. **역할 → 그룹.** 문서에 나오는 사람 종류(참여자·운영자·판매자)가 화면 목록의 묶음이 된다.
2. **핵심 고리 찾기.** 사용자가 가치를 얻는 한 바퀴 — 돈·예약·주문·약속 같은 주고받음이 끝나는 경로. 시안의 1차 범위는 이 고리다.
   하류 사례: 51화면 중 "참여 → 결제 → 진행 → 인계 → 완료" 13화면이 1차였다.
3. **고리를 화면 단위로 쪼갠다.** 한 화면은 한 결정(무엇을 보고 무엇을 누르나). 같은 화면의 상태가 다르면 장면을 나눈다(`EB-01a`·`b`).
4. **요구·규칙을 화면에 매핑**해 근거 칸을 채운다. 요구 ID 가 있으면 범위 안 것을 `requires` 줄에 모은다 — 빠진 요구를 기계가 잡는다.
5. **문서에 없어 정한 것은 `가정 P<n>`.** 버튼 위치·화면 순서·빈 상태 같은 것. 명세표 아래 목록으로 모아 확정받는다.

고리 밖 화면은 `2차` 행으로 남긴다. 버리지 않는 이유: 다음에 이어 붙일 때(SKILL.md ⑧) 그대로 1차로 올리면 된다.

## 3. 수준 C — 보강 질문 세 개

한 번에 묻고, 답이 오면 `docs/design-docs/prototype-brief.md` 를 짧게(한 화면 분량) 써서 확정받는다. 그 뒤는 수준 B.

1. **누가 쓰나** — 역할이 몇 종류인가 (화면 목록의 그룹이 된다)
2. **무엇을 끝내면 성공인가** — 사용자가 한 바퀴 돌고 얻는 것 (핵심 고리가 된다)
3. **돈이나 약속이 오가나** — 되돌릴 수 없는 화면이 어디인가 (확인 단계·실패 화면이 필요한 곳)

선택지로 물을 수 있는 것은 선택지로, 값이 자유인 것(제품 이름·역할 이름)은 한 문장 질문으로 묻는다. 질문 폼을 연달아 띄우지 않는다.

## 4. 표를 쓸 때의 판단

- **번호**: 문서 번호를 그대로 쓰되 글자 규칙(`assets/spec-table.md`)에 안 맞으면 새로 붙이고 원래 번호는 근거 칸에.
- **틀**: 휴대폰 앱이면 `phone`, 반응형 웹 서비스면 `browser`, 관리자·업무 도구면 `desktop`, 태블릿·키오스크면 `tablet`. 한 시안에 섞어도 된다 (고객 앱 `phone` + 운영 `desktop`).
- **행동**: 문서에 "→ 다음 화면" 이 있으면 그대로. 없으면 고리 순서대로 잇고 `가정`. 뒤로 가기도 행동이다.
- **들어오는 버튼 없는 장면**: 상태·권한 장면(정지된 계정 등)은 목록으로만 들어와도 된다 — 근거 칸에 "목록 진입" 이라고 적어 두면 검사의 알림이 의도된 것임을 다음 사람이 안다.
- **크기**: 1차가 20화면을 넘으면 묶음을 둘로 나눠 중간에 한 번 보여 준다 (하류: 38화면을 2a·2b 로 나눠 방향 수정 비용을 줄였다).
