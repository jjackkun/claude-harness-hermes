# 표시 내용 규칙

시안을 보는 사람은 화면의 숫자와 이름을 **결정된 것**으로 읽는다. 지어낸 가게 이름·금액이 한 번 시안에 올라가면
기획 회의에서 그 값이 사실처럼 돌아다닌다. 그래서 화면에 들어가는 값은 출처가 있는 것만 쓴다.

## 규칙

1. **문서에 나온 예시만 쓴다.** 기획서·PRD·화면 흐름 문서에 적힌 이름·금액·문구. 모든 값은 `scripts/content.js` 한 곳에 모은다 — 화면 파일에 값을 흩어 두면 출처를 대조할 수 없다.
2. **값마다 출처 주석을 단다.** `// PRD PAY-04 예시 "1개 예상 원가 10,000원"` 처럼 문서와 위치를 적는다.
3. **문서에 없는 값은 자리 표시 + 「예시」 표기.** `NB.parts.exTag()` 를 옆에 붙인다. 시간·거리처럼 배치를 보기 위한 값은 `content.note` 에 "자리 표시" 라고 밝힌다.
4. **아직 정해지지 않은 숫자는 `N`.** 요율·포인트·한도처럼 미결인 숫자를 그럴듯한 값으로 채우지 않는다. `N` 으로 두고 문서의 미결 목록 번호를 주석에 단다 (하류: "포인트 N" → 미결 Q5).
5. **계산되는 값은 명세의 예시와 맞춘다.** 세 칸 금액처럼 계산식이 문서에 있으면 그 식으로 계산하고, 문서의 예시 숫자가 화면에 그대로 나오는지 확인한다.
6. **`content.note` 는 필수 키다.** 화면 목록 아래 늘 보이는 "표시 내용 출처" 안내 — 무엇이 문서 값이고 무엇이 자리 표시인지.

## 금지어

프로젝트에 쓰면 안 되는 말(법무·브랜드 문서의 금지어)이 있으면 **원문 낱말 그대로** 검사 목록을 만든다.
요약해서 옮기면 놓친다 — 하류에서 "판매하기·상품 구매" 만 검사해 "판매" 단독을 기계가 못 잡았다.

```bash
# 금지어는 문서 원문에서 옮긴다 (예: LEGAL-02 원문이 "판매·구매·재고·마진")
grep -rnE '판매|구매|재고|마진' docs/prototypes/<이름>/scripts/ docs/prototypes/<이름>/index.html
```

설명 문구(화면 목록 안내·캡션)도 검사 대상이다 — 하류에서 내가 쓴 안내 문구의 "마진" 이 적발됐다.

## 글

- 화면 글은 사용자 말로: 시스템 이름이 아니라 사용자가 하는 일 ("알림 받기", "웹훅 설정" 이 아니라).
- 버튼은 무슨 일이 일어나는지 동사로 ("저장하기", "확인" 이 아니라). 같은 행동은 흐름 끝까지 같은 이름.
- 빈 상태·오류는 무엇이 잘못됐고 어떻게 고치는지. 사과하지 않는다.
