# pre-commit-measure — 커밋 전에 주장을 잰다

## 왜 만들었나

한 세션(2026-09-23)에서 **커밋 뒤 리뷰가 결함을 네 번** 찾았다. 그날 전체 시험 묶음은 다섯 번
돌렸다. 많이 돌렸지만 **바꾼 코드가 주장하는 것**을 잰 적은 없었다.

| 커밋 뒤 드러난 결함 | 커밋 전에 이 한 번이면 잡혔다 |
| --- | --- |
| 프로젝트별 재계산이 실제로는 안 돌았다 | 함수를 **두 번** 불러 두 번째에도 새로 계산되는지 |
| 기본 모드도 출력을 모았다가 한꺼번에 찍었다 | **스위치를 안 켠** 기본 모드로 돌려 도중에 출력이 보이는지 |
| 버전을 대상 폴더 기준으로 골라 실제 실행기와 달라졌다 | 대상에 **옛 설정 파일을 심고** 고른 값을 실제 값과 대조 |
| 끄기 스위치가 중첩될 때 안 먹었다 | **우회가 이미 걸린 부모 아래에서** 끄기를 켜고 원래대로 돌아오는지 |

넷 다 몇 초짜리 실행이었다. 그리고 넷 중 둘은 기존 시험이 **구조적으로 못 잡는** 종류였다 —
묶음을 백 번 돌려도 초록이다.

## 절차 — 셋

### 1. 주장을 한 줄씩 적는다

diff 를 보고 "이 변경이 참이면 무엇이 관측돼야 하나" 를 적는다. 한 줄에 하나, **관측 가능한 문장**으로.

- ❌ `pyenv 우회 개선` (무엇을 보면 참인지 없다)
- ✅ `같은 셸에서 폴더를 바꿔 두 번 부르면 두 번째는 그 폴더의 버전을 고른다`

두 종류를 빠뜨리기 쉽다. 위 결함 넷 중 셋이 여기서 나왔다.

- **안 바뀌어야 하는 것** — "기본 모드의 출력은 그대로다" 처럼 새 기능이 옛 경로를 건드리지 않는다는 주장.
- **두 번째 · 중첩 · 상속** — 한 번 부르면 맞는데 두 번째, 안쪽, 물려받은 환경에서 틀리는 것.

주장이 다섯 개를 넘으면 커밋이 너무 크다는 신호다. 나눌 수 있으면 나눈다.

### 2. 주장마다 그것을 깨뜨릴 가장 작은 실행을 돌린다

"통과하는지" 가 아니라 **"틀렸다면 여기서 드러나는지"** 로 입력을 고른다.

- 가짜 입력은 임시 폴더에 만든다(`mktemp -d`, 배경 세션이면 `$CLAUDE_JOB_DIR/tmp`). 저장소를 더럽히지 않는다.
- **기대값과 관측값을 둘 다 찍는다.** `ok` 한 글자가 아니라 `기대 3.11.9 / 관측 3.11.9`.
  무엇을 쟀는지 출력에 남아야 나중에 읽는 사람이 믿을 수 있다.
- 실행 하나는 **수 초** 가 목표다. 1분을 넘기면 가장 작은 실행이 아니다 — 입력을 줄인다.
- 버그를 고친 커밋이면, 할 수 있을 때 **고치기 전 코드로도 한 번** 돌려 실패하는지 본다
  (`git stash` 로 되돌려 보거나 옛 함수 본문으로). 고치기 전에도 통과하는 실측은 아무것도 재지 않는다.

잴 수 없는 주장도 있다(외부 서비스, 실제 다른 기계). 그때는 억지로 초록을 만들지 말고
`실측 못함: <이유>` 로 적는다. 빈칸보다 낫다.

### 3. 결과로 가른다

- 하나라도 틀리면 → 고치고 **그 주장만** 다시 잰다. 전체 묶음으로 돌아가지 않는다.
- 다 맞으면 → 커밋 메시지 본문에 남긴다. 형식: `주장 — 실행 — 관측값`. (아래는 9-23 결함으로 만든 예시다.)

```
fix(install): pyenv 우회를 실행 폴더 기준으로 다시 계산한다

실측(커밋 전):
- 두 번째 호출 재계산 — 폴더 A(3.10) → B(3.11) 순서로 부름 → 기대 3.11.9 / 관측 3.11.9
- 기본 모드 출력 불변 — 끄기 없이 긴 시험 1개 → 도중 출력 3줄 보임(고치기 전: 0줄)
- 중첩 끄기 — 우회 걸린 부모 + HARNESS_NO_PYENV_BYPASS=1 → python3 = pyenv shim
- 다른 기계 — 실측 못함: pyenv 없는 기계가 이 컴퓨터에 없음
```

## 하지 않는 것

- **전체 묶음으로 대신하지 않는다.** 묶음은 R-test 가 커밋 게이트에서 이미 돈다. 이 스킬은
  묶음이 **못 보는 것**을 잰다. 묶음을 한 번 더 돌리는 것은 실측이 아니다.
- **안 잰 숫자를 쓰지 않는다.** 메시지의 관측값은 방금 출력에서 옮긴 것이어야 한다. 기억이나
  예상으로 채우면 이 절차 전체가 거짓말이 된다.
- 문서·주석만 바꾼 커밋에는 쓰지 않는다. 주장이 동작이 아니다.

## 관련

- `run-to-the-end` — 긴 명령을 앞에서 기다릴지 정한다. 이 스킬은 **무엇을** 잴지 정한다.
- `verification-loop` — 빌드·린트·시험 전체 순회. 이 스킬과 겹치지 않는다: 저쪽은 넓게, 이쪽은 주장 하나씩.
