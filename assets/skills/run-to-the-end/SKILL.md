# run-to-the-end — 시작한 일은 그 턴 안에서 끝낸다

## 왜 만들었나

실제로 난 일이다. 한 세션에서 **세 번** 같은 모양이었다.

```
나    시험을 배경으로 돌린다 → "끝나면 커밋하겠습니다" → 턴을 끝낸다
사용자 "시험 끝났어?"
나    (읽어 보고) "끝났습니다. 커밋하겠습니다" → 또 턴을 끝낸다
사용자 "왜 자꾸 끝났는데 끝나는대로 하겠다고 하는거야"
```

★ **턴을 끝내면 공이 사용자에게 넘어간다.** 배경으로 돌린 뒤 턴을 끝내는 것은
**기다리는 일을 사용자에게 떠넘기는 것**이다. 사용자는 진행 보고를 원한 적이
없다 — **끝난 결과**를 원했다.

⚫ 마지막에는 더 나빴다: 시험 결과(`537 passed`)를 **이미 읽어 놓고도**
*"끝나면 하겠습니다"* 라고 했다. 읽은 것과 말한 것이 어긋났다.

## 두 번째로 난 일 — 앞에서 막혀서 말을 못 했다

위 실수를 막으려고 "600초 한도까지 앞에서 버텨라" 고 가르쳤더니, 반대쪽이 터졌다(2026-10-14).

```
나    세팅 스크립트를 앞에서 돌린다 (timeout=600000, 출력은 로그 파일로)
      → npm 설치가 끝나고 sudo 가 Password: 를 기다리며 멈춘다
      → 명령이 끝나기 전엔 내 차례가 오지 않는다 — 멈춘 것을 보지도 말하지도 못한다
사용자 "왜 말 안 하고 지켜만 보냐"
```

★ **앞에서 돌리는 동안 나는 아무것도 못 한다.** 진행도, 멈춤도, 입력 대기도
사용자에게 알릴 수 없다. 길 수 있는 명령을 앞에 두면 사용자는 아무 말 없는 화면을 본다.

## 🔴 어떻게 돌리나 — 짧으면 앞에서, 길 수 있으면 배경 + Monitor

| 명령 | 이렇게 |
| --- | --- |
| 1~2분 안에 끝날 것이 확실한 것 (바뀐 부분 시험·린트·작은 스크립트) | **앞에서** 돌리고 결과를 손에 쥔 채 다음 걸음까지 간다 |
| 길 수 있는 것 (설치·전체 시험·빌드·마이그레이션·처음 돌리는 세팅 스크립트) | **배경**으로 돌리고 **Monitor** 로 로그를 지켜보며 중간 보고한다 |
| 사람 입력이 필요한 것 (`sudo` 비밀번호·대화형 로그인·`[y/N]`) | 돌리지 않는다 — 사용자에게 `! <명령>` 으로 넘긴다 |

판단 기준 한 줄: **`timeout` 을 300000(5분) 이상 주고 싶어지면 그건 "길 수 있는" 명령이다.**
Bash 가드가 그 경우를 경고한다.

```bash
# ✅ 길 수 있는 명령 — 배경으로 돌리고, 같은 턴에서 지켜본다
Bash(command="<명령> > .harness/out/run.log 2>&1", run_in_background=True)
Monitor(command="tail -n +1 -f .harness/out/run.log | grep --line-buffered -E '<진행 표식>|Error|FAIL|Traceback|Password|\[y/N\]'",
        description="<무슨 명령> 진행·실패·입력 대기", timeout_ms=1800000)
# → 알림이 올 때마다 한 줄로 보고한다: "설치 3/5 — 의존성 내려받는 중"
# → Password · [y/N] 가 보이면 바로 멈추고 "! <명령> 으로 직접 돌려 주십시오" 라고 넘긴다
# → 끝나면(배경 명령 완료 알림) 결과를 읽고 다음 걸음까지 간다

# 🔴 이러지 않는다
Bash(command="<긴 명령> > run.log 2>&1", timeout=600000)   # 10분 동안 아무것도 안 보인다
Bash(command="<긴 명령>", run_in_background=True)  → 턴 끝  # 사용자가 "끝났어?" 를 묻는다
```

⚠️ **Monitor 필터는 실패와 입력 대기도 잡아야 한다.** 성공 표식만 걸면
멈춘 명령과 도는 명령이 똑같이 조용하다. 조용함은 진행이 아니다.

⚠️ **이 저장소는 얼마나 걸리나.** 숫자는 저장소마다 다르고 시간이 가면 늙는다.
그래서 **외우지 말고 잰다:**

```bash
bash <이 스킬 폴더>/tests/how-long.sh
```

`package.json` · `Makefile` · `pyproject.toml` 등에서 **그 저장소의 검사 명령을
스스로 찾아** 하나씩 재고, 앞에서 돌려도 될 만큼 짧은지 알려 준다.

## 배경으로 돌렸으면 — 턴을 끝내지 않는다

배경은 **사용자에게 기다림을 넘기는 수단이 아니다.** 진행을 보이면서 내가 계속 일하는 수단이다.

```
✅ 배경으로 돌리고 Monitor 로 보며 중간 보고 → 끝나면 결과를 읽고 다음 걸음
✅ 배경으로 돌리고 그 사이 문서를 채운다 → 같은 턴에서 결과를 읽는다
🔴 배경으로 돌리고 할 일이 없어서 턴을 끝낸다      ← 첫 번째 실수
🔴 앞에서 10분 막혀 멈춘 것을 말하지 못한다          ← 두 번째 실수
```

## 느리면 — 먼저 CPU 사용률을 잰다, 그다음 바뀐 부분만

오래 걸리는 시험을 만나면 **줄이거나 나누기 전에 한 번만 잰다:**

```bash
/usr/bin/time -f "%e초 CPU %P" <시험 명령>
```

- **CPU 가 낮으면(한 자릿수~수십 %)** 계산이 아니라 **기다림**이다. 기다리는 곳(원격 DB · 네트워크)이 원인이다.
  terminal-shipping 백엔드 1,465개는 **18분 · CPU 7%** 였고, 시험 DB 를 이 PC 로 옮기자 **83초 · CPU 78%** 가 됐다(13배).
  시험 개수는 그대로였다 — 원인은 개수가 아니라 거리였다. 근거: `docs/design-docs/core-beliefs.md#r-test-db`
- **CPU 가 높으면** 그때 시험을 나누거나 바뀐 부분만 돈다.

**작업 중에는 바뀐 부분만, 전체는 푸시 전 한 번.** 파이썬 프로젝트는 `pytest --testmon` 이 바뀐 코드에 걸린 시험만 고른다
(일부러 깨뜨린 변경 3가지에서 전체 실행의 실패를 하나도 안 놓침 · 3~4초 vs 85초). 쓰기 전에 알아 둘 것:
처음 한 번은 기록하는 전체 실행이다 · 프로젝트에 `coverage.py` 같은 같은 이름의 모듈이 있으면 부딪친다 ·
**파이썬 코드만 추적**하므로 스키마·`.env`·프론트가 바뀌었으면 전체를 돈다. 자세한 표: `core-beliefs.md#r-test-changed-only`.
커밋 게이트(R-test)는 이것을 쓰지 않고 **늘 전부** 돈다 — 게이트가 덜 돌면 조용해질 위험이 있다.

## 턴을 끝내기 전 한 줄 점검

**마지막 문장이 사용자에게 "기다리라" 고 말하고 있나?**

```
🔴 "시험이 끝나면 커밋하겠습니다"
🔴 "결과가 나오면 알려 드리겠습니다"
✅ "537개 통과했습니다. 커밋했습니다 (abc1234)."
```

★ **끝났으면 다음 걸음까지 간다.** 사용자가 이미 *"진행하자"* 라고 했다면
그 진행에는 **커밋까지**가 들어 있다. 검사가 초록인 것을 확인한 뒤 다시
물어볼 일이 아니다.

⚠️ **예외는 하나다** — 사람이 정해야 답이 갈리는 것. 그때는 묻고 멈춘다.
*"검사가 끝나기를 기다린다"* 는 그런 것이 아니다.

## 하위 에이전트(리뷰어)도 같다

리뷰어를 띄웠으면 **그 결과를 읽고 반영하는 것까지가 한 묶음**이다.

```
✅ 리뷰를 띄운다 → 그동안 다음 걸음을 짠다 → 결과를 읽는다 → 반영한다 → 커밋한다
🔴 리뷰를 띄운다 → "결과 나오면 알려 드리겠습니다" → 턴 끝
```

⚫ 리뷰는 몇 분이 걸릴 수 있다. **그동안 할 일이 정말 없으면** 짧은 보고 한 번은
괜찮다 — 다만 그 보고 뒤에 **결과를 읽으러 돌아온다.**

## 함께 볼 것

- ⚠️ **시험을 동시에 둘 돌리지 않는다.** 같은 개발 DB·포트·임시 파일을 밟으면
  **엉뚱한 시험이 빨개지고 원인 찾는 데 시간이 든다.** 배경으로 돌려도 하나씩
  돌리는 것이 결과도 더 믿을 만하다.
- ⚫ 매 턴 리마인더 1번이 같은 말을 짧게 한다. 이 스킬은 **왜 그런지와 재는 법**을 맡는다.
- ⚠️ `.sh` 를 쓸 때 **변수·함수 이름은 영문**이다. 셸은 한글 식별자를 못 받는다.

## 이 스킬이 안 하는 것

```
✗ 무엇을 검사할지 정하기        그 저장소의 CLAUDE.md · README
✗ 시험을 어떻게 쓰나            tdd-workflow 등
✗ 물어야 할 때 안 묻기          갈리는 결정은 여전히 묻는다
```
