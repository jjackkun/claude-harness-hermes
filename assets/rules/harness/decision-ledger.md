# 내가 대신 결정한 것 (decision-ledger)

사람에게 묻지 않고 내린 판단을 **한자리에 모아** 사람이 되돌릴 수 있게 한다.
결정 수를 줄이는 규칙이 아니다. 흩어진 결정을 보이게 하는 규칙이다.

> 출처: [obra/superpowers](https://github.com/obra/superpowers) 6.3.0
> `skills/subagent-driven-development/SKILL.md` 의 "Rulings, not stalls" · "Finish" 절을 옮기고 넓혔다.
> 근거: `docs/exec-plans/` 의 decision-ledger 계획서.

## 우선순위

아래보다 **낮다**. 충돌하면 아래를 따른다.

- 사용자 전역 규칙 (존댓말, 불확실하면 추측 금지, 자동 커밋 금지 등)
- 하네스·세션 규약 (`result:` 표기, 파괴적 작업 전 확인)

## 1. 멈추고 묻는 경우는 넷뿐이다

1. 되돌릴 수 없거나 파괴적인 일 (삭제, force push, DB drop)
2. 보안이 걸린 일 (비밀값, 권한, 인증)
3. 작업 공간 밖으로 부작용이 나가는 일 (머지, 공유 브랜치 push, 배포, 외부 서비스 게시)
4. 어느 쪽을 골라도 추측인 경우 (코드·문서·요청 어디에도 근거가 없음)

이 넷이 아니면 합리적인 쪽으로 정하고 계속한다. "계속할까요?" 로 멈추지 않는다.

## 2. 정했으면 그 자리에서 세 칸으로 적는다

`결정 — 이유 — 틀렸을 때 손해`

- ✅ `update-all 은 실행하지 않았다 — 12개 프로젝트에 영향 — 전파가 늦어져 새 규칙이 다음 설치까지 안 보인다`
- ❌ `적절히 처리했습니다` (무엇을 정했는지 없음)
- ❌ `A 로 했습니다` (이유·손해 없음 — 사람이 되돌릴지 판단할 수 없음)

## 3. 작업을 끝내는 보고에 전부 모은다

작업을 끝내는 보고(`result:` 를 쓰는 턴 포함)에 **「내가 대신 결정한 것」** 칸을 둔다.

- 이번 작업에서 적은 결정을 **빠짐없이, 정한 순서대로** 옮긴다. 기록에 있으면 목록에도 있어야 한다.
- 하나도 없으면 `내가 대신 결정한 것: 없음` 이라고 쓴다. **빈칸과 빠뜨림은 구분돼야 한다.**
- 사용자가 명시적으로 지시한 것은 결정이 아니다. 지시가 답하지 않은 부분을 정한 것만 적는다.
- 인사·확인 질문처럼 작업이 없는 답에는 붙이지 않는다.
- 보고 끝의 "다음 행동" 줄 **바로 앞**에 둔다. 답변 형식 규칙이 금지하는 "요약 반복" 이 아니다.

적히지 않은 결정은 몰래 내린 결정이다.

## 4. 헤르메스 루프에서

- 헤드리스: 보고 블록에 `DECISION: 결정 — 이유 — 손해` 를 결정마다 한 줄, 없으면 `DECISION: 없음`.
- 대화형: `hermes-loop.py step ... --decision "결정 — 이유 — 손해"` (반복 지정), 없으면 `--decision 없음`.
- 두 경로 모두 `loop_decisions` 에 저장되고 report.html 「내가 대신 결정한 것」 섹션에 모인다.
  줄을 빠뜨린 반복은 "기록 누락" 으로 표시된다.
