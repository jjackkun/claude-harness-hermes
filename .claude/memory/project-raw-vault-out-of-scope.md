2026-09-29 사용자: "여기서는 필요없어. 이건 개인이나 비공개 팀 프로젝트에서 하는게 맞는다고 생각해."
카카오톡 서랍처럼 원문을 저장·불러오는 방식(별도 비공개 저장소 + 암호화)을 논의했고, 공용으로 나가는 이 프로젝트(공장, sync.json 은 PUBLIC)에는 만들지 않기로 했다.

**Why:** 공용 도구가 원문 저장 기능을 가지면 위험(마스킹 한계·키 유출)을 도구가 떠안고, 보관소 위치·키·보존 기간은 사용자마다 달라 설정·유지 부담이 커진다.
공장의 역할은 "개인 정보를 프로젝트 저장소에 못 올라가게 막는 것"(R-privacy 게이트)이다.

**How to apply:** 원문 보관·서랍·별도 비공개 보관소를 공장 기능으로 제안하지 않는다. 사용자가 개인 도구로 만들자고 하면 이 저장소 밖에서 만든다.
참고 수치(2026-09-29 실측): 사람 세션 원문 통째 압축 약 14MB/일(1년 약 5GB)이라 GitHub 권장 1GB를 2개월이면 넘고, 말·답변 글만은 1년 약 120MB. GitHub 한도: 저장소 1GB 권장·5GB 강력 권장·디스크 10GB, 파일 50MiB 경고·100MiB 차단, 푸시 2GB.
