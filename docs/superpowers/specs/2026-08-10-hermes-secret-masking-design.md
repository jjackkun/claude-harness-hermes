# 헤르메스 세션 기록 비밀 마스킹 — 평문 자격증명이 실려 커밋된 결함과 수정 설계

> 작성일: 2026-08-10
> 트리거: 소비 프로젝트(terminal-shipping)에서 커밋 직전 발견. 값이 커밋·푸시까지 갔다.
> 성격: **프리셋(claude-harness-hermes) 결함.** 소비 프로젝트가 고칠 수 없다 —
> 해당 스크립트들이 프리셋과 바이트 동일이라 로컬 수정은 `setup.sh` 재실행 시 소실된다.
> 상태: 🔴 착수 전
>
> 구조는 `docs/exec-plans/template.md` 를 따른다. 다만 `docs/exec-plans/active/` 는
> 이 저장소에서 커밋 대상이 아니므로(개인 작업로그 배제 정책) 프리셋 자체의 설계
> 문서로서 `docs/superpowers/specs/` 에 둔다.

## 1. 동기 (Why)

2026-08-10, terminal-shipping 저장소에서 커밋 직전 `.hermes/history/*.jsonl` 안에
**외부 시스템 계정 5종의 평문 자격증명**이 발견됐다. 값은 2026-08-08 커밋부터
origin/main 에 올라가 있었다 (비공개 1인 저장소라 제3자 노출은 아님 — §3 참조).

### 관측된 사실

| # | 사실 | 확인 방법 |
|---|---|---|
| 1 | `.env` 는 한 번도 커밋된 적 없다 | `git log --all -- '*.env'` → 0건 |
| 2 | 값이 실린 파일은 `.hermes/history/*.jsonl` 뿐이다 | `git ls-files \| xargs grep -l` |
| 3 | 값을 최초로 담은 레코드는 전부 `role: user` 다 | jsonl 파싱 |
| 4 | `.gitignore` 가 이 디렉터리만 **예외로 풀어** 커밋 대상이다 | `.gitignore` 10~14행 |
| 5 | DB 적재 직전 `redact()` 는 **호출되고 있다** | `hermes_save_session_storage.py:94` |
| 6 | 그런데 이 형태를 **못 잡는다** | 아래 실행 결과 |

### `redact()` 실측 (가짜 값으로 재현)

```
막힘   password=Fakepw11aa       → password=[REDACTED:SECRET]
막힘   비밀번호: Fakepw11aa       → 비밀번호: [REDACTED:SECRET]
막힘   sk-abcdef…                → [REDACTED:TOKEN]
막힘   010-1234-5678             → [REDACTED:PHONE]

통과❌ fakeuser | !Fakepw11aa    ← 사용자가 실제로 친 형태
통과❌ FAKE01 ⏎ QWER1234*        ← URL 아래 ID·비번을 줄바꿈으로 나열
통과❌ SOME_PASSWORD=Fakepw11aa   ← 라벨에 접두어가 붙은 형태
```

### 근본 원인 — 네 겹이 순서대로 뚫렸다

| 겹 | 장치 | 왜 뚫렸나 |
|---|---|---|
| 1 | `redact()` (DB 적재 경계) | **딱지(`label=value`) 가 있어야만 가린다.** 사람이 실제로 주는 형태는 URL 아래 `아이디 \| 비번` 처럼 딱지가 없다 |
| 2 | 〃 | `_KV_LABELS` 앞의 `\b` 때문에 `SOME_PASSWORD=` 처럼 접두어가 붙으면 경계가 사라져 매치 실패 |
| 3 | `hermes-export-history.py` (DB→파일 경계) | **마스킹이 아예 없다.** 1번에서 걸러졌다고 전제한다 |
| 4 | 커밋 경계 | 프리셋에 비밀 스캐너가 없다. 소비 프로젝트가 자체 제작했으나 pre-commit 에 연결되지 않았고, 연결됐어도 jsonl 한 줄(1.6만 자)에 `example` 이 섞이면 **그 줄 전체가 면제**돼 통과했다 |

### 핵심 판단

> **형태를 추측하는 마스킹은 사람이 실제로 주는 형태를 못 따라간다.**
> 딱지 어휘를 아무리 늘려도 `아이디 | 비번` 은 못 잡는다.
> 정답지(`.env` 실제 값)와 대조하는 **값 기반 마스킹**이 있어야 한다.

2번 구멍은 이미 소비 프로젝트의 `check-secrets.py` 에서 발견·수정됐고 주석까지 남았으나
**원본 `hermes_redact.py` 에 역류되지 않았다.** 복제본만 고치고 원본을 두면 이렇게 된다.

## 2. 목표 (What — 검증 가능한 형태)

- [ ] **G1. 값 기반 마스킹** — `.env` 에 실재하는 값이 세션 기록에 나타나면 딱지 유무와
      무관하게 치환된다. 검증: `아이디 | 비번` 형태를 넣고 `redact()` 결과에 원문이 없음
- [ ] **G2. `\b` 구멍 제거** — `SOME_PASSWORD=` 형태가 잡힌다. 검증: 단위 테스트
- [ ] **G3. 추출 경계 다층 방어** — `hermes-export-history.py` 가 파일로 쓰기 직전 한 번 더
      마스킹한다. 검증: DB 에 오염된 행을 심고 export → 파일에 원문 없음
- [ ] **G4. 커밋 경계 차단** — 프리셋이 비밀 스캐너를 제공하고 pre-commit 에 등록한다.
      검증: 가짜 비밀을 담은 파일을 스테이징 → 커밋 실패
- [ ] **G5. 줄 단위 면제 구멍 제거** — 자리표시자는 **매치 구간만** 면제한다. 줄 전체를
      건너뛰지 않는다. 검증: `example` 과 진짜 비밀이 같은 줄에 있어도 탐지
- [ ] **G6. 회귀 테스트** — 위 형태들이 `tests/` 에 고정된다. 검증: `pytest` 통과

## 3. 비목표 (Out of Scope)

- **이미 커밋된 값의 히스토리 재작성** — 소비 프로젝트(terminal-shipping)의 몫이다.
  이 계획은 *앞으로* 새지 않게 하는 것만 다룬다.
- **비밀번호 교체** — 해당 저장소는 비공개·1인·포크 없음·CI 없음이므로 제3자 노출로
  보지 않는다. 교체는 사용자 판단.
- **`.hermes/history/` 커밋 관례 폐지** — 이 디렉터리는 *여러 컴퓨터 간 세션 이식*이라는
  실제 기능을 지탱한다 (`hermes-reindex.py` 가 pull 받은 jsonl 을 읽어 재색인).
  기능을 죽이는 대신 **내용을 깨끗하게 만드는** 쪽을 택한다.
- 대화 내용 자체의 저장 여부 재검토.

## 5. 단계 (Steps)

### Step 1. 값 집합 추출기 — `hermes_secret_values.py` [Impl]

- 입력: 프로젝트 루트
- 산출: `load_secret_values(project_dir) -> dict[str, str]` (키 이름 → 값)
- 규칙:
  - `.env` · `backend/.env` 등 알려진 위치를 순회. 없으면 빈 집합 (실패 아님)
  - 값 길이 4자 미만 제외 — 오탐으로 산문이 깨진다
  - `changeme` · `example` · `your-…` 등 자리표시자 제외
  - **`$HOME` 경로에 포함되는 값 제외** ⚠️ 실제 사례: 계정 ID 가 홈 디렉터리명과 같아
    무조건 치환하면 `/home/<id>/…` 경로가 전부 깨진다. 제외하고 그 사실을 로그로 남긴다
- 검증: 가짜 `.env` 로 단위 테스트. **값을 stdout 에 찍지 않는지**도 테스트한다

### Step 2. `redact()` 보강 [Impl]

- 값 기반 규칙을 **가장 먼저** 적용 → `[REDACTED:ENV:<KEY>]`
- `_KV_LABELS` 앞 `\b` 제거 (구멍 2)
- `_SECRET_VALUE` 첫 글자에 특수문자 허용 (구멍 2 의 짝)
- 검증: §1 의 7가지 형태 전부 `tests/test_redact_shapes.py` 로 고정
- ⚠️ 과마스킹 회귀 주의 — 한글 산문이 깨지지 않는지 기존 테스트 유지

### Step 3. 추출 경계 다층 방어 [Impl]

- `hermes-export-history.py` 가 jsonl 줄을 만들기 직전 `redact()` 1회
- 근거: 1번 겹을 믿지 않는다. DB 에 이미 오염된 행이 있어도 파일은 깨끗해진다
- 검증: 오염 행을 DB 에 심고 export → 파일에 원문 없음

### Step 4. 커밋 경계 — 스캐너 승격 [Impl]

- terminal-shipping 의 `check-secrets.py` 를 프리셋으로 가져온다
- **구멍 5 수정**: `PLACEHOLDER_RE` 를 줄 전체 skip 이 아니라 **매치 구간 제외**로 바꾼다
- 값 기반 규칙 추가 (Step 1 재사용)
- pre-commit 4단 → 5단. 등록은 `setup.sh`
- 검증: 가짜 비밀 파일 스테이징 → 커밋 거부. `example` 이 같은 줄에 있어도 거부

### Step 5. 소급 정리 도구 [Impl]

- `session_history` 테이블과 `.hermes/history/*.jsonl` 을 값 기반으로 훑어 치환
- **멱등**해야 한다. 값을 출력하지 않는다
- 파괴적이므로 `--dry-run` 이 기본. 실제 치환은 명시 플래그
- 검증: 오염본 → 실행 → 재실행 시 변경 0건

### Step 6. 회귀 테스트 고정 [Impl]

- `tests/test_redact_shapes.py` 에 §1 표의 7행을 그대로 케이스로
- **가짜 값만 사용한다.** 테스트 파일에 실제 자격증명을 넣지 않는다

## 7. 발견·예외

### 발견 1 — 복제본만 고치고 원본을 안 고치는 패턴

`check-secrets.py` 는 `hermes_redact.py` 의 패턴을 **복제**해 만들어졌고, 주석에
복제 이유가 적혀 있다("프리셋이 관리하는 파일이라 덮여쓸 수 있다"). 그 복제본에서
구멍 두 개를 찾아 고쳤지만 **원본에는 역류되지 않았다.** 원본을 쓰는 경로(DB 적재)가
계속 뚫려 있었다.

→ **룰 후보**: 프리셋 파일의 패턴을 복제할 때는 역류 경로를 계획에 명시한다.

### 발견 2 — 자리표시자 면제가 탐지기를 무력화한다

오탐을 줄이려는 `PLACEHOLDER_RE` 가 **줄 단위**로 걸려 있었다. 한 줄이 1.6만 자인
jsonl 에서는 `example` 한 번이면 그 줄의 진짜 비밀이 통째로 면제된다.

→ **룰 후보**: 면제 규칙은 탐지 단위와 같은 폭이어야 한다. 줄 단위 탐지에 줄 단위
면제를 붙이면 긴 줄에서 무너진다.

### 발견 3 — 규칙은 파일을 지켰고, 값은 파일이 아니라 텍스트로 샜다

"`.env` 를 커밋하지 않는다"는 규칙은 완벽히 지켜졌다. 그런데 같은 값이 **채팅 텍스트**로
전달되는 순간 규칙의 사정권 밖으로 나갔다.

→ **룰 후보 (core-beliefs 승격 검토)**: *비밀의 경계는 파일이 아니라 값이다.
파일 단위 금지 규칙은 값이 다른 매체로 옮겨가는 순간 무력해진다.*
