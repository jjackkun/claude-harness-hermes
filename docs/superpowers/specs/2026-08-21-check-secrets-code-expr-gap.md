# check-secrets — 인자 이름을 자격증명으로 오인한다

> 작성일: 2026-08-21
> 목적: `CODE_EXPR_RE` 가 **맨 이름 참조**를 면제하지 못해 정상 코드가 막히는 것을 고친다.
> 계기: 설치본(terminal-shipping)에서 하루에 네 번 커밋이 막혔다 — §1
> 상태: 🟢 완료 — `assets/hooks/check-secrets.py` 수정 + `tests/check-secrets-code-expr-test.sh` 회귀 고정.

## 1. 무엇이 걸렸나

하루 동안 네 번 막혔다. **앞의 셋은 코드를 고치는 것이 옳았고, 넷째는 아니었다.**

| 걸린 것 | 실제 정체 | 판단 |
|---|---|---|
| `COMPANY_KEY` 상수 | PostgreSQL 세션 설정값 이름(GUC) | 코드를 고침 — `COMPANY_SETTING` 이 더 정확 |
| `ADMIN_URL_KEY` 상수 | 환경변수 **이름** | 코드를 고침 — `ADMIN_URL_ENV` 가 더 정확 |
| 컬럼 이름 나열 | 문서의 표 설계 설명 | 문서를 고침 — 표로 풀어 쓰니 읽기도 나아짐 |
| **함수 인자 이름** | 코드 식별자 | 🔴 **검사기를 고쳐야 한다** |

넷째가 이런 형태다.

```python
await login(conn, secret, email=email, password=PASSWORD)
issue(user_id=row.id, token=refresh_plain)
```

★ **`password=` 는 로그인 함수의 자연스러운 인자 이름이다.**
바꾸면 코드가 나빠진다 — 검사기를 피하려고 API 를 비트는 셈이 된다.

## 2. 왜 안 걸러졌나

`CODE_EXPR_RE` 는 이미 *"값 자리가 코드 식이면 면제"* 를 하고 있다. 그런데
면제 목록에 **맨 이름 참조**가 없었다.

```
✅ 면제됨   token = _CSRF_META.search(page)     호출식
✅ 면제됨   secret_key = os.environ["KEY"]      알려진 루트
✅ 면제됨   password: string                    타입 표기
❌ 안 됨    password=PASSWORD                   상수 참조
❌ 안 됨    token=refresh_plain                 변수 참조
```

**따옴표가 없으므로 리터럴이 아니라 식별자다.** 구문으로 단정할 수 있다 —
그 파일이 스스로 정한 기준(*"값 자리가 코드라고 구문으로 단정할 수 있는 형태만 면제"*)에
그대로 들어맞는다.

## 3. 고친 것

`CODE_EXPR_RE` 에 대안 둘을 더했다.

```python
r"|(?-i:[A-Z][A-Z0-9_]{2,})(?=[\s),;\]]|$)"          # ALL_CAPS 상수 참조
r"|(?-i:[a-z_][a-z0-9_]*_[a-z0-9_]*)(?=[\s),;\]]|$)"  # 밑줄 든 변수 참조
```

**좁게 유지한 두 장치**

```
① ALL_CAPS 이거나 밑줄이 든 이름만
   그래야 따옴표 없이 적힌 짧은 진짜 비밀번호가 면제되지 않는다
② (?-i:) 로 대소문자를 구분한다
   이 정규식 전체에 (?i) 가 걸려 있다
```

### 3-1. 🔴 ②가 없으면 검사기가 약해진다 — 실제로 겪었다

처음에 `(?-i:)` 없이 넣었더니 `(?i)` 때문에 `[A-Z]` 가 소문자까지 잡았고,
**따옴표 없이 적힌 진짜 비밀번호가 통과**하게 됐다.

⚠️ **여덟 경우를 표로 만들어 재보고 나서야 발견했다.** 안 재봤으면 오탐을 고치면서
탐지력을 깎은 채 넘어갔을 것이다 — 그리고 그 사실을 아무도 몰랐을 것이다.

## 4. 검증

**새로 만든 여덟 경우** — 넷은 잡아야 하고 넷은 통과해야 한다.

```
잡아야 함   따옴표 있는 하드코딩 · 따옴표 없는 비밀 · API 키 · 대문자 시작 혼합
통과해야 함  상수 참조 · 변수 참조 · 호출식 · 타입 표기
```

→ 여덟 다 맞음.

**여덟 경우를 회귀로 고정했다** — `tests/check-secrets-code-expr-test.sh`.
문서에만 적힌 시험은 다음 사람이 면제 규칙을 건드릴 때 돌지 않는다. 이 시험은
양방향을 지킨다: 수정 이전 정규식에서는 상수·변수 참조를 오탐해 실패하고,
`(?-i:)` 를 뺀 판에서는 진짜 비밀 둘을 통과시켜 실패한다(둘 다 실측 확인).

**기존 시험** `tests/check-secrets-answerkey-test.sh` → 다섯 다 통과.
이 시험은 `tests/run-all.sh` 에 등재돼 있지 않아 한 번도 자동 실행되지 않았다.
새 시험과 함께 등재한다.

```
✅ 위반을 차단했다 (exit 2)
✅ 라벨 없는 평문을 잡았다
✅ 자리표시자 옆 평문을 잡았다
✅ 아이디는 놓아줬다
✅ 정답지가 없어도 죽지 않는다
```

## 5. 남은 것

```
⬜ 커밋            이 저장소 작업은 별도 세션에서 한다는 사용자 판단
⬜ 시험 추가        위 여덟 경우를 answerkey 시험에 넣으면 회귀를 막는다
⬜ 설치본 갱신      update-all 로 퍼져야 실제로 적용된다
```

⚠️ **설치본은 `.git/hooks/check-secrets.py` 를 쓴다.** 그 파일은 커밋 대상이 아니라
저장소 이력에 안 남는다 — 설치본에서 고쳐도 다음 갱신 때 덮인다.
**여기(원본)에 반영해야 영구히 남는다.**

## 6. 발견

- ★ **오탐을 고칠 때마다 이름을 바꾸는 것이 늘 답은 아니다.** 셋은 이름이 실제로
  부정확해서 고치는 것이 옳았고, 넷째는 검사기가 틀렸다. **어느 쪽인지 매번 판단해야
  한다** — 기계적으로 이름을 비틀면 코드가 검사기 모양으로 휜다.
- ⚠️ **검사기를 고치는 일에는 "약해지지 않았는가" 확인이 따라붙는다.**
  오탐을 없애는 방향은 정의상 탐지 범위를 줄이는 방향이다.
