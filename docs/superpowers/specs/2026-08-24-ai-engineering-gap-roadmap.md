# AI 엔지니어링 격차 — 스펙 로드맵

> 작성일: 2026-08-24
> 목적: 로버트 마틴 대담(Tech Bridge) 대비 하네스의 격차 7건을 스펙으로 묶고, 착수 순서를 정한다.

## 개요

영상은 AI 코딩 에이전트 시대에 **자연어 지침 대신 결정론적 도구로 강제하라**고 말한다.
이 저장소는 그 구조를 이미 갖고 있다 — `pre-commit` 의 7개 검사 단계가 그것이다
(파일 헤더의 "4단 검사" 표기는 uninstall 이 하네스 설치본을 식별하는 마커이므로 바꾸지 않는다).
격차는 **무엇을 재는가**에 있었다.

전수 대조 결과 7개 항목이 비어 있었고, 각각을 스펙으로 옮겼다.

  뒤 코드가 `NameError` 로 죽는다 — "없어도 동작한다" 가 성립하지 않는다.

### 3. `R-cov` — 1단계 완료 (2026-08-24)

죽어 있던 `R-test` 를 되살렸다. 커버리지 임계(2단계)는 측정 대상이 생긴 뒤의 일이다.

`R-test` 가 이제 **세 상태를 구분한다**:

| 상태 | 판정 | 이유 |
|---|---|---|
| 테스트 실패 | **차단** | 회귀다 |
| 수집 0개 (exit 5) | 경고 | 파이썬 없는 프로젝트도 설치 대상이라 막으면 안 된다 |
| pytest 실행 불가 | 경고 | 도구가 못 뜬 것이지 코드 문제가 아니다 |

**세 번째 상태는 스펙에 없었다.** 초안은 "실패 / 수집 0개" 둘만 봤다.
구현 중 드러났고, 예전 코드는 이를 `[R-test] pytest 실패` + Traceback 으로 보고하며
**커밋을 막았다** — 도구가 못 뜬 것을 테스트 실패로 보고하면 사람이 자기 코드를 뒤진다.

재현 경로가 있다: `HOME` 이 바뀌면 user-site(`~/.local/lib/.../site-packages`)가 사라져
실행 파일은 남고 import 만 깨진다. `harness-hooks-smoke.sh` 가 `HOME` 을 격리하는
순간 이 증상이 그대로 나왔다 — 게이트를 고치려고 테스트를 쓰다가 게이트의 다른 결함을 만났다.

테스트는 **실제 pytest 에 의존하지 않는다.** mock pytest 로 종료코드를 통제해 세 상태를
각각 검증한다. 실제 도구에 의존하면 스모크가 환경에 따라 흔들린다.

**2단계(커버리지 임계)는 두 가지에 막혀 있다:**

1. `coverage.py` 미설치. WSL 이므로 사용자가 직접 설치한다 (`pip install coverage`).
2. 무엇을 측정할지 결정 — (A) bash 통합 테스트의 커버리지를 측정하거나
   (B) 파이썬 단위 테스트를 신설한다. **(A) 를 권한다**: 28개 통합 테스트가 이미
   실제 경로를 돌고 있어 비용이 낮고, 거기서 잰 값이 "실제로 검증되는 코드" 에 더 가깝다.

### 6. `R-pipe` — 완료 (2026-08-25)

| 산출물 | 내용 |
|---|---|
| `assets/hooks/claude-posttooluse-review-record.sh` | 리뷰어 dispatch 를 리뷰 빚 청산으로 기록 (신규) |
| `assets/hooks/pre-commit.sh` | `8-bis. R-pipe` 단계 — 리뷰 기록이 남은 파일이 커밋에 포함되면 경고 |
| `presets/workflow/harness.conf` | `POST_TOOL_USE_HOOKS+=('Task\|Agent::…review-record.sh')` |
| `docs/design-docs/core-beliefs.md` | `#r-review` 정정 + `R-pipe` Provisional 명시 |
| `tests/pipe-gate-test.sh` | 24/24 |
| `tests/harness-hooks-smoke.sh` | `1e` 배선 검사 추가 (98/0) |

구현 중 확정한 것 (스펙 미해결 3건 전부):

1. **리뷰 기록 방법** — 리뷰어 dispatch 시 `.review-dirty` 를 **자동 삭제**한다.
   문서는 이미 "리뷰 후 `rm`" 이었으나 그 `rm` 이 수동이라 지켜지지 않았다. 훅이 대신 지우면
   문서가 참이 된다. 리뷰어 판별은 목록이 아니라 **`-reviewer` 접미사 규칙**이다 —
   에이전트를 추가할 때 훅을 같이 고쳐야 한다는 것을 아무도 기억하지 못한다.
2. **Specifier 강제** — 추가하지 않는다. `R-plan-missing` 이 이미 담당한다.
3. **경고 피로** — 스펙의 경고 2개를 **1개로 줄였다.** `pre-commit` 에는 이미 경고 지점이
   15곳 있다. Hardener 조건("변경된 `.py` 에 대응 테스트 존재")은 `R-cov` 2단계와 중복이므로
   그쪽으로 이관했다.

구현 중 잡은 것:

- **`core-beliefs.md#r-review` 가 없는 강제를 주장하고 있었다.** "안 지우면 commit 단계에서
  차단" 이라 적혀 있었으나 `pre-commit` 은 `.review-dirty` 를 **한 번도 읽지 않았다**
  (2026-04-15 도입 이래). `R-test` 가 테스트 0개로 늘 통과하던 것과 같은 결함이다.
- **`POST_TOOL_USE_HOOKS` 배열은 이번이 첫 사용이다.** 렌더링 경로가 죽어 있었어도
  아무도 몰랐을 자리라, 실제 `settings.json` 산출물을 단언하는 검사를 스모크에 넣었다.
- **훅 개수 기대값이 매직넘버였다.** `assert "… 경로 존재" "9"` 는 훅을 추가할 때마다
  손으로 고쳐야 했고(08-04 8→7, 08-13 7→8, 08-24 8→9), 그 갱신은 기능 회귀와 구분되지
  않는다. 프리셋 등록 수에서 **도출**하도록 바꿨다 — 이제 "등록한 것이 전부 렌더링됐는가"
  를 묻는다.

구현 중 잡은 것 — **스펙의 전제 두 개가 실측과 달랐다**:

  라쳇의 "개선되면 기준선을 낮춘다" 경로를 처음으로 실제로 밟았다(파일 최대 13 → 8).

- **테스트가 살아 있는 소스의 측정값을 픽스처로 박아 뒀다.** `complexity-gate-test.sh` 가
  `plan_state.py 최대 13` 을 단언하고 있어, 복잡도가 **좋아지자 테스트가 깨졌다** —
  개선을 회귀로 신고하는 구조다. 고정해야 할 것은 특정 파일의 숫자가 아니라
  **기준선과 실측의 관계**이므로, `.cxbaseline` 의 모든 항목이 실측 이상인지를 보는
  불변식으로 바꿨다(기준선이 실측보다 낮으면 손대지도 않은 파일이 다음 커밋에서 막힌다).

**교차 충돌은 예측대로 일어났고, 라쳇이 예측대로 처리했다.** `R-cx` 를 일괄 임계 12 로
켰다면 `R-acc` 착수 전에 리팩터링이 선행돼야 했을 것이다.

## 착수 순서

```text
1. R-iface  ─┬─→  2. R-cx  ─┬─→  3. R-cov  ─→  4. R-mut
             │              ├─→  6. R-pipe
             │              └─→  7. R-acc
             └─→  5. R-dep
```

**`R-iface` 가 먼저인 이유**: 나머지가 모두 모듈 경계에 의존한다.
한 파일에 책임 5개가 섞여 있으면 파일 단위 복잡도·커버리지 점수가 의미를 잃고,
의존 계약은 경계가 흐릿한 상태에서 쓸 수 없다.

**`R-acc`·`R-pipe` 가 `R-cx` 뒤인 이유** (2026-08-24 교차 검증에서 발견):
두 스펙 모두 기존 훅 파일을 수정해야 하는데, 그 파일들이 `R-cx` 차단 목록에 있다.

| 스펙 | 수정 대상 | 그 파일의 최대 복잡도 |
|---|---|---|
| `R-acc` | `assets/hooks/plan_state.py` (§2 파서 추가) | **13** |
| `R-pipe` | `pre-commit.sh` 계열 (`.review-dirty` 판정) | — (bash, `R-cx` 대상 아님) |

`R-cx` 가 라쳇 방식이면 기준선이 13 으로 동결되므로 `plan_state.py` 수정이 막히지 않는다.
**라쳇을 채택하지 않고 일괄 임계 12 로 가면 `R-acc` 착수 전에 리팩터링이 선행돼야 한다.**
`R-cx` 스펙의 도입 전략 결정이 이 순서를 좌우한다.

## 측정 방법 — 이번에 배운 것

초안의 의존 그래프는 `^(from|import)` 정규식으로 측정했고 **들여쓴 import 를 전부 놓쳤다.**
AST 재측정에서 간선 9개(전체의 3분의 1)가 추가로 드러났고,
그중 하나가 초안의 `forbid` 규칙을 위반하는 의도된 설계였다.

파이썬의 조건부·지연 import 는 함수나 `try` 블록 안에 들어가므로 들여쓰기가 기본이다.
**구조를 재는 도구는 정규식이 아니라 AST 로 구현한다** — `R-cx`·`R-dep`·`R-iface` 공통 요건이다.

같은 이유로 초안은 `R-cx` 의 도입 비용을 "함수의 7%" 로만 적었으나,
게이트는 파일 단위로 차단하므로 실제로는 **파일의 43%** 였다.
**게이트의 영향은 게이트가 판정하는 단위로 재야 한다.**
