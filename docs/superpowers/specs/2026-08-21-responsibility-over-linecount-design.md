# R-size 축 — 줄 수가 책임을 밀어냈다

> 작성일: 2026-08-21
> 목적: `1 파일 = 1 책임` 이라는 교리를 강제할 장치가 전부 줄 수를 재고 있어,
> 400 줄 전까지는 어떤 신호도 나오지 않는 구멍을 메운다.
> 계기: 설치본(terminal-shipping)에서 실제로 발생한 위반 — §1-3

## 1. 동기 (Why)

**교리는 정확하다. 그것을 강제하는 장치가 다른 것을 잰다.**

### 1-1. 교리에는 고칠 것이 없다

`docs/design-docs/core-beliefs.md:15` 은 이렇게 적혀 있다.

> **R-size — 1 파일 = 1 책임 (500은 안전망)**
> 500 을 넘으면 "어디서 자르지?" 가 아니라 **"왜 여기까지 왔지?"** 부터 묻는다.
> 500 초과 파일은 거의 항상 책임 2개 이상이 섞여 있고, 제대로 분리하면
> 500 한도는 자연히 지켜진다.

**이 문장은 옳다.** 아래 문제는 교리가 아니라 구현의 문제다.

### 1-2. 그런데 장치 셋이 전부 줄 수를 잰다

전부 코드에서 확인한 사실이다.

```bash
assets/hooks/claude-posttooluse-size-warn.sh:46   LC=$(wc -l < "$FILE_PATH")
assets/hooks/pre-commit.sh:92                     LC=$(wc -l < "$f")
```

```
assets/hooks/claude-userpromptsubmit-reminders.sh:117
  "2. 파일 책임을 좁게 유지하고 soft 400 / hard 500 줄을 넘기기 전에 분리."
```

★ **`size-warn.sh:50` 은 "책임이 몇 개인지 세라" 고 정확히 말한다.**

```
"이 파일에 책임이 몇 개인지 세고, 2개 이상이면 파일별 책임 분리 → 배럴 재export."
```

**그런데 그 문장이 400 줄에 닿아야 출력된다.** 책임 검사가 **줄 수 트리거에
종속돼 있다.** 300 줄짜리 파일에 책임이 셋이면 어떤 장치도 아무 말을 하지 않는다.

### 1-3. 실제로 일어난 위반 (terminal-shipping · 2026-08-20~21)

```
8/20     data-model.md 에 §7 "물리 설계" 를 만든다
         → 이 순간 파일의 책임이 둘이 됐다
            논리 설계(무엇을 담나) · 물리 설계(어떤 타입·제약)
8/20~21  §7-1 … §7-12 를 계속 붙인다        경고 없음 (300 줄대)
8/21     458 줄. soft 400 경고를 보고서야 분리
```

⚠️ **정정 (2026-08-21 코드 대조).** 위 마지막 줄은 사실이 아니다. `size-warn` 과
`pre-commit` 의 검사 대상은 `py|js|jsx|ts|tsx|svelte|vue` 뿐이고 **`.md` 는 들어 있지 않다.**
이 파일은 처음부터 끝까지 어떤 줄 수 장치의 대상도 아니었다 — 400 을 비껴간 것이 아니라
**애초에 재지 않았다.** 구멍은 문서가 말한 것보다 넓다. §3.2 는 `.md` 편입을 포함한다.

**파일명이 이미 답을 주고 있었다** — `data-model` 은 자료 모델이지 DDL 이 아니다.
그런데 조용한 구간에서는 아무도 그것을 묻지 않았다.

⚠️ **에이전트는 "400 이 가까우니 이제 쪼갠다" 고 판단했다.** 즉 안전망을 트리거로
학습했다. 사람이 *"왜 항상 500 에 가까워져야 쪼개기 시작하느냐"* 고 물어 드러났다.

### 1-4. 왜 이 구멍이 안 메워졌나

```
재려는 것    책임 수    ← 기계가 못 센다
재는 것      줄 수      ← 기계가 잰다
```

`wc -l` 은 있어도 `wc -responsibility` 는 없다. **잴 수 있는 것으로 대신했고,
대신한 것이 원본을 밀어냈다.** 하네스 엔지니어링에서 흔한 실패 형태다 —
*측정 가능한 대리 지표가 목표를 대체한다.*

### 1-5. 리마인더가 가장 세다

매 턴 주입되는 문장은 **하루에 수십 번 읽힌다.** 장치 하나를 고치는 것보다
문구 한 줄이 판단에 더 크게 작용한다. 그런데 그 한 줄이 지금 숫자를 앞세운다.

## 2. 문제 정의

```
① 신호가 늦다        책임이 둘이 된 시점이 아니라 400 줄에서 울린다
② 프레임이 틀렸다     리마인더·파일명이 "줄 수" 를 앞세운다
③ 설계 단계가 무강제  "코드 전에 파일 구조를 설계한다" 는 규칙에 장치가 없다
```

★ ③ 이 근본이다. ①②는 사후 감지이고, ③ 은 애초에 그 상황이 안 생기게 한다.

## 3. 설계 결정

### 3.0 지배 원칙

```
교리는 건드리지 않는다        core-beliefs.md#r-size 는 이미 옳다
차단은 늘리지 않는다          경고는 경고로 둔다. 판단은 사람·에이전트가 한다
오탐이 규율을 죽인다          과발화하는 순간 사람이 꺼 버린다 → 지금보다 나빠진다
근거 없는 숫자를 박지 않는다   임계는 이 저장소 파일들을 실측해 정한다 [P4]
```

### 3.1 리마인더 문구를 뒤집는다 (우선순위 1)

```
지금   "파일 책임을 좁게 유지하고 soft 400 / hard 500 줄을 넘기기 전에 분리."
바꿈   "한 파일은 한 책임만 진다. 책임이 둘이 되면 그 자리에서 분리.
        400/500 줄은 안전망이지 분리 시점이 아니다."
```

- 대상: `assets/hooks/claude-userpromptsubmit-reminders.sh:117` — **한 줄**
- 판정: 그 문장을 읽고 *"400 줄까지는 괜찮다"* 로 읽히지 않는다
- ⚠️ 다른 줄과 길이·어조를 맞춘다. 리마인더가 길어지면 전체가 안 읽힌다

★ **비용이 가장 싸고 노출이 가장 잦다.** 여기부터 한다.

### 3.2 400 줄 전에 울리는 대리 지표

책임 수는 못 센다. 그러나 **"책임이 늘었을 가능성"의 값싼 대리 지표**는 있다.

```
마크다운   최상위 절(## ) 개수 · 하위 절을 N 개 이상 거느린 절의 수
파이썬     최상위 def/class 개수 · import 군집 수
TS/JS      export 심볼 개수
```

#### 실측 결과 (2026-08-21) — 절대값 후보는 탈락했다

`terminal-shipping/docs/design-docs` 21 개 문서의 **전체 커밋 이력**과 이 저장소 파일들을
재생해 세 후보를 위반 사례와 대조했다. 위반의 기준점은 `9752c8a` — `data-model.md` 에
물리 설계가 들어와 책임이 둘이 된 커밋이다.

| 후보 | 위반 시점 값 | 판별력 |
|---|---|---|
| 줄 수 (현행) | **397 줄** | ✗ soft 400 을 3 줄 차이로 비껴감 (그나마 `.md` 라 재지도 않음) |
| 절 개수 절대값 | 뚱뚱한 절 2 | ✗ **못 가름.** 이 저장소 spec 17 개 중 7 개가 같은 값 — **이 문서 자신 포함** |
| **한 편집의 하위 절 증가량 Δ** | **+13 (4→17)** | ✓ 전체 1 위. 2 위 +9, 나머지 **전부 +3 이하** |

★ **절대값으로는 어떤 임계를 잡아도 이 설계 문서 자신이 오탐에 걸린다.** §5 의 첫 위험이
가설이 아니라 실측 사실이었다. 판별력이 있었던 것은 **변화량뿐이다.**

#### 확정

```
지표    마지막 커밋(git show HEAD:) 대비 최상위 심볼 증가량
        .md → 하위 절(###) · .py → 최상위 def/class · TS/JS → export
임계    RESP_DELTA_WARN = 5
```

- **임계 5 의 근거**: 마크다운은 3 과 9 사이, 코드는 3 과 6 사이가 비어 있다.
  두 실측이 같은 간극을 가리켜 한쪽 숫자를 다른 쪽에 옮겨 심지 않았다.
  (코드 표본 분포 — 0:39 · 1:8 · 2:5 · 3:1 · **간극** · 6:1 · 8:1 · 10:1)
- **기준선을 HEAD 로 잡는 이유**: 상태 파일이 필요 없고, 커밋마다 스스로 재설정된다.
- **HEAD 에 없는 신규 파일은 건너뛴다**: 기준선이 없으면 "증가" 를 말할 수 없고,
  한 번에 써 내려간 새 문서가 전부 오탐이 된다.
- **줄 수 경고가 이미 나갔으면 침묵한다**: 그쪽이 이미 "책임을 세라" 고 말한다.
  겹치면 경고 피로 → §3.0.
- ⚠️ **표본은 21 개 문서·한 저장소다.** 임계 5 는 이 표본에서의 간극이지 보편 상수가 아니다.
  `.harnessrc` 의 `RESP_DELTA_WARN` 으로 조정한다.

- 대상: `assets/hooks/claude-posttooluse-size-warn.sh` 에 발화 조건 추가
- 판정: 책임 둘인 300 줄 파일이 경고를 받는다 / 정상 파일이 과발화하지 않는다

⚠️ **파일명 자체가 줄 수 프레임이다.** `size-warn` → `responsibility-warn` 이 맞다.
다만 이름이 `claude-settings-hooks.json`·`setup.sh`·`uninstall` 에 박혀 있어
**이름 변경은 별건으로 뺀다** — 섞으면 되돌리기가 어려워진다.

### 3.3 설계 게이트 — 책임 수는 못 세도 "설계 유무" 는 센다

```
PreToolUse(Write)   새 디렉터리에 첫 파일을 만들려 할 때
                    → active/ 계획서에 그 조각의 파일 구조가 적혀 있는가
                    → 없으면 경고 (차단은 3.0 에 따라 하지 않는다)
```

★ **관행이 이미 있다.** terminal-shipping 의 `webapp-foundation` §4 가
**파일별 책임을 한 줄씩** 적어 두었다. 훅은 *그것이 있는지*만 보면 된다.

⚫ **미결**

```
"새 디렉터리" 판정          git 추적 파일이 0개인 디렉터리?
계획서에서 무엇을 찾나       파일 경로 문자열? 특정 절 제목?
R-plan-missing 과의 관계     그쪽은 커밋 시점 "계획서가 있나",
                            이쪽은 쓰기 시점 "파일 구조가 적혀 있나"
                            → 합치는 편이 나을 수 있다
```

### 3.4 pre-commit 은 건드리지 않는다

`assets/hooks/pre-commit.sh` 의 R-size 차단(500)은 **지금대로 둔다.**
문제는 안전망이 아니라 **안전망이 유일한 신호라는 점**이다.

## 5. 위험

| 위험 | 징후 | 대응 |
|---|---|---|
| **대리 지표 오탐** | 한 책임인데 절이 많은 문서가 경고를 받음 | 임계를 실측으로. 차단 아님 |

| **설치본 미반영** | 이 저장소만 고쳐짐 | §4 ③ |

## 6. 발견

- ★ **이 문서의 발단이 에이전트 자신의 위반이다.** 하네스가 잡지 못한 위반을
  사람이 지적해 드러났다. **장치가 못 잡는 영역이 어디인지 알려주는 표본**이므로
  그 경로 자체를 기록으로 남긴다
- ⚫ **이 문서의 유력 후보(절 개수 절대값)를 실측이 탈락시켰다.** 그것도 **이 문서 자신이
  오탐 표본으로 잡히는** 방식으로. §3.0 의 *"근거 없는 숫자를 박지 않는다"* 가 없었다면
  그럴듯한 임계를 하나 박고 넘어갔을 것이다. **실측을 미결로 남긴 것이 설계를 구했다.**
- ⚠️ **`size-warn.sh` 는 이미 옳은 말을 하고 있었다.** 새 문장을 지어낼 필요가 없다 —
  **그 문장이 나오는 시점만 옮기면 된다.** 이것이 이 설계의 핵심이다
