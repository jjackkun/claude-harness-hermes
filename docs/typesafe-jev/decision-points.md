# 하네스 안의 판단 지점 — Jev 로 넘길 수 있는가

> 작성일: 2026-09-21
> 목적: "에이전트 고르기·검색·분류를 Jev 로 처리하면 토큰과 시간이 준다" 는 가정을 하네스의 실제 판단 지점마다 대 본다.

## 개요

> **2026-09-21 보정 — 이 문서는 하네스 스크립트 안만 봤다.** 세션 안에서 Claude 가 Playwright MCP 로 브라우저를 한 단계씩 움직이는 루프가
> 빠져 있었고, 그 자리가 가장 크다: 2,794턴 · 입력 약 13억 토큰(전체의 7.5%) · 단계당 컨텍스트 46.5만. → [playwright-in-sessions.md](playwright-in-sessions.md).
> 아래 "토큰이 거의 줄지 않는다" 는 **하네스 스크립트의 판단 지점 18곳에 한한** 결론이다.

**가정은 절반만 맞다.** 판단 지점은 많지만 **Claude 토큰이 실제로 줄어드는 곳은 거의 없다.**
판단 지점은 누가 판단하느냐에 따라 세 부류로 나뉘고, 부류마다 Jev 가 주는 것이 다르다.

| 부류 | 누가 판단하나 | Jev 로 바꾸면 | 개수 |
|---|---|---|---|
| **A** | 세션 안의 Claude (에이전트·스킬·도구 고르기) | **줄지 않는다** — 판단이 Claude 의 턴 안에 녹아 있다 | 4 |
| **B** | 스크립트의 규칙 (FTS·토큰 겹침·정규식·카운터) | 토큰은 원래 0. **정확도·회상이 오를 수 있고** Jev 크레딧·지연·외부 전송이 생긴다 | 7 |
| **C** | 백그라운드 `claude -p` | 고르는 일이면 **Claude 크레딧이 준다.** 글을 쓰는 일이면 Jev 가 할 수 없다 | 7 |

C 에서 고르는 일은 둘뿐이고, 그 둘은 도는 횟수가 거의 0 이다(C1·C2).
그래서 "토큰 절감" 은 이 저장소에서 측정 가능한 크기가 되지 않는다.
Jev 의 실제 이득은 **B 의 빈손 구간을 메우는 것**이다 — 기획서([proposal.md](proposal.md))가 고른 자리가 여기다.

실측은 모두 2026-09-21, `.hermes/hooks.log`(3,379줄)와 코드 기준이다.

## A. 세션 안의 Claude 가 판단하는 곳

| # | 판단 | 지금 | Jev 로 바꾸면 |
|---|---|---|---|
| A1 | 어느 서브에이전트를 부를까 | Claude 가 `Agent` 도구의 `subagent_type` 을 고른다. `claude-pretooluse-agent-guard.sh` 는 고른 **뒤에** 검사만 한다 | 훅이 Jev 를 불러도 Claude 는 이미 토큰을 쓴 뒤다(PDF 10쪽 "내부 도구 방식" 과 같은 구조) |
| A2 | 어느 스킬을 부를까 | Claude 가 스킬 목록 설명을 읽고 `Skill` 을 부른다 | 같음 |
| A3 | 무엇을 검색할까·어느 파일을 볼까 | Claude 가 Grep·Read 를 고른다 | 훅은 컨텍스트를 **더할** 수만 있고 Claude 의 탐색을 뺄 수 없다 |
| A4 | 사용자 요청이 단순 명령인가 | Claude 가 해석한다 | 앞단에서 가로챌 대상이 994건 중 3건(0.3%) — [proposal.md](proposal.md) §2 ① |

**A 를 줄이는 유일한 방법은 판단을 Claude 밖으로 완전히 빼는 것**(PDF 의 래퍼 CLI)인데, 빼낼 요청이 0.3% 였다.
`UserPromptSubmit` 에서 "이 에이전트를 쓰라" 고 미리 넣어 주는 방법은 토큰을 **늘린다**. 잘못된 dispatch 가 줄어 시간이 줄지는 잴 수단이 없다.

B 에서 Jev 는 **Claude 토큰을 줄이지 않는다.** 원래 모델을 안 쓰기 때문이다.
얻는 것은 빈손·오판 감소이고, 치르는 것은 Jev 크레딧·호출 지연·프롬프트 외부 전송이다.

## C. 백그라운드 `claude -p` 가 판단하는 곳

모두 `claude-haiku-4-5-20251001` 을 쓰고 월간 프로그래매틱 크레딧에서 빠진다(`docs/design-docs/claude-p-policy-change-2026-06.md`).
세션이 끝난 뒤 도는 것이 대부분이라 **사용자가 기다리는 시간은 원래 없다.**

| # | 무엇 | 출력 | 횟수 (hooks.log) | Jev 로 |
|---|---|---|---|---|
| C1 | 스킬이 일반 지식인가 (`hermes_mesh_gate.py:63` 프롬프트) | **`GENERAL` / `SPECIFIC` 한 단어** | 사람이 `hermes-propose.py` 를 칠 때만. 전역 공유 스킬 **0개** | **모양은 완벽**(Noul). 횟수가 0 이라 줄어드는 양도 0 |
| C2 | 스킬 검색 뉘앙스 폴백 (`hermes_search_fallback.py:78`) | 스킬 고르기 | **0** — 운영에서 꺼짐 | = B1 |
| C3 | 드림 결정화 후보 (`hermes-dream.py:174` `PROPOSE_PROMPT`) | 새 kebab-case 키 목록 또는 `NONE` | 약 20회 | 키를 **지어내는** 일이라 못 한다. `NONE` 여부만 먼저 거르는 문지기는 가능하나 횟수가 작다 |

`harness-eval` · `hermes-summon` · `hermes-loop` · `hermes-manager` · `hermes-cron-run.sh` 의 `claude -p` 는 **에이전트가 일을 하는** 호출이라 판단 지점이 아니다.

## 결론

1. **"토큰을 줄인다"** — 측정 가능한 크기로는 안 된다. 고르는 일을 하는 `claude -p` 는 C1·C2 둘인데 둘 다 도는 횟수가 거의 0 이다. 요약·결정화처럼 크레딧을 쓰는 곳은 전부 글쓰기라 Jev 가 대신할 수 없다.
2. **"시간을 줄인다"** — 사용자가 기다리는 판단은 B1·B2 뿐이다. 지금은 폴백을 꺼서 기다림이 0 이고 대신 빈손이다. Jev 는 "기다림 0 을 유지하며 빈손을 메우는" 선택지다.
3. **Jev 의 실제 자리** — B1·B2(스킬 검색 빈손)가 1순위, B3(진화 대상 고르기)가 2순위다. B3 는 오판하면 스킬을 덮어쓰므로 B1 의 그림자 운영 결과를 본 뒤에만 연다. 그리고 그보다 먼저 진화 힌트 입력의 오탐을 고쳐야 한다(아래 "발견").

## 발견 — Jev 와 별개

- **진화 힌트가 사람이 쓰지 않은 글에서 나오고 턴마다 되풀이된다.** `pip` 292회, `docker` 290회 빈손. `pip` 는 `pipeline`·`pipefail`·`R-pipe` 가 부분 문자열로 걸린 것이 절반 이상이고, "피드백" 본문은 서브에이전트 반환·압축 요약·스킬 본문이었다. 공장에서 진화된 스킬은 0개지만 소우주 3곳에서 19개가 96번 고쳐졌고, 재현한 48번은 전부 비인간 글이 근거였다. B3 를 Jev 로 바꾸기 전에 입력부터 고쳐야 한다 — 백로그 `docs/exec-plans/backlog/evolve-hint-false-positive.md`.
- **B2 는 호출 여부가 기록되지 않는다.** assist 훅은 결과를 stderr 로만 `hooks.log` 에 남겨 몇 번 돌았고 몇 번 빈손이었는지 셀 수 없다. B1 처럼 `enter`·`injected`·`empty` 를 남겨야 B2 도 잴 수 있다.
