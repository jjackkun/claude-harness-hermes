# Jev 기획서 — 스킬 검색 빈손 구간을 결정 모델로 메운다

> 작성일: 2026-09-21
> 목적: TypeSafe Jev 를 하네스의 어디에 붙이고 어디에 붙이지 않을지, 무엇을 재서 판단할지 정한다.
> 상태: **제안 — 착수 전.** 사용자 결정 2건(§4 D1·D2)이 있어야 P0 를 시작한다.

## 개요

**원래 질문 "Jev 를 앞단에 두면 Claude 를 덜 쓰게 되나" 에 대한 답은, 이 저장소의 사용 방식에서는 거의 아니다** 이다.

- PDF 가 권한 "앞단 게이트웨이" 는 단순 명령 요청을 가로채는 구조다. 이 프로젝트의 실제 프롬프트 994건 중 그런 요청은 **3건(0.3%)** 이었다.
- Claude 사용량의 대부분은 턴마다 다시 들어가는 컨텍스트다. 세션 고정 비용만 **53,992 B ≈ 18,000 토큰**이다(`docs/exec-plans/completed/2026-09-21-context-budget.md:15`). Jev 는 이것을 줄이지 못한다.

대신 Jev 가 정확히 들어맞는 자리가 하나 있다. **스킬 검색이 후보를 하나도 못 찾는 14.1%**(818회 중 115회)다.
이 자리의 뉘앙스 폴백은 `claude -p` 가 턴을 최대 30초 멈추게 해서 꺼 두었다. Jev 의 **Choice**(목록에서 고르기)는 공식 예시 기준 0.114초이고 Claude 크레딧을 쓰지 않는다.

이 기획은 **비용 절감이 아니라 기능 복구**다. 그 한 자리만 재고, 결과가 좋을 때만 넓힌다.

> **2026-09-21 보정 — 비용 절감 자리가 하나 있었다.** 위 결론은 하네스 스크립트와 "앞단 게이트웨이" 만 본 것이다.
> 세션 안의 **Playwright MCP 루프**는 2,794턴 동안 입력 약 13억 토큰(전체의 7.5%)을 읽었고, 한 단계를 정할 때마다 평균 46.5만 토큰을 다시 읽었다.
> 여러 단계를 Claude 밖의 러너에 통째로 맡기면 이론상 최대 약 9.6억 토큰이 빠진다. 절감의 대부분은 **맡기기**에서 나오고,
> Jev 는 그 러너 안에서 선택자를 모르는 단계(28%)를 고르는 부품이다. 측정·구조·먼저 할 일은 [playwright-in-sessions.md](playwright-in-sessions.md).
> 단, 스크립트로 바꾼 실제 사례 96번을 보면 **동작은 제대로 하지만 확인 하나마다 Claude 턴 하나**여서 토큰은 거의 그대로였다.
> 토큰이 주는 것은 여러 확인을 스크립트 하나로 **묶는 검증 구간**뿐이다(같은 문서 §5-1). 9.6억은 그 조건을 모두 채웠을 때의 상한이다.
> 화면 스냅샷은 고객 데이터가 섞여 **Jev 로 보내지 않는다**(사용자 판단, 2026-09-21) — 러너의 기본값은 Jev 없음.

숫자의 출처와 확인 상태는 [fact-check.md](fact-check.md), 원본 내용은 [source-notes.md](source-notes.md) 에 있다.

## 1. 배경 — 이 사용자의 비용은 무엇으로 청구되나

| 경로 | 청구 방식 | 근거 |
|---|---|---|
| 대화형 Claude Code 세션 | 구독 한도 (토큰 단가로 청구되지 않음) | `docs/design-docs/claude-p-policy-change-2026-06.md` "적용 제외: 대화형" |
| 백그라운드 `claude -p` (요약·드림·결정화 등) | 월간 프로그래매틱 크레딧 (Max 20x ≈ $200, 이월 없음) | 같은 문서 |
| Jev | 입력 $0.042 / 100만 토큰, 출력은 PDF 기준 무료, **매달 $5 크레딧** | 공식 가격 · 사용자 콘솔 화면 |

PDF 의 "Opus 대비 119배 저렴" 같은 비교는 **토큰 단가로 청구될 때만** 돈이 된다.
구독 사용자에게 절감의 단위는 달러가 아니라 **한도 여유**이고, 그 여유는 Claude 호출이 실제로 빠질 때만 생긴다.

매달 $5 는 5 ÷ 0.042 ≈ **1억 1,900만 입력 토큰**이다. 아래 후보는 이 크레딧 안에서 도는지로 비용을 판단한다.

## 2. PDF 제안을 이 저장소에 대 보면

| PDF 제안 | 이 저장소 실측 | 판정 |
|---|---|---|
| ① 결정적 명령을 앞단에서 처리 ("테스트 돌려줘") | 994건 중 3건(0.3%), 셋 다 결과 해석을 요구. 짧은 명령형 87건 중 84건은 "커밋 푸시" — 메시지 작성·게이트 처리가 필요 | **안 한다** — 걸러낼 것이 없다 |
| ② 파일 좁히기 (Context Pruning) | 훅은 컨텍스트를 **더할** 수만 있고 모델이 스스로 파일을 찾는 것을 뺄 수 없다. 효과를 잴 수단도 없다 | **안 한다** |
| ③ 읽기 전용 질문을 로컬 문서로 답하기 | Jev 는 답을 쓰지 못한다(결정 값만 반환). 답을 만들 다른 주체가 필요 | **안 한다** |
| ④ 루프 헛바퀴 차단 | 이미 있다 — `scripts/hermes_loop.py:23` `NO_PROGRESS_LIMIT = 3` | **안 한다** — 규칙으로 풀린 문제 |
| Claude Code 내부 도구로 Jev 호출 | PDF 스스로 "비용 절감 효과는 거의 없다" (10쪽) | **안 한다** |
| 요약·드림·결정화의 `claude -p` 대체 | 모두 텍스트 생성. Jev 가 할 수 없다 | **안 한다** |
| 스킬 검색 빈손 구간의 뉘앙스 폴백 | 14.1% 빈손, 폴백은 지연 때문에 꺼져 있음 (`scripts/hooks/claude-userpromptsubmit-reminders.sh:109-112`) | **한다** — §3 |

하네스 전체의 판단 지점 18곳(세션 안 Claude 4 · 스크립트 규칙 7 · 백그라운드 호출 7)을 같은 방식으로 대 본 표는 [decision-points.md](decision-points.md) 에 있다.

## 3. 제안 — 스킬 검색 폴백을 Jev Choice 로

### 무엇을 바꾸나

지금 흐름:

```text
사용자 프롬프트 → hermes-search.py (FTS5 토큰 일치)
  ├─ 후보 있음 (85.9%) → 스킬 주입
  └─ 후보 없음 (14.1%) → --no-fallback 이라 아무것도 안 함
```

제안 흐름:

```text
사용자 프롬프트 → hermes-search.py (FTS5 토큰 일치)
  ├─ 후보 있음 → 스킬 주입 (변경 없음)
  └─ 후보 없음 → Jev Choice(마스킹한 프롬프트, 스킬 설명 목록)
        ├─ confidence ≥ τ → 고른 스킬 주입
        ├─ confidence < τ → 아무것도 안 함 (지금과 같음)
        └─ 키 없음 · 제한시간 초과 · 오류 → 아무것도 안 함 (지금과 같음)
```

### 왜 이 자리인가

1. **질문 모양이 그대로 맞는다.** "이 프롬프트에 맞는 스킬은 목록 중 무엇인가" 는 Choice 의 정의("Choose an option from a list")다.
2. **교체 지점이 하나다.** 폴백 자리(`scripts/hermes_search_fallback.py` 의 `haiku_fallback`)가 이미 있다. 호출 대상만 바꾸면 된다.
3. **틀려도 손해가 작다.** 잘못 고르면 관계없는 스킬 하나가 주입될 뿐, 아무것도 막지 않는다. 신뢰도가 낮으면 지금처럼 빈손이다.
4. **꺼 둔 이유를 정면으로 없앤다.** 꺼 둔 이유는 품질이 아니라 30초 지연이었다.

### 무엇을 얻고 무엇을 잃나

- 얻는 것: 빈손 14.1% 구간에서 스킬 회상. Claude 크레딧 사용 0.
- 잃는 것: 주입되는 만큼 Claude 입력이 조금 늘어난다(주입 1회 평균은 P0 에서 `injected bytes` 로 잰다). 프롬프트가 제3자에게 나간다(§4 D2).

### 설계 원칙 (구현 계획서에서 파일 단위로 풀 것)

- **실패는 지금 동작으로 떨어진다.** 키가 없거나, 제한시간을 넘기거나, 오류가 나면 조용히 빈손. 사용자 턴을 막지 않는다.
- **제한시간은 훅의 지연 예산에서 정한다.** 기존 훅 경로의 실측 지연과 Jev 실측 지연(P0)을 보고 정한다. 미리 숫자를 박지 않는다.
- **τ 는 P1 그림자 기록에서 정한다.** PDF 사례의 0.7·0.8·0.95 는 다른 과제의 값이라 옮겨 쓰지 않는다.
- **원문을 기록하지 않는다.** 기록에는 프롬프트 해시·후보 수·고른 스킬·신뢰도·지연·입력 토큰만 남긴다.
- **키는 저장소 밖에 둔다.** 환경변수로만 읽고 `R-secret` 게이트가 지킨다.
- **공장 전용 · 선택 사항.** 프리셋에 넣지 않는다. 12곳 전파는 P3 에서 따로 결정한다.

## 4. 사용자가 정할 것

### D1. R3 에 Jev 가 걸리나

- R3 원문(`assets/rules/harness/rules.md`): "`anthropic` SDK 설치·import·호출 전부 금지. **모든 LLM 호출은 구독 CLI 어댑터 경유.**"
- 문구 그대로면 Jev 호출도 금지다. 한편 이 규칙의 표적은 Claude 호출의 과금 경로다(`docs/design-docs/agent-eval-llm-path.md:17`). 비슷한 도구를 거절했던 이유도 "구독 트래픽이 종량제로 넘어간다" 였다(`docs/exec-plans/backlog/agent-model-routing-blindspot.md`). Jev 는 Claude 트래픽을 대신 받지 않는다.
- 선택지: **(가)** R3 에 "Claude 호출에 한한다. Claude 가 아닌 결정 모델은 opt-in·fail-open 조건에서 허용" 을 덧붙인다. **(나)** R3 를 그대로 두고 이 기획을 접는다.
- 제안: (가). 규칙 문구를 바꾸는 일이라 사람이 정한다.

### D2. 프롬프트를 외부로 보내도 되나

- 폴백이 도는 순간 사용자 프롬프트(이 저장소 기록상 최대 6,341자)가 TypeSafe 서버로 간다. 비밀값이나 개인정보가 섞일 수 있다.
- 약관 확인 (2026-09-21, `typesafe.ai/privacy`): 입력을 **학습에 쓰지 않는다.** 그러나 보관 기간은 "서비스에 필요한 동안 또는 사업·상업적 목적을 위해" 로 **사실상 기한이 없고**, 보관하지 않는 옵션이 없다. 저장 위치는 미국.
- 조건안: 이미 쓰고 있는 `hermes-sync` 업로드 전 마스킹을 그대로 거친다. 보내는 길이는 P0 에서 q_len 분포를 보고 정한다.
- 판단: 사용자가 2026-09-21 에 "Jev 서버로 보내면 안 되지 않나" 라고 물었다. 한 번 보내면 되돌릴 수 없으므로 **고객·업무 데이터가 섞일 수 있는 입력은 보내지 않는 것**이 기본이다. 이 폴백을 열려면 사용자가 "마스킹을 거친 프롬프트는 보내도 된다" 를 명시적으로 정해야 한다.

## 5. 단계와 판단 기준

| 단계 | 하는 일 | 끝 조건 | 멈추는 조건 |
|---|---|---|---|
| **P0 사실 확인** | `docs.typesafe.ai/api.md` 와 약관을 읽는다 → 키 발급 → 실제 호출 1회 | [fact-check.md](fact-check.md) 의 미확인 칸(엔드포인트·인증·요청 필드·입력 한도·지연·크레딧 차감)이 값으로 채워진다 | 입력을 학습에 쓴다 · 텍스트 입력을 받지 않는다 · 호출 1회 지연이 기존 훅 예산을 넘는다 |
| **P1 그림자 운영** | 빈손 구간에서 Jev 를 부르되 **주입하지 않고** 기록만 한다 | 기간은 이 저장소의 관측 관례인 3주(`R-out` 과 같은 기간). 기록된 판정을 사람이 전수 검토해, 신뢰도가 높은 구간일수록 실제로 맞는지(보정)를 본다. τ 를 여기서 정한다 | 신뢰도와 정답 여부가 무관하다(보정이 성립하지 않는다) · 3주 사용량이 월 $5 를 넘는 추세다 |
| **P2 주입 켜기** | 이 저장소에서만 τ 이상일 때 주입 | P1 과 같은 3주 동안 사용자가 "관계없는 스킬이 붙었다" 고 지적한 건수를 기록한다. 기준값은 P1 결과를 본 뒤 사용자가 정한다 | 사용자가 끄라고 한다 |
| **P3 전파 결정** | 12곳에 옵션으로 보낼지 정한다 | `claude-harness-hermes-install` 규칙에 따라 사용자 승인 | — |

P1 의 판정 데이터는 **실제 프롬프트에서 나온 기록만** 쓴다. 만든 예시 문장으로 적중률을 재지 않는다.

## 6. 하지 않는 것

- `claude` 앞에 두는 래퍼 CLI, `UserPromptSubmit` 에서 프롬프트를 막는 게이트 — §2 ①
- Claude Code 안에서 Jev 를 도구로 부르기 — §2
- 텍스트 생성 경로의 대체 — §2
- 오픈소스 대체재(OpenJev 등) 로컬 구동 — 존재를 확인하지 않았고, GPU·설치는 사용자 몫이다(WSL)
- 소우주 앱 코드(예: 다른 프로젝트의 분류·라우팅)에 Jev 붙이기 — 프로젝트마다 따로 정할 일이다. 공식 스킬(`typesafe-ai/skills`)이 바로 그 용도다

## 8. 이 기획이 틀렸다면

- 0.3% 가 과소 추정이라면 — 키워드와 길이 기준이라 표현이 다른 명령 요청을 놓쳤을 수 있다. 대화 기록 994건을 사람이 훑어 명령형 요청이 1% 를 넘으면 §2 ① 을 다시 연다.
- 빈손 구간의 프롬프트가 원래 스킬이 필요 없는 잡담이라면 — P1 전수 검토에서 "맞는 스킬이 목록에 없었다" 비율이 높게 나온다. 그러면 Jev 가 아니라 검색 자체가 옳게 빈손이었던 것이고, 이 기획은 접는다.
