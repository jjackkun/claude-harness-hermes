# 원본 정리 — "how to zev" 대화 기록

> 작성일: 2026-09-21
> 목적: `docs/temp/how to zev.pdf`(26쪽)의 내용을 빠짐없이 질문 단위로 옮겨 적는다.

## 개요

- 형식: 사용자와 다른 AI 챗봇의 대화 캡처. 사용자 메시지 16개를 이어지는 것끼리 묶어 14개 절로 적었다(Q12 는 연속 메시지 2개, Q14 도 2개).
- 여기 적힌 가격·배수·프로젝트 이름·프로모션은 **그 챗봇이 한 말**이다. 확인 상태는 [fact-check.md](fact-check.md) 에 따로 적는다.
- `[잘림]` 은 원본 자체가 잘려 읽을 수 없는 곳이다.

## Q1. typesafe.ai 를 알고 있나 (1–2쪽)

- 표방: "사람을 위한 챗봇이 아닌, 머신(코드)을 위한 결정 모델". JSON Mode·Structured Outputs 와 겉보기엔 비슷하지만 설계 철학과 동작 방식이 다르다고 한다.
- **Not Chat, Decisions** — 일반 LLM 은 RLHF 로 대화 선호에 맞춰져 모드 붕괴·과도한 확신·신뢰성 부족이 생긴다. TypeSafe 는 새 모델 분류 **System One Model**(대표 모델 **Jev**)을 만들었고, 대화 텍스트 대신 소프트웨어가 곧바로 파싱·실행할 정형 데이터(Typed Decisions)를 돌려준다.
- **RLCD** (Reinforcement Learning for Calibrated Decisions) — 자체 학습 알고리즘과 새 샘플러. 모든 결정에 보정된 신뢰도(Calibrated Confidence)를 붙인다. 신뢰도가 임계값 이상이면 자동 실행, 낮으면 사람·별도 검증으로 넘긴다(Fallback).
- **속도·비용** — 긴 텍스트 디코딩을 생략해 일반 LLM 대비 100~200배 빠르고, 10억 입력 토큰당 $42 수준. 분류·라우팅·조건 검증 같은 결정 단계에 맞춘 사양.
- 실무 의의 — 파이프라인·에이전트의 골칫거리인 비결정성(파싱 에러·환각·느린 속도)을 "코드 블록처럼 작동하는 작고 신뢰도 높은 결정 전용 모델"로 풀어 Router·Guardrail·Evaluator 에서 신뢰성을 확보하려는 시도.

## Q2. Claude Code Pro Max 로 10억 입력이면 얼마인가 (2–3쪽)

챗봇이 제시한 표(100만 토큰당 입력가 → 10억 토큰 비용):

| 모델 | 1M 당 입력가 | 1B 입력 비용 |
|---|---|---|
| Claude Opus | $5.00 | $5,000 (약 670만 원) |
| Claude Sonnet | $3.00 | $3,000 (약 400만 원) |
| Claude Haiku | $1.00 | $1,000 (약 135만 원) |
| TypeSafe Jev | $0.042 | $42 (약 5만 6천 원) |

- Sonnet 대비 약 71배, Opus 대비 약 119배 저렴.
- 사이트의 "238x Lower than Claude Fable 5.1" 은 $10/1M(1B 당 $10,000) 모델 기준이라고 설명.
- **왜 10억 토큰이나 쓰나** — 에이전트는 파일 트리·코드 파일·직전 대화(수만~수십만 토큰)를 매 턴 전부 다시 넣는다(Context Amplification). 10턴이면 세션 하나에 수백만 토큰. 조건 분기·파일 분류·도구 선택 같은 결정마다 큰 LLM 을 부르면 비용과 지연이 기하급수로 는다.
- `[잘림]` "핵심 요약" 제목 뒤 본문이 3쪽에 없다.

## Q3. 대체재가 Threads 에 쏟아진다 (4–5쪽)

2026년 9월 중순 공개 직후 리버스 엔지니어링·오픈소스 대체재가 나오고 있다고 한다. Jev 는 클로즈드 베타/웨이트리스트 중심 독점 API 라서 로컬 GPU(RTX 3090/4070 등)나 사내 인프라용 포크가 늘었다고 한다.

- **OpenJev · mini-jev** — Qwen3.5-4B 같은 가벼운 모델을 고정하고, 선택지(A/B/C/D) 첫 토큰의 Logit 만 바로 읽는다(Direct Logits Read). 일반 JSON 생성 대비 5배 이상 빠르고 로컬에서 비용 없이 돈다.
- **jevlike** — 입력 상태와 N개 선택지 벡터를 한 번에(Single Pass) 점수 매기는 소형 인코더/분류기.
- **vLLM PR (#57250) · MLX 병렬 디코딩 엔진** — 스키마 슬롯 단위 병렬 평가, 엔트로피/로그 확률로 신뢰도 측정.

왜 빨리 나왔나:

1. "텍스트 생성을 포기하고 Logit 만 뽑아 쓰면 된다" — `{"route": "billing"}` 을 생성·파싱하는 대신 선택지 토큰 확률만 뽑으면 병렬로 50~100ms 에 끝난다.
2. "Zero Hallucination" 의 실체 — 모델이 완벽해서가 아니라 선언한 선택지(Enum/Schema) 밖의 출력 경로를 막았기 때문(Schema Conformance by construction). Outlines·Guidance 같은 제약 디코딩으로 흉내 낼 수 있다.

비교표:

| 구분 | TypeSafe Jev | 오픈소스 대체재 |
|---|---|---|
| 핵심 장점 | RLCD 보정 신뢰도 — 0.9면 실제로 맞을 확률이 높은 보정치 | 즉시 로컬 구동, API 비용 0, 데이터 프라이버시 |
| 한계 | 웨이트리스트/얼리 액세스, 클로즈드 API 의존 | Logit 만 뽑는 수준이라 확률 보정이 Jev 보다 떨어짐 |

- 권고: 급하면 OpenJev·경량 모델 Logit 분류로 구조를 먼저 짜고, Jev 정식 키가 나오면 엔드포인트만 바꿔 A/B 해 보는 흐름이 `[잘림]`.

## Q5. API 키가 있어야 하고 돈이 드는 것인가 (7–8쪽)

- 무료 티어 없음. 크레딧 충전이나 카드 등록 방식.
- 과금: 입력 100만 토큰당 $0.042(약 56원). **출력 토큰 무료** — 확률·결정 값 몇 바이트만 돌려주기 때문.
- 체감: 간단한 결정 요청 1,000번에 약 $0.02(약 25~30원).
- 난관: 공식 콘솔은 얼리 액세스 대기열이라 승인 후 키 발급.
- 우회: OpenRouter 에 `typesafe/jev-latest`(또는 `typesafe/jev-1.13`)로 올라와 있어 바로 호출 가능, 가격 동일.
- 결론: 스킬은 무료지만 실제로 붙이려면 결제 수단이 연결된 키(공식 또는 OpenRouter)가 필요.

## Q7. 스킬로 Jev 를 쓰게 하면 Claude 비용이 줄까 (9–11쪽)

결론: 구조에 따라 극과 극. Claude Code **안**에 스킬로 얹으면 오히려 더 들고, **앞단(게이트웨이)** 에 세우면 30~50% 이상 줄일 수 있다고 한다.

효과 없는 방식 — 내부 도구로 호출:

```text
[사용자 입력]
   ⬇
[Claude Code (Opus/Sonnet) - 컨텍스트 수십만 토큰 주입]
   ⬇ "어? Jev 도구를 써서 분류해야겠네?" (Claude가 판단)
[Tool Call: Jev 호출]
```

- Claude 가 "Jev 를 부를까" 판단하는 순간 이미 비싼 입력·출력 비용이 나갔다. Jev 호출은 $0.0001 이지만 그걸 부르려고 쓴 비용이 수 센트~수십 센트.

돈을 아끼는 방식 — 앞단 게이트(라우터):

```text
[사용자 터미널 입력 / Git Hook / 이슈 생성]
   ⬇
[1단계: Jev ($0.00004)]
   • 작업 분류: 단순 문법 체크? 포맷팅? 파일 탐색? 복잡한 아키텍처 리팩토링?
   • 신뢰도(Confidence) 측정
   ⬇
[A. 단순/결정적 작업]                    [B. 고난도 리즈닝 필요]
 • 정적 분석 툴 (Ruff, ESLint) 실행        • Claude Code (Sonnet/Opus) 호출
 • 로컬 스크립트/경량 로컬 모델 처리
 ➔ Claude 호출 비용 0원!                   ➔ 꼭 필요할 때만 고가 LLM 호출
```

- 시나리오: ① "버그와 관련된 파일이 auth.py 인가 billing.py 인가" 를 Jev 로 좁혀 Claude 에게 그 파일만 넘긴다. ② 테스트 에러가 환경 문제인지 로직 문제인지 Jev 로 먼저 분류해 헛바퀴 호출을 막는다.
- 현실적 결론: 공식 스킬은 "사용자 코드베이스 안에 Jev 를 쓰는 백엔드 로직을 짜도록 돕는 가이드" 이지 Claude Code 비용을 줄이는 플러그인이 아니다. 줄이려면 쉘 단의 프런트엔드 라우터(프록시 CLI)로 구현해야 한다. `[잘림]` 문장 끝이 반쯤 잘렸다.

## Q8. 게이트웨이를 앞에 둔다는 게 무엇인가, 훅으로 잡는 것인가 (11–14쪽)

- 사용자 직관("대화 중간에 hook 이나 pre 로 먼저 잡는다")이 맞다고 답했다. 본체가 비싼 토큰으로 생각하기 전에 입구에서 가로채(Intercept) 판별하는 장치.
- **방식 A — Pre-Tool / Pre-Prompt 훅**: 입력이나 도구 실행을 가로채 Jev 에 0.1초 판별 요청, 결과에 따라 본체 호출 없이 종료하거나 로컬 스크립트로 돌린다.
- **방식 B — 터미널 래퍼 CLI/프록시**: `claude` 대신 작은 래퍼를 거친다. 가장 확실하다고 한다.

```text
[사용자 입력: "mypy 돌리고 에러 난 파일 목록만 정리해줘"]
   ⬇
[1단계: Jev 게이트웨이 (입력 토큰 극소량 소모, 0.1초)]
 - 판별: { "task_type": "DETERMINISTIC_TOOL", "target": "mypy", "confi…  [잘림]
   ⬇
 Jev 신뢰도 높음 (단순 도구/로컬 작업)     Jev 신뢰도 낮음 (복잡한 아키텍처 작업…  [잘림]
 Claude Code를 아예 켜지 않음!             Claude Code 실행 (`claude ...`)
 로컬 Bash/Python 스크립트로 mypy 실행      Sonnet/Opus가 본격적인 추론 및 수…  [잘림]
 ➔ 비용: $0.00004 (Claude 비용 0원)         ➔ 비용: Claude 정상 과금
```

걸러낼 수 있는 것 넷:

| 번호 | 유형 | 상황 | Jev 가 하는 일 |
|---|---|---|---|
| ① | 결정적 명령·정적 분석 | "린트/빌드/테스트 돌려줘", "패키지 뭐 설치됐나" | `EXECUTE_TEST` 로 판별해 Claude 없이 로컬 명령 실행 |
| ② | 파일 스코핑 (Context Pruning) | "이 버그 고치려면 어떤 파일?", "장바구니 컴포넌트 위치" | 경로 목록+질문으로 `target_files: ["src/routes/cart/+page.svelte"]` 를 좁혀 그 파일만 넘김, 입력 90% 이상 압축 |
| ③ | 읽기 전용 질의 | "DB 스키마 구조?", "FastAPI 엔드포인트 컨벤션?" | Write/Edit 인지 Read/Query 인지 분류, 조회면 로컬 벡터 DB·README 로 즉시 반환 |
| ④ | 루프 중단 (Circuit Breaker) | 같은 에러로 3~4턴 헛바퀴 | 직전·현재 에러 로그 유사도로 `IS_STUCK: true (confidence: 0.95)` 면 차단하고 사람에게 넘김 |

- 정리: 대화 중 Pre-Hook 이나 터미널 진입점의 경량 라우터로 "생각이 필요한가, 단순 분류/정적 실행인가" 를 $0.00004 판별기로 먼저 가르는 것이 게이트웨이 `[잘림]`.

## Q9. 사진 판별·분석도 되나 (14–15쪽)

- 안 된다. 텍스트 기반 비정형 상태(문자열·JSON·로그·텍스트 DOM)만 받는다. Vision Encoder 가 없고, 상태와 질문을 단일 패스로 처리해 Enum·Boolean·Score 와 신뢰도만 뽑는다. base64 이미지를 넣어도 시각 특징을 이해하지 못한다.
- 실무: 경량 VLM(Moondream2, Florence-2 등)이 이미지를 캡션·태그 텍스트로 바꾸고, Jev 가 정책·라우팅을 판정하는 2단계.

```text
[이미지 / 스크린샷]
   ⬇
[1단계: 가벼운 오픈소스 VLM (예: Moondream2, Florence-2 등)]
   • 이미지를 보고 짧은 설명/캡션/오브젝트 태그 텍스트로 변환
   ⬇
[2단계: Jev (TypeSafe System One Model)]
   • VLM이 뽑아낸 텍스트 설명 + 메타데이터를 State로 주입
   • 질문: "이 이미지가 유해 정책을 위반하는가?", "다음 클릭할 버튼이 무엇인가?"
   • 결과: { "violation": false, "category": "safe", "confidence": 0.9…  [잘림]
```

- 고가 Vision LLM(GPT-4o, Claude Sonnet Vision 등)은 비용과 지연(2~4초)이 크다. 작은 로컬 VLM 으로 요약만 뽑고 결정은 Jev(50ms, $0.00004)에 맡긴다.
- `[잘림]` 결론 "이미지를 텍스트로 설명한 메타데이터가 주어졌을 때 이를 기반으로 규칙을 판단하고 분류하는" 뒤가 없다.

## Q10. Threads 에 모인 활용 예시 (15–18쪽)

공통 특성: "50ms 이내 판별 + 보정된 신뢰도 반환".

1. **웹 스크래핑·브라우저 에이전트 — 다음 액션 결정** (반응이 가장 뜨거웠다고 함). Playwright/Puppeteer 루프에서 DOM 전체(수십~수백 KB)를 `state` 로 넣고 "로그인 폼 다음 클릭 셀렉터는?", "'다음' 버튼이 활성인가?" 를 묻는다. 페이지마다 3~5초 걸리던 것을 0.1초에 `CLICK`·`WAIT`·`SCROLL`·`FINISH` 로 받는다. confidence 0.8 미만일 때만 Vision LLM 으로 스크린샷을 보게 해 크롤러 속도를 10배 이상 올렸다고 함.
2. **CI/CD·에러 로그 서킷 브레이커** — 테스트 실패 로그·500 스택 트레이스를 넣는다.

   ```typescript
   type ErrorClassification = {
     is_transient: boolean;      // 일시적 네트워크/DB 타임아웃인가?
     requires_rollback: boolean; // 즉시 롤백해야 할 코드 결함인가?
     risk_level: "LOW" | "HIGH" | "CRITICAL";
     confidence: number;
   }
   ```

   `is_transient: true` 이고 신뢰도 0.95 이상이면 알림 없이 자동 재시도, 코드 결함이면 배포 중단 후 슬랙 알림.
3. **멀티 에이전트 오케스트레이터(라우터)**

   ```typescript
   type AgentRoute = {
     target: "SQL_AGENT" | "SEARCH_AGENT" | "REFACTOR_AGENT" | "…  [잘림]
     estimated_complexity: 1 | 2 | 3 | 4 | 5;
   }
   ```

   LangChain·LlamaIndex 의 라우팅용 Sonnet/GPT-4o 호출을 대체해 첫 응답 지연(TTFT)을 1초 이상 줄이고 비용을 거의 0 으로.
4. **사기 탐지·실시간 트랜잭션 이상 감지** — 최근 10회 행동 로그·IP 변경 이력·결제 메타데이터를 텍스트로 넣고 "어뷰징/도용 패턴과 일치하는가" 판별. 의심 확률 0.99 이상 자동 차단 / 0.60~0.85 OTP 트리거 / 0.20 이하 무검사 승인.
5. **고객 문의 우선순위 분류·에스컬레이션** — Zendesk·슬랙 채널 메시지를 `{ "churn_risk": true, "department": "ENTERPRISE_SUPPORT", "urgent": true }` 로만 추출. 1B 당 $42 라 수만 건 웹훅도 전수 조사 가능.

- 공통 공식: "결과물로 긴 글을 받아야 하는 곳에는 절대 쓰지 말고, IF/ELSE 조건문에 들어갈 boolean 이나 enum 값을 뽑는 자리에 집어넣어라." `[잘림]` "즉 텍스트 생성이 필요한 최종 단계(Claude GPT)와 전통적인 결정론적" 뒤가 없다.

## Q12. (사용자 콘솔 캡처) 매달 $5 인가, 호출하면 거기서 빠지나 (19–21쪽)

- 사용자가 콘솔 크레딧 화면을 캡처해 올렸다. 캡처는 썸네일이라 원본에서 글자를 읽을 수 없고, 아래는 챗봇이 읽어 준 내용이다.
  - Type: `Monthly credit`
  - Granted `Sep 20, 2026` / Expires `Oct 20, 2026`, 툴팁 "Oct 20, 2026 · In 29 days"
  - 일회성 가입 축하금이 아니라 매달 $5 가 지급되는 정기 크레딧이라고 해석.
- 차감: API 호출마다 $5.00 잔고에서 실시간 차감. 툴팁 "Credits closest to expiring are used first" — 나중에 카드 충전(+ Add funds)을 해도 먼저 만료되는 무료 크레딧이 먼저 빠진다.
- 자동 결제 없음: `Auto-recharge: Off`, 카드 미등록(`Needs a card on file first`). 다 쓰면 결제되지 않고 호출이 멈출 뿐.
- 우측 상단 `Try an example request` 에서 키 발급·샘플 cURL 화면으로 간다. `[잘림]` "발급받은 키로 호출해보시면 이 화면의" 뒤가 없다.

## Q13. Playwright 는 시간뿐 아니라 토큰도 줄어드나 (21–22쪽)

1. 출력 토큰 — 일반 LLM 은 CoT 와 긴 JSON 을 턴마다 수십~수백 토큰 내고 출력 단가가 입력의 3~5배. Jev 는 Enum·Selector ID 같은 단일 값만 내고 출력이 무료.
2. 컨텍스트 누적 — 챗봇형 에이전트는 `Page 1 열림 ➔ 버튼 클릭함 ➔ Page 2 로딩됨` 을 계속 쌓아 10스텝이면 수백만 토큰. Jev 는 무상태(Stateless)라 현재 DOM 과 질문만 넣는다.
3. 비교 (DOM 약 20,000 토큰, 10번 연속 클릭/입력):

| 구분 | Claude 3.7 Sonnet | TypeSafe Jev |
|---|---|---|
| 입력 토큰 비용 | 약 $0.60~$1.20 (히스토리 누적) | 약 $0.0084 (누적 없음) |
| 출력 토큰 비용 | 약 $0.05~$0.15 | $0.00 (무료) |
| 소요 시간 | 턴당 2~4초, 총 30초 이상 | 턴당 0.1초, 총 1~2초 |
| 총비용 | 약 $0.70~$1.35 (약 1,000~1,800원) | 약 $0.008 (약 11원) |

- 결론: 시간과 함께 비용도 약 1/100.

## Q14. "너무 좋은데?" 와 Top 5 (22–26쪽)

"너무 좋은데?" 에 대한 답:

- 속도: 턴당 2~4초 루프가 0.1초로 내려가 네이티브 스크립트처럼 돈다.
- 비용: 매달 $5 로 개인 크롤링·라우팅은 사실상 무제한 테스트.
- 신뢰도 연계: 신뢰도 0.7 이하에서만 고가 LLM 으로 넘기는 예외 처리.
- 콘솔 `Try an example request` 에서 키를 받아 라우팅·분기 스크립트부터 붙여 보라고 권했다.

Playwright 외 Top 5 (특성: 50~100ms 지연, $42/1B 입력, 보정된 신뢰도):

1. **비정형 문서·영수증·인보이스 스키마 추출 (ETL)** — 수십 장 PDF 전문을 `state` 로 한 번에 넣고 필드별 질문을 병렬로. Q1 "발행일자가 있는가? 있다면 ISO-8601 값은?", Q2 "결제 통화는 KRW·USD·EUR 중 무엇인가?". 전체 JSON 생성에 5~10초 걸리던 것을 필드별 0.1초. 신뢰도 0.95 이상은 DB 자동 저장, 0.7 미만은 관리자 검토 큐.
2. **멀티 에이전트 트래픽 라우터**

   ```typescript
   type RouteDecision = {
     target: "SIMPLE_SQL" | "VECTOR_SEARCH" | "HEAVY_REASONING" | "DI…  [잘림]
     estimated_difficulty: 1 | 2 | 3;
     confidence: number;
   };
   ```

   라우팅용 고가 LLM 호출로 생기던 1~2초 TTFT 를 50ms 로.
3. **실시간 트랜잭션 이상 감지** — 위험 확률 0.98 이상 즉시 차단 / 0.50~0.85 OTP·SMS / 0.15 이하 무검사 패스. 초당 수백 건도 전수 조사 가능.
4. **CI/CD 배포 로그 서킷 브레이커**

   ```typescript
   type BuildVerdict = {
     is_transient_network_error: boolean; // 일시적 네트워크 타임아웃인가
     is_code_defect: boolean;             // 코드/문법 결함인가?
     should_retry: boolean;
   };
   ```

   정규식은 새 형태의 로그를 놓치고 LLM 은 빌드를 늦춘다. 네트워크 에러면 자동 재시도, 코드 에러면 배포 중단·슬랙 알림.
5. **대규모 유입 티켓 감정/우선순위 분류** — `{ "churn_risk": true, "urgency": "IMMEDIATE", "dept": "ENTERPRISE_BILLING" }` 만 추출. 키워드 매칭이 놓치는 뉘앙스를 읽으면서 파싱 실패·환각 없이 웹훅 핸들러에 붙는다.

- 공통 관통점: "LLM 의 긴 자연어 생성 기능은 완전히 버리고, 비정형 텍스트를 읽고 IF/ELSE 조건문에 넣을 True/False 나 Enum 만 뽑아내는" `[잘림]` — 문서가 여기서 끝난다.
