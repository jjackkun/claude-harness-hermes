# 세션 안의 Playwright 루프 — Jev 가 들어갈 가장 큰 자리

> 작성일: 2026-09-21
> 목적: Claude Code 세션이 Playwright MCP 로 브라우저를 한 단계씩 움직이며 쓴 토큰·시간을 재고, 이 비용을 줄이는 구조를 정한다.

## 개요

처음 조사([decision-points.md](decision-points.md))는 하네스 **스크립트** 안의 판단만 봤고, Playwright 는 "소우주 앱의 일" 로 치웠다.
그런데 Playwright 루프는 **Claude Code 세션 안에서** 돈다. Claude 가 한 단계를 정할 때마다 세션 컨텍스트 전체를 다시 읽는다.
PDF 21–22쪽이 말한 "기록 누적" 이 이 사용자의 기록에 실제로 있었다.

| 무엇 | 값 |
|---|---|
| Playwright 호출을 정한 Claude 턴 | **2,794턴** (전체 43,332턴의 6.4%) |
| 그 턴들이 읽은 입력 | **약 13억 토큰** (전체 입력 172.5억의 7.5%) — 캐시 읽기 12.97억 · 캐시 쓰기 336만 · 새 입력 1만 |
| 한 단계를 정할 때 읽은 컨텍스트 | 평균 **46.5만 토큰** |
| 한 단계에 걸린 시간 | 중앙값 **5.7초** (75%는 9.2초 이내) — 모델 판단 + 브라우저 실행 합계 |
| 연속 구간에서 보낸 시간 | 약 **292분** (529구간) |

**줄이는 방법은 Jev 를 도구로 부르는 것이 아니다**(PDF 10쪽 — Claude 가 이미 턴을 쓴 뒤다).
**여러 단계를 통째로 Claude 밖에 맡기는 것**이다. Jev 는 그렇게 맡긴 루프 안에서 "다음에 무엇을 누를까" 를 고르는 부품이다.

## 1. 어떻게 쟀나 (2026-09-21)

- 대상: `~/.claude/projects/*/*.jsonl` 전체 (이 사용자의 모든 프로젝트 대화 기록).
- 도구 이름에 `playwright` 가 들어간 `tool_use` 를 셌다.
- 토큰: assistant 메시지의 `usage`(input · cache_read · cache_creation · output)를 **메시지 id 로 중복 제거**해 더했다. 한 메시지가 여러 줄로 저장되기 때문이다.
- 시간: 연속한 Playwright 턴 사이의 `timestamp` 차이. 600초 이상은 사람이 자리를 비운 것으로 보고 뺐다.
- 캐시 읽기가 구독 한도에서 새 입력과 같은 무게인지는 **확인하지 않았다.** 토큰 수는 사실이고, 그것이 한도를 얼마나 깎는지는 모른다.

|---|---|---|---|---|

## 3. 연속 구간 — 통째로 맡길 수 있는가

Claude 턴이 Playwright 호출만 하며 이어진 구간을 셌다.

| 구간 길이 | 구간 수 |
|---|---|
| 1 | 140 |
| 2–4 | 348 |
| 5–9 | 108 |
| 10–19 | 45 |
| 20 이상 | 16 (최장 61) |

- 5단계 이상 구간이 Playwright 턴의 **63%**(2,743 중 1,717)를 차지한다.
- 각 구간을 "도구 한 번" 으로 맡겼다면 둘째 턴부터 쓴 입력 **약 9.6억 토큰**이 빠진다. **이론상 상한**이다 — 맡긴 뒤에도 결과를 읽는 턴과 실패해서 돌아오는 턴이 남는다.
- **실측으로 보면 이 상한은 멀다.** 스크립트로 바꾼 실제 사례에서도 확인 하나마다 턴 하나였다 — §5-1.

## 4. 단계의 종류 — Jev 가 맡을 수 있는 몫

| 단계 | 횟수 | 비율 | 맡을 곳 |
|---|---|---|---|
| JS 실행으로 값 재기 (`browser_evaluate` · `browser_run_code_unsafe`) | 1,114 | 40% | **미리 만든 측정 스크립트.** Claude 가 매번 JS 를 짜던 일. Jev 는 코드를 못 쓴다 |
| 다음 행동 고르기 (click · type · fill_form · press_key · snapshot 등) | 761 | 28% | **Jev Choice** — 스냅샷의 요소 목록 중 하나 고르기 |
| 페이지 이동 (`browser_navigate`) | 515 | 19% | 스크립트 (주소가 정해져 있다) |
| 스크린샷 | 145 | 5% | Jev 불가(이미지). 필요하면 Claude 로 돌려보낸다 |
| 기타 (네트워크 요청 · 콘솔 · 크기 조절) | 225 | 8% | 스크립트 |

**절감의 대부분은 Jev 가 아니라 "맡기기" 에서 나온다.** 72% 는 Jev 없이 스크립트로 맡길 수 있는 단계다.
Jev 의 몫은 28% — 선택자를 미리 모르는 단계를 스크립트가 스스로 넘길 수 있게 해 주는 것이다.
Jev 가 없으면 그 단계에서 스크립트가 멈추고 Claude 에게 돌아와야 한다.

## 5. 이미 있는 선례 — terminal-shipping

`terminal-shipping/.claude/memory/browser-probe-headless-script.md` (2026-09-20):

- "화면 실측은 playwright MCP 대신 node 헤드리스 스크립트로" 옮겼다.
- 이유: MCP 로 비밀번호를 치면 **도구 인자로 대화 기록에 남는다.** 스크립트는 `.env` 에서 읽어 출력하지 않는다.
- 스크립트가 반복되던 함정 셋을 피한다 — 빌드 직후 리로드 중인 로그인 폼, 흘려 받는 화면의 hydration 대기, 슬래시 메뉴의 Enter 두 번.
- 스크립트는 잡 폴더에 매번 새로 쓰고 저장소에 두지 않는다.

### 5-1. 스크립트로 바꾸면 제대로 도는가, 토큰은 주는가 (2026-09-21 실측)

대화 기록 전체에서 Bash 로 `playwright-core`·`chromium.launch` 를 직접 띄운 실행을 찾았다 — **96번, 세션 7개**(zeroday-frontend·terminal-shipping).

**동작 — 제대로 돈다.**

| 결과 | 횟수 |
|---|---|
| 원하는 값을 냈다 (버튼 수·선택값·픽셀 위치 등) | 78 |
| 앱의 실제 문제를 드러냄 · 확인 실패 (예: "저장하지 못했다 — Network Error" 안내 확인) | 8 |
| 스크립트 설정 실패 — `playwright-core` 모듈을 못 찾음 | 5 |
| 타임아웃 · 페이지 이동 대기 | 5 |

스크립트 자체 문제는 10번이고, 그중 절반은 처음 경로 설정이다. 한 번 잡으면 되풀이되지 않는다.

**토큰 — 지금 쓰는 방식으로는 거의 줄지 않는다.**

- 출력은 작아졌다: 수십~수백 바이트. MCP 스냅샷(평균 3.2 KB, 최대 52 KB)보다 훨씬 작다.
- 그러나 성공한 78번 중 74번이 **스크립트 한 번에 확인 하나**였다(출력 앞 140자만 봐서 과소 추정일 수 있다). 확인 하나마다 Claude 턴 하나다.
- 토큰의 대부분은 출력이 아니라 **턴마다 다시 읽는 컨텍스트**다. 세션 `b945faad` 는 17번을 돌리며 매번 53만~73만 토큰을 다시 읽었다. MCP 로 한 단계씩 한 것과 턴 수가 같다.
- 따라서 §3 의 "약 9.6억 토큰" 은 스크립트를 이렇게 쓰면 **실현되지 않는다.**

**줄어드는 조건 — 확인을 묶을 때.** 세션 `9a6e6181` 은 스크립트 한 번으로 "목표1·목표2·목표5" 를 한꺼번에 냈다.
무엇을 확인할지 **미리 알 때**(구현을 마친 뒤의 검증)만 묶을 수 있다. 원인을 찾는 탐색은 결과를 보고 다음을 정해야 하므로 한 단계씩 갈 수밖에 없다.
러너가 줄일 수 있는 것은 **검증 구간**이고, 탐색 구간은 그대로다. 두 구간의 비율은 아직 재지 않았다(§9).

**맡기기 방향은 이미 한 프로젝트에서 검증됐다.** 아직 없는 것은 두 가지다. 이것을 다른 프로젝트도 쓰게 하는 공용 장치, 그리고 선택자를 미리 모를 때 스크립트가 스스로 고르는 부품이다.

## 6. 제안 구조

```text
Claude 턴 1회: "방 화면에서 고정 버튼 누르고 배지가 뜨는지 확인" + 알려진 단계 목록
   ⬇
[브라우저 과제 러너 — Claude 밖]
   • 이동·대기·로그인: 스크립트 (비밀값은 .env, 출력 안 함)
   • 값 재기: 미리 만든 측정 함수
   • 선택자를 모르는 단계: 스냅샷의 요소 목록 → Jev Choice
        ├─ confidence ≥ τ → 실행하고 계속
        └─ confidence < τ · Jev 오류 · 키 없음 → 멈추고 지금까지의 요약을 들고 Claude 로 돌아감
   ⬇
Claude 턴 1회: 결과 요약만 읽는다 (스냅샷 원문은 컨텍스트에 들어오지 않는다)
```

- **러너의 기본값은 Jev 없음이다.** 선택자를 모르는 단계에서는 멈추고 Claude 로 돌아온다. 새로운 외부 전송이 0 이다.
- Jev 는 **멈추는 횟수를 줄이는** 선택 부품이고, 화면에 보내도 되는 데이터만 뜨는 경우에만 붙인다(§8).
- τ 는 실측으로 정한다. PDF 의 0.8(16쪽)·0.7(23쪽)은 근거가 없는 값이라 쓰지 않는다([use-case-playwright.md](use-case-playwright.md) §5).

## 7. Jev 비용 어림

- 고르기 단계 761회 × 스냅샷 평균 3.2 KB. 바이트 수를 토큰 수의 상한으로 잡으면 약 **244만 토큰** ≈ **$0.10** (입력 $0.042/100만).
- 남아 있는 기록 전체를 합해도 매달 $5 크레딧의 한 귀퉁이다. 가장 큰 스냅샷은 52 KB 였다 — 입력 한도는 아직 모른다([fact-check.md](fact-check.md)).

## 8. 막는 조건

- **고객·화물·계정 정보가 뜨는 화면의 스냅샷은 Jev 로 보내지 않는다 (2026-09-21 사용자 판단).**
  스냅샷에는 화면의 데이터가 그대로 들어간다. TypeSafe 개인정보 처리방침은 입력을 학습에 쓰지 않는다고 하지만,
  보관 기간이 "서비스에 필요한 동안 **또는 사업·상업적 목적을 위해**" 로 사실상 기한이 없고, 보관하지 않는 옵션이 없다([fact-check.md](fact-check.md)).
  한 번 보내면 되돌릴 수 없다. 같은 화면은 지금도 Playwright MCP 를 통해 Anthropic 으로 가고 있으므로, Jev 는 **받는 회사를 하나 더 늘리는** 일이다.
  - 요소의 역할·이름만 보내는 방식도 안전하지 않다 — 버튼·링크 이름에 고객명·화물번호가 들어간다.
  - 외부 전송 없이 같은 모양의 판단을 하려면 로컬 모델(작은 오픈 모델의 선택지 확률 읽기)을 써야 한다. PDF 4쪽이 든 OpenJev 등은 존재를 확인하지 않았고, GPU·설치는 사용자 몫이다(WSL).
- **유료 호출 승인.** terminal-shipping 에는 `no-paid-calls-without-approval` 기억이 있다. 크레딧 안이어도 첫 연결은 사용자 승인으로 한다.
- **R3** — 기획서 D1 과 같은 문제.
- **배포 범위.** 러너는 공장 자산(스킬 + 스크립트)으로 만들어야 여러 프로젝트가 쓴다. 전파는 `claude-harness-hermes-install` 규칙대로 사용자가 정한다.

## 9. 먼저 할 것 — Jev 없이 재는 단계

0. Playwright 연속 구간을 **검증 구간**(무엇을 확인할지 정해져 있음)과 **탐색 구간**(결과를 보고 다음을 정함)으로 나눠 비율을 잰다. 러너가 줄일 수 있는 것은 검증 구간뿐이다(§5-1). 검증 구간이 작으면 여기서 멈춘다.
1. 과거 기록에서 **실제로 되풀이된** 브라우저 과제를 고른다(예: 로그인 → 특정 화면 → 값 재기). 만든 과제는 쓰지 않는다.
2. 같은 과제를 MCP 방식(기록에 있는 그대로)과 러너 방식으로 비교한다. Claude 턴 수·읽은 입력·걸린 시간을 잰다.
3. 러너가 멈춘 단계 중 "선택자를 몰라서" 멈춘 비율을 센다. **이 비율이 Jev 가 줄일 수 있는 몫**이다. 낮으면 Jev 는 붙이지 않는다.
