# Claude Code 모드(mods) — 패널 모드 세 개의 설계와 엔진 규칙

> 작성일: 2026-10-06
> 목적: Claude Code 의 모드 기능으로 패널 모드 세 개를 만들며 내린 결정과, 직접 부딪혀 확인한 엔진 규칙을 남겨 다음에 모드를 만들 때 같은 시행착오를 줄인다.

## 개요

| 항목 | 내용 |
|------|------|
| 대상 기능 | Claude Code 의 모드(mods): TypeScript 훅 모듈로 패널·띠·상태줄·명령을 더하는 플러그인 |
| 만든 때의 엔진 | Claude Code 2.1.290 (시험을 마지막으로 돌린 때는 2.1.291) |
| 만든 것 | 패널 모드 세 개 — `tool-calls-pane`, `hermes-roster-pane`, `file-explorer` |
| 위치 | `~/.claude/skills/<모드 이름>/` — **이 저장소 밖**이다. 이 컴퓨터에만 있고 다른 컴퓨터로 전파되지 않는다 |
| 상태 | 세 모드 모두 실제 화면에서 동작 확인(`file-explorer` 의 탭과 git 탭 포함). 시험: `file-explorer` 77건, 나머지 각 6건 통과 |
| 주의 | 엔진 타입 파일 머리말에 "EARLY ACCESS: 예고 없이 바뀔 수 있다"고 적혀 있다. 아래 규칙은 2.1.290 기준이다 |

이 문서의 "엔진 규칙"은 두 종류다. **확인**은 시험이나 실제 화면으로 본 것이고, **문서**는 엔진 타입 파일
(`claude-code.d.ts`)에 적힌 것을 읽은 것이다. 추정은 추정이라고 적는다.

## 모드의 기본 구조

모드 하나는 폴더 하나이고, 최소 파일은 셋이다.

```text
<모드 이름>/
├── .claude-plugin/plugin.json   # 이름, 버전, 설명, (상태를 쓰면) types 경로
├── hooks/hooks.json             # { "modules": ["./register.tsx"] }
├── hooks/register.tsx           # export const register: Register = on => { ... }
├── types/index.d.ts             # $.state 에 두는 값의 모양(상태 계약)
└── tests/*.test.tsx             # claude plugin test 가 돌린다
```

| 하려는 일 | 방법 |
|-----------|------|
| 엔진이 받아들이는지 검사 | `claude plugin validate <폴더>` |
| 시험 | `claude plugin test <폴더>` |
| 로드됐는지 확인 | `claude plugin list` 에서 `Status: ✔ loaded` |
| 고친 것을 열린 세션에 반영 | 저장하면 자동으로 다시 읽는다. 새 모드는 `/reload-plugins` |

**어디에 두느냐가 로드 범위를 정한다(확인).**

- `~/.claude/dev-mods/<세션 id>/` — 그 세션 전용이다. 다른 세션은 읽지 않는다. 첫 파일을 쓰면 엔진이
  "Enable hot reloading for this session?" 을 묻고, 이 답은 사람만 할 수 있다.
- `~/.claude/skills/<이름>/` — 모든 새 세션이 플래그 없이 읽는다. 세 모드를 여기에 두었다.
- `claude --plugin-dir <폴더>` — 그 세션에서만 읽는다.

같은 이름의 모드를 두 곳에 두면 둘 다 로드될 수 있다. 세션 전용 폴더에 남은 옛 사본은 지웠다.

## 만든 모드 세 개

| 모드 | 여는 방법 | 하는 일 |
|------|-----------|---------|
| `tool-calls-pane` | `/tool-calls`, 띠의 `[ 도구 호출 ]` | 이번 세션의 도구 호출을 `실행`/`완료` 줄로 쌓는다 |
| `hermes-roster-pane` | `/roster`, 띠의 `[ 에이전트 명부 ]` | `scripts/hermes-agent.py --project . roster` 의 출력을 그대로 보인다. 에이전트를 부른 직후 다시 읽는다 |
| `file-explorer` | `/files [경로]`, 띠의 `[ 파일 ]` | `editor` 탭: 폴더 트리, 문법 색이 들어간 읽기 화면, 편집·저장, 휠 스크롤과 스크롤 막대. `git` 탭: 바뀐 파일 목록과 변경 내용(읽기 전용) |

세 모드 공통:

- 프롬프트 위 띠에 여는 버튼을 하나씩 둔다. 띠는 하나뿐이라, 각 모드가 `next(e)` 로 아래 모드가 그린 것을
  받아 그 옆에 자기 버튼을 붙인다. 통째로 그리면 다른 모드의 버튼이 가려진다(확인).
- 패널 첫 줄의 오른쪽 끝에 `[ 닫기 ] [ 전체 닫기 ]` 를 둔다. `[ 전체 닫기 ]` 는 세 패널 이름을 차례로 닫는다.
  패널 이름 목록(`ALL_PANES`)은 세 모드에 각각 적혀 있으므로, 패널 모드를 더하면 세 곳을 함께 고친다.

## 결정 기록

| 결정 | 이유 | 치른 값 |
|------|------|---------|
| 문법 색에 Prism.js 를 묶어 넣었다 | 엔진의 `Code` 부품은 이 환경에서 색이 나오지 않았다(원인 미확인). 직접 만든 한 줄 단위 규칙은 여러 줄 문자열과 vue 의 구역을 못 가렸다 | 묶음 55KB. 언어는 22개만 |
| Prism 은 다른 프로젝트의 `node_modules` 사본에서 가져왔다 | 내려받기·설치 없이 끝낼 수 있고 MIT 라이선스가 복사를 허용한다 | 1.29.0 이다(당시 최신은 1.30.0) |
| vue 는 마크업 문법에 바인딩 규칙을 더한 전용 문법으로 | Prism 에 vue 문법이 없다. 바인딩 속성 값과 `{{ }}` 안을 JS 로 칠하려면 필요하다 | 마크업 문법을 고치기 전에 통째로 복제해 html·svelte 용으로 따로 둔다 |
| 에디터는 고칠 때마다 파일 **전체**를 훅으로 보낸다 | 한 프레임의 `post` 는 마지막 것만 전달된다. 변경분만 보내면 빠르게 칠 때 글자가 빠진다 | 9만 자를 넘는 파일은 편집할 수 없다 |
| 트리와 가로 막대를 화면 모듈(`Client`)로 | 엔진 `Button` 은 빠르게 누르면 글자가 선택된다. 화면 모듈은 마우스 누름을 직접 받는다 | 터미널·데스크톱에서만 된다. 단축키를 직접 만들어야 한다 |
| 휠은 마우스가 있던 곳에 따라 가른다 | 휠 이벤트가 주는 것은 줄 수와 마우스 칸뿐이다 | 가로 스크롤은 "가로 막대 위의 휠"로만 된다. Shift+휠은 구분할 수 없다 |
| 색은 테마 색 이름으로 준다 | 밝은 테마와 어두운 테마 모두에서 읽히게 | Prism 의 웹 테마 색과 다르다 |
| git 탭은 읽기 전용으로(상태와 변경 내용만) | 엔진 문서에 "git 은 저장소 훅을 끈 채 실행된다"고 적혀 있다. 모드에서 커밋하면 이 저장소의 pre-commit 게이트가 돌지 않을 수 있다(미확인) | 스테이징·커밋은 터미널에서 한다 |
| git 목록은 트리 화면 모듈을 다시 쓴다 | 같은 일(줄 나열, 마우스 누름, 세로 막대)이다 | 트리 화면 모듈이 줄마다 색(없으면 `null`)을 받게 됐다 |
| git 목록의 줄 색은 `git status` 와 같은 기준으로 | 두 글자 상태의 오른쪽(작업 폴더)이 비어 있으면 스테이징이 끝난 것이라 초록, 아니면 빨강 | 한 줄에 한 색이다. 일부만 스테이징한 파일(`MM`)은 빨강으로만 보인다 |
| 파일 트리에 git 상태 색을 넣는다(고친 것 노랑, 새 것 초록, 지운 것 빨강. 폴더는 안의 파일을 따르되 파일과 다른 색: 고친 것을 품으면 주황, 새 것만 품으면 청록) | 편집기들이 쓰는 기준이라 익숙하다. 폴더에 고친 파일과 새 파일이 함께 있으면 고친 쪽(노랑)이 이긴다 | 패널을 열 때·저장할 때·새로고침할 때 `git status` 가 한 번씩 더 돈다. git 탭의 색 기준(스테이징 여부)과 다르다 |
| 트리 폭은 세로선을 끌어 바꾼다 | 긴 파일 이름이 잘린다. 화면 모듈은 누른 뒤 뗄 때까지 영역 밖의 움직임도 받으므로, 지금 폭에 가로 이동량을 더하면 새 폭이 된다 | 폭은 세션 동안만 기억한다. 트리 12칸, 보기 화면의 글자 자리 12칸 아래로는 줄지 않는다 |
| 명부 패널은 명령 출력을 그대로 그린다 | `/hermes-roster` 스킬의 원칙("표가 곧 사실이다")을 따른다. JSON 출력이 없다 | 패널이 표보다 좁으면 줄이 접힌다 |

## 엔진 규칙

### 코드를 나눌 때

- **`$` 는 다른 파일로 넘길 수 없다(확인).** 같은 파일 안에 선언한 함수로만 넘어간다. 넘기면 모듈이 로드되지 않는다.
- **상태 참조(`atom`)도 쓰는 파일 안에 직접 적는다(확인).** 다른 파일에서 가져오면 로드되지 않는다.
  그래서 `$` 를 쓰는 파일마다 같은 `atom(...)` 선언이 반복된다.
- 반면 `on`(훅 등록 함수)과 `$.ui.resolve(e)` 가 돌려준 부품 표는 다른 파일로 넘겨도 된다(확인).
- 외부 라이브러리는 모드 폴더 안의 파일로 넣는다. `require` 가 없고 `import()` 가 든 모듈은 로드되지 않는다(문서).
  Prism 은 축소판 파일들을 이어 붙이고 끝에 `export default Prism` 한 줄을 더해 ES 모듈로 만들었다(확인).
  정규식 안에 `import(` 글자가 들어 있는 것은 문제없었다(확인).

### 상태

- **세션 상태(`$.state`)는 모드를 다시 읽어도 남는다(확인).** 상태의 모양을 바꾸면 옛 모양이 그대로 들어온다.
  읽고 쓰는 모든 자리에서 빠진 값을 채워야 한다(`reducers.ts` 의 `sane`).
- **값에 `undefined` 가 섞여 화면 모듈로 넘어가면 패널 전체가 빈 화면이 된다(확인).** 엔진이 그리다 실패하면
  그 자리를 자기 것으로 대신 그린다. 속성도 마찬가지라, 없는 속성은 `undefined` 로 두지 말고 만들지 않는다.
- 그리기 훅(`ui.render`) 안에서는 상태를 쓸 수 없다(문서). 쓰기는 버튼 처리기나 다른 이벤트에서 한다.

### 패널과 띠

- 패널의 자리는 엔진이 정한다(문서): 대화 옆(`dock`) 또는 프롬프트 위(`inline`). 모드는 폭과 높이만 요청한다.
- 모드가 혼자 여는 패널은 터미널 폭 144칸 미만이면 열리지 않는다(문서). 사람의 행동에 답해 여는 것은 폭과 무관하다.
- **모드가 스스로 부른 `$.ui.open` 은 자기 `ui.open` 훅을 거치지 않는다(확인).** 열기 전에 할 일은 여는 쪽에서 한다.
- **한 모드가 `$.ui.close({ id })` 로 다른 모드의 패널도 닫을 수 있다(확인).**
- 탭 줄은 엔진이 그린다. 모드가 그릴 수 있는 곳은 패널 몸통과 프롬프트 위 띠다(문서). 패널 안의 탭은 몸통 첫 줄에 버튼으로 직접 그린다.
- 세션 작업 폴더는 `$.session.cwd()` 로 읽는다(시험으로 확인). 외부 명령은 `$.process.run(argv)` 로 실행하고, 종료 코드와 출력을 돌려받는다(확인).
- 엔진에 완성된 스크롤바 부품은 없다. `Box` 의 넘침 처리는 `visible`/`hidden` 뿐이다(문서).

### 휠

- 패널 위의 휠과 스크롤 키는 `ui.scroll` 이벤트로 온다(확인). 담긴 값은 움직인 줄 수(`by`)와 마우스가 있던
  칸(`pointer.column`, `pointer.row`)이다.
- 훅이 `next` 없이 답하면 엔진은 패널을 옮기지 않는다. 머리줄은 고정하고 자기 줄만 옮길 수 있다(확인).
- 화면 모듈(`Client`) 영역 위에서 굴린 휠도 같은 이벤트로 온다(확인: 가로 막대 위의 휠이 동작한다).
- **Shift 등 키 눌림 여부와 가로 방향 정보는 없다(문서).** Shift+휠은 구분할 수 없다.

### 화면 모듈(`Client`)

- 화면 모듈은 키와 마우스 좌표를 직접 받는다. `$` 는 없고, `surface.post(값)` 으로 훅에 보내면 훅은
  `ui.message` 로 받는다(확인).
- **한 프레임의 `post` 는 마지막 것만 전달된다(문서).** 변경분이 아니라 최신 전체 값을 보낸다.
- **영역 크기(`surface.rows`, `surface.columns`)는 첫 배치 전에 0 이다(확인).** 그 크기만큼만 그리면 첫 그리기에
  아무것도 그리지 않게 되고 빈 영역으로 굳는다. 첫 그리기에 쓸 크기를 훅이 값으로 넘긴다.
- **한 번도 `setState` 하지 않았으면 `surface.state` 는 계속 `undefined` 다(확인).** 매번 지금 값으로 새 상태를
  만들면 "이전 값과의 차이"를 볼 수 없다. 기준점은 고정값으로 두고, 값을 되돌리는 일은 훅에서 한다.
- 영역 안에서 마우스를 누르면 뗄 때까지 그 영역이 마우스를 잡는다(문서).
- 화면 모듈은 터미널과 데스크톱에만 있다. vscode 와 모바일에는 없다(문서).

### 글자와 칸

- **한글·한자·전각 문자는 한 글자가 두 칸이다(확인).** 줄을 글자 수로 자르면 영역 폭을 넘어 다음 행으로 접히고,
  접힌 행이 아래 줄을 덮는다. 화면 칸 수로 자른다(`cells.ts`).
- 엔진은 상대 경로를 세션 작업 폴더 기준 절대 경로로 바꿔 아래로 넘긴다(확인). 시험에서 경로를 비교할 때 주의한다.

### 시험

- 시험은 "무엇을 그리라고 했는가"까지만 본다. 터미널에 실제로 칠해진 색과 모양은 확인하지 못한다.
- 시험용 엔진에는 `$.state` 와 `$.ui.open` 이 없다. 패널은 띠 버튼을 눌러 열고, 상태 계산은 순수 함수로 따로 시험한다.
- `$.ui.scroll(...)` 로 휠 이벤트를 넣을 수 있다. 화면 모듈에는 `ui.key`, `ui.pointer` 로 입력한다.
- 같은 이벤트에 답을 두 번 등록하면 시험이 로드되지 않는다.
- 세션 안에서 `claude -p` 를 띄우는 것은 하네스 훅(summon-guard)이 막는다. 로드 확인은 `claude plugin list` 로 한다.

## 한계와 미확인

| 항목 | 상태 |
|------|------|
| 엔진의 `Code` 부품이 이 환경에서 색을 안 입히는 이유 | 미확인 — 쓰지 않기로 했다 |
| 빠르게 눌러도 글자가 선택되지 않는가(트리·가로 막대) | 실제 화면에서 확인받지 못했다. 근거는 엔진 문서의 문장뿐이다 |
| 머리줄의 엔진 버튼(`[ 편집 ]` 등)을 연타할 때의 선택 | 막지 않았다 |
| 한글 입력(조합 중인 글자) | 시험하지 못했다 |
| 탭 문자 | 한 칸으로 보인다 |
| 9만 자를 넘는 파일 | 편집할 수 없고 색도 없다 |
| 세로 스크롤 막대 | 위치만 보인다. 잡아 끌 수 없다 |
| Shift+휠 가로 스크롤 | 엔진이 Shift 값을 주지 않아 만들 수 없다 |
| 파일 이름 필터 | 만들지 않았다 |
| git 탭 | 읽기 전용이다. 변경 내용의 긴 줄은 잘리고 좌우로 넘길 수 없다. 9만 자를 넘는 변경 내용은 색이 없다 |
| 타입 검사(`tsc`) | 돌리지 못했다. 이 컴퓨터에 TypeScript 가 없다 |

## 고치거나 다시 만들 때

```bash
# 검사와 시험
claude plugin validate ~/.claude/skills/file-explorer
claude plugin test ~/.claude/skills/file-explorer

# Prism 묶음을 다시 만든다(언어를 늘리면 스크립트의 LANGUAGES 와 hooks/languages.ts 를 함께 고친다)
~/.claude/skills/file-explorer/tools/build-prism.sh <prismjs 패키지 폴더>
```

- 엔진 타입 파일은 `plugin-authoring` 스킬을 부르면 임시 폴더에 쓰인다. 약 2만 줄이라 이름으로 찾아 읽는다.
- 상태에 값을 더하면 `types/index.d.ts`, `$` 를 쓰는 세 파일의 `atom` 초기값, `reducers.ts` 의 `sane` 을 함께 고친다.
- 한 파일이 100줄에 닿으면 기능을 더하기 전에 나눈다.
