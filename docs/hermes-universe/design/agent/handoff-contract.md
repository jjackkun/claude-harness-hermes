# 인계 계약 — 에이전트끼리 일을 넘기는 형식, 소우주 사이 이동

> 작성일: 2026-09-15
> 목적: 에이전트가 다른 에이전트에게 일을 넘길 때 반드시 적는 칸과 되돌아오는 방식, 그리고 에이전트가 소우주 경계를 넘는 유일한 방법(복제)을 정한다.

## 개요

- 인계는 조직 세 축(직군 · 수직 · 수평)에서 방향이 정해진다: **지시 · 협업 · 요청 · 보고**.
- 넘길 때는 요청서(봉투)에 `goal`과 `done_when`을 반드시 적는다. 받는 쪽은 봉투 검사 후 시작한다.
- 다른 소우주에 있는 일은 **사람을 거쳐서만** 요청한다.
- 에이전트는 **소우주 하나에만 속한다.** 다른 소우주에서 필요하면 우주 템플릿을 거쳐 **복제**한다. 겸직·파견은 없다.

## 1. 인계의 네 방향 (확정)

| 방향 | 이름 | 예 | 받는 쪽이 거절할 수 있나 |
|---|---|---|---|
| 위 → 아래 (수직) | **지시** | 리드가 담당에게, 사람이 `main`에게 | 못 함. "막힘"으로 되돌릴 수는 있음 |
| 같은 수평 단위 안 | **협업** | users 도메인의 프론트가 같은 도메인 QA에게 | 가능 (사유 필수) |
| 다른 수평 단위로 | **요청** | users 담당이 공통 컴포넌트 담당에게 | 가능 (사유 필수) |
| 아래 → 위 | **보고 · 문의** | 담당이 리드에게, 에이전트가 사람에게 | — |

> ✅ 리뷰 확정 (2026-09-15, RV-07) — 근거: 리뷰 R-8. "지시는 거절 불가" 는 **규칙보다 위가 아니다.** 지시가 결정 원장 §1 의 멈추는 네 경우(파괴적 · 보안 · 작업 공간 밖 부작용 · 근거 없는 추측)나 R 룰(`--no-verify`, 비밀값 출력)에 걸리면 받는 쪽은 `claimed: blocked` 에 사유 `rule:<이름>` 을 붙여 되돌린다. 거절이 아니라 막힘이다 — 규칙이 막은 것이지 에이전트가 판단한 것이 아니다. 지시자가 사람이면 사람에게 올라가고, 에이전트면 그 위 사람에게 올라간다.

## 2. 요청서(봉투) 칸 (확정)

| 칸 | 내용 | 누가 씀 |
|---|---|---|
| `handoff_id`, `task_id`, `parent_task_id` | 식별자. 받는 쪽에 새 `task.assigned`가 생기고 `parent_task_id`로 이어진다 | 기계 |
| `from`, `to`, `kind` | 행위자(`agent:`/`human:`), 지시 · 협업 · 요청 중 하나 | 기계 |
| **`goal`** | 무엇을 원하는가, 한 문장 | 보내는 쪽 |
| **`done_when`** | 끝났다고 볼 조건. 검증 가능한 형태(테스트 이름, 파일 존재 등) | 보내는 쪽 |
| `inputs` | 필요한 자료의 **참조**(파일 경로, 이벤트 id). 원문을 붙여넣지 않는다 | 보내는 쪽 |
| `constraints` | 건드리면 안 되는 것, 기한 | 보내는 쪽 |
| `return_to` | 결과를 돌려줄 곳. 기본은 `from` | 기계 |

- `done_when`이 없으면 받는 쪽이 "성공"이라 주장해도 검증 기준이 없다. 작업 이력의 `verified` 층이 이 칸을 근거로 채워진다.
- `goal` · `done_when` · `constraints`는 자유 글이므로 원격에 올릴 때 암호화 대상이다([work-journal.md](work-journal.md) 7절).

## 3. 되돌아오는 방식 (확정)

| 결과 | 이벤트 | 뜻 |
|---|---|---|
| 완료 | `task.finished` (`claimed` + `verified`) | `done_when` 기준으로 기계가 검증 |
| 거절 | `handoff.declined` + 사유 | 협업 · 요청만 가능. 보낸 쪽은 사람에게 문의하거나 다른 담당을 찾음 |
| 막힘 | `task.finished` `claimed: blocked` | 지시받은 일이 막혔을 때. 위로 올라감 |
| 되묻기 | `handoff.question` | 봉투가 불충분할 때. 답이 올 때까지 시작하지 않음 |

받는 쪽은 시작 전에 **봉투 검사**를 한다. `goal`이나 `done_when`이 비어 있으면 기계가 막고, 내용의 부족함은 에이전트가 판단해 되묻는다.

같은 에이전트에게 동시에 여러 요청이 몰리면 지시 → 협업 → 요청 순으로 우선하고, 같은 종류 안에서는 먼저 온 것부터 처리한다(합의).

### 받는 쪽이 응답하지 않을 때

> ✅ 리뷰 확정 (2026-09-15, RV-08) — 근거: 리뷰 R-7, cumora K-3

받는 쪽이 아예 응답하지 않는 경우가 있다: 헤드리스 러너가 죽음, 그 컴퓨터에 열쇠가 없어 봉투를 못 풂, 담당이 있으나 소환할 세션이 없음. 지금 문서에는 기한을 적는 칸(`constraints`)만 있고 만료 뒤 무엇이 일어나는지 없다. 누락 감지([work-journal.md](work-journal.md) 8절)는 세션 종료 시점만 본다.

| 단계 | 처리 |
|---|---|
| 봉투 | `expires_at` 은 **선택** 칸. 보내는 쪽이 정한다. 근거 없는 기본 시간은 두지 않는다(G-17 과 같은 태도) — 없으면 만료 없음 |
| 만료 판정 | 시간 기반 데몬이 아니라 **세션 시작 훅**이 돌린다: 기한이 지났는데 `task.started` 도 `handoff.question` 도 없는 봉투를 찾아 `handoff.expired` 이벤트를 남기고 세션에 알린다. cron 없이 동작한다 |
| 대체 | 보낸 쪽은 (a) 다른 담당을 찾거나 (b) 공통 담당 · `main` 이 대신 수행하되 `actor` 는 대신 한 쪽, `caused_by` 에 만료 이벤트를 적는다 (c) 둘 다 없으면 사람에게 문의 |
| 기록 | 만료 횟수는 그 에이전트 성적의 참고 자료다(G-12). 원인이 열쇠 없음 · 러너 죽음이면 에이전트 탓이 아니므로 `evidence.reason` 에 기계 판정을 남긴다 |

cumora 가 배운 것: 응답 없는 구성원은 "고칠 대상" 이 아니라 **정상 조건**이다. "올리비아를 살리자" 로 가지 않고 "누가 없어도 팀이 끝낸다" 로 갔을 때 사슬이 닫혔다(`docs/COORDINATION.md` "Don't treat absent members as a failure mode"). 대체 수행을 예외가 아닌 기본 경로로 둔다.

**되묻기 남용.** `handoff.question` 은 봉투가 부족할 때만이다. cumora 는 공짜 우회 플래그가 선제 사용으로 게이트를 없애는 것을 겪었다(K-1). 되묻기도 같은 길을 갈 수 있다 — 어려운 일을 받으면 되묻고 미루는 식. 되묻기는 **봉투의 어느 칸이 부족한지** 를 지목해야 하고, 같은 봉투에 두 번째 되묻기는 사람에게 올라간다.

## 4. 다른 소우주에 있는 일 (확정)

격리 원칙상 직접 인계는 불가능하다. **경로는 사람 하나뿐이다.**

```text
A 소우주의 담당: "다른 저장소의 API 응답에 필드 하나가 더 필요하다"
  → A 안에서 handoff.external 이벤트를 남기고 사람에게 문의
  → 사람이 그 저장소(다른 소우주)에서 직접 요청을 시킴
  → 그쪽 결과(커밋 해시, 문서)를 사람이 A에 알려 줌
```

- 에이전트가 다른 소우주의 원격에 이슈를 여는 자동 경로는 두지 않는다. 요청 내용 자체가 이쪽 소우주의 정보다.

## 5. 에이전트는 소우주 하나에만 — 겸직 없음, 복제만 (확정)

### 결정

- 에이전트(id · SOUL · 기억 · 이력)는 **태어난 소우주 하나에만** 존재한다.
- 다른 소우주에서 같은 실력이 필요하면 **우주 템플릿을 거쳐 복제**한다. 파견(같은 에이전트가 오감)과 겸직(한 에이전트가 여러 소우주에 등록)은 두지 않는다.

### 복제 경로 — 기존 스킬 승격 경로를 그대로 쓴다

```text
A 소우주                                   우주(공장)                  B 소우주
에이전트 (id a…)
  │ 사람: "이 에이전트를 공유하자"
  ▼
SOUL + 개인 스킬을 일반화 → 봉투 ─▶ 이슈 → 국한성 심사 → 허가 ─▶ 우주 공통 직무 템플릿
  기억 · 이력 · 성적은 넣지 않음                                        │ 설치 · 전파
                                                                      ▼
                                                            사람이 입사시킴 → 새 id (b…)
                                                            수습 기간부터 시작
```

| 구성 요소 | 소우주 경계를 넘나 |
|---|---|
| SOUL.md (정체성 · 원칙 · 금지) | 예 — 소우주 사실을 벗기면 |
| 개인 스킬 | 예 — 일반화를 거치면 |
| 기억 | **아니오** — 그 소우주의 사실 |
| 작업 이력 · 수습 성적 | **아니오** — 그 소우주에서 검증된 것 |

- 복제된 에이전트는 **id가 다른 별개의 존재**다. 이름은 같아도 된다. B에서 수습 기간을 다시 거친다.
- "A에서 배운 실력이 B로 가는 유일한 길"이 개인 스킬 승격이므로, 승격이 자주 가볍게 일어나야 한다. 이것은 [skill-layers.md](../world/skill-layers.md)의 제안 → 허가 흐름이 담당한다.
- 우주를 거치지 않는 직접 복제(A → B)는 두지 않는다. 일반화 심사를 건너뛰면 A의 사실이 B로 샌다.

### 검토했다가 폐기한 안

| 안 | 폐기 이유 |
|---|---|
| 파견 (같은 id가 두 소우주를 오감) | B에서 배운 기억이 A로 돌아오는 것이 곧 인커전. 격리 원칙과 정면 충돌 |
| 출장 (기억 일부를 가져가되 귀환 금지) | "일반화된 기억만 골라내기"가 앞서 거부한 "민감정보만 골라내기"와 같은 구조 |
| 겸직 + 기억 `scope: personal / universe` | 저장은 `universe_id` PK로 안전하지만, 모든 조회를 `(agent_id, universe_id)` 쌍으로 강제해야 하고, 애매한 스코프 판정이 남는다. Cumora가 다중 테넌트 id 충돌 버그를 겪고 1 에이전트 = 1 워크스페이스로 되돌린 사례가 근거([existing-tools-research.md](../../evidence/existing-tools-research.md) 6절) |

## 6. 다중 컴퓨터는 그대로 — 열쇠 없음 안내 (확정)

겸직과 별개로, 같은 소우주를 여러 컴퓨터에서 쓰는 것은 유지한다. b 컴퓨터에서 A 저장소를 처음 받으면 열쇠가 없다. 이때 **세션 시작 시 기계가 판정해 알린다.**

```text
[헤르메스] 이 소우주(A)는 이식이 켜져 있지만, 이 컴퓨터에는 A 열쇠가 없습니다.
  → 원격의 기억 · 이력 · 원문 조각 <N>개를 풀 수 없어 회상이 백지에서 시작합니다.
  → 열쇠를 만들려면 AI 세션이 아닌 별도 터미널에서: <열쇠 만들기 명령>
  → 열쇠는 ~/.hermes/keys/<universe_id>/ 에 저장됩니다. 저장소 밖이며 git에 올라가지 않습니다.
  → 자물쇠 등록: 기존 열쇠가 있는 컴퓨터에서 <자물쇠 등록 명령>(마스터 열쇠를 새 자물쇠로 감싸 올림), 또는 비상 열쇠로 <복구 명령>
  → 열쇠 값이나 명령 출력을 이 세션에 붙여넣지 마십시오.
```

| 단계 | 하는 일 | 어디서 |
|---|---|---|
| ① | 열쇠 만들기 → `~/.hermes/keys/<universe_id>/<사람 id>-<자물쇠 지문>.key`, 자물쇠(공개키) 출력 | b 컴퓨터, AI 세션 밖 |
| ② | 자물쇠를 목록에 등록하고 **마스터 열쇠 파일을 새 자물쇠로 감싸 올림**(과거 조각 재암호화 없음, RV-03) | 기존 열쇠가 있는 컴퓨터(a), 또는 b에서 비상 열쇠로 |
| ③ | 세션을 다시 열면 마스터 열쇠를 풀고 조각을 풀어 재색인 | b 컴퓨터 |

> ✅ 2026-09-15 리뷰 후속 — 이 표는 처음에 "기존 조각을 다시 잠금" 이었다. RV-03(마스터 열쇠 감싸기, [encryption-keys.md](../protection/encryption-keys.md) 2절)에 맞춰 고쳤다. 컴퓨터 id 는 RV-02 에 따라 자물쇠 지문이다.

- 열쇠 없이도 세션은 쓸 수 있다. 그동안 새로 쌓인 기억은 **열쇠가 생길 때까지 로컬에만** 남고 push되지 않는다(평문으로 올리지 않는다).
- Cumora의 `--doctor`처럼 **열쇠 · 자물쇠 등록 · 조각 복호화 가능 여부를 한 번에 보여 주는 점검 명령**을 둔다(합의).

### 기억을 물었을 때 "없음"의 구분 (확정)

| 상황 | 기계가 아는 방법 | 대답 |
|---|---|---|
| 이 컴퓨터에 그 소우주 저장소가 없음 | 명부 · SOUL의 `universe_id`에 해당하는 로컬 소우주 없음 | "이 컴퓨터에 A가 없어 읽을 수 없습니다" |
| 저장소는 있는데 조각을 못 풂 | fetch된 조각 수 > 복호화된 수, 또는 `refs/hermes/sync` 없음 | "열쇠로 풀 수 없습니다" 또는 "이식이 꺼져 있어 원격에 기억이 없습니다" |
| 읽었는데 그런 기억이 없음 | 조회 0건 | "그 내용의 기억이 없습니다" |

앞의 둘은 소환 시점에 기계가 판정해 세션에 알린다. 에이전트가 짐작하게 두지 않는다. 전역 규칙 "불확실하면 추측하지 않는다"를 기억 조회에 적용한 것이다.
