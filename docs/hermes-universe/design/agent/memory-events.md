# 에이전트 기억 — PK를 가진 추가 전용 기억 이벤트

> 작성일: 2026-09-15
> 목적: 같은 에이전트가 한 컴퓨터에서, 또는 여러 컴퓨터에서 동시에 소환되어도 기억이 덮이거나 충돌하지 않게 저장한다.

## 개요

기억을 `MEMORY.md` 파일 하나에 직접 고쳐 쓰지 않는다. **기억 하나 = 고유 id(UUIDv7)를 이름으로 가진 이벤트
파일 하나**로 추가만 한다. `MEMORY.md`는 이벤트를 합쳐 계산한 **보기**다. 파일 충돌은 PK로 사라지고, 내용
충돌은 둘 다 보여 준 뒤 정리 이벤트로 해결한다(확정).

## 1. 왜 필요한가

| 상황 | 예 |
|---|---|
| 한 컴퓨터에서 동시 소환 | 대화형 세션과 백그라운드 루프가 같은 에이전트를 부름 |
| 여러 컴퓨터에서 동시 소환 | 컴퓨터 A와 B에서 같은 소우주 작업 |

| 기록 | 동시에 쓰면 |
|---|---|
| 작업 이력 | 문제없음 (이벤트 단위, 합집합) |
| SOUL.md | 사람 승인으로만 드물게 바뀌므로 문제 적음. 파일로 유지 |
| MEMORY.md 직접 수정 | 한쪽이 덮이고, 여러 컴퓨터 사이에서는 git 충돌 |

### 검토한 선택지

| 안 | 내용 | 판정 |
|---|---|---|
| A | 한 에이전트는 한 번에 한 작업만(잠금) | 잠금은 한 컴퓨터 안에서만 통해 여러 컴퓨터 동시 작업을 막지 못함 |
| **B** | **동시 허용 + 기억을 추가 전용 이벤트로** | **채택** |
| C | 동시 허용 + MEMORY.md 쓸 때만 잠금 | 여러 컴퓨터 충돌이 남음 |

## 2. git과 같은 원리 (확정)

사용자 제안: git이 커밋마다 고유 식별자를 붙여 충돌 없이 쌓듯, 기억에도 PK를 붙인다.

| git | 기억 이벤트 |
|---|---|
| 커밋마다 고유 해시 | 기억마다 고유 id |
| 커밋은 바뀌지 않음 | 이벤트는 바뀌지 않음 |
| 부모 커밋을 가리킴 | 갱신·철회가 원래 기억을 가리킴 (`revises`) |
| 같은 부모에서 각자 커밋하면 갈라짐 | 같은 기억을 각자 갱신하면 갈라짐 |

### id 방식

| 방식 | 판정 |
|---|---|
| 내용 해시(git 방식) | 같은 문장을 다른 시점에 다시 배운 것이 한 건으로 합쳐져 "언제 또 배웠나"가 사라짐 → **보조 칸으로만** |
| **UUIDv7** | 시간순 정렬, 작업 이력 id와 같은 형식 → **기본 id** |

## 3. 이벤트 형식

| 이벤트 | 뜻 |
|---|---|
| `memory.added` | 새로 알게 된 사실 |
| `memory.revised` | 기존 기억(`revises`)의 내용 갱신 또는 충돌 정리 |
| `memory.retracted` | 틀린 기억 철회. 지우지 않고 철회 표시 |

```json
{
  "memory_id": "<UUIDv7>",
  "kind": "memory.revised",
  "agent_id": "<에이전트 id>",
  "universe_id": "<소우주 id>",
  "ts": "<시각>",
  "about": "<주제 키>",
  "revises": "<원래 memory_id 또는 null>",
  "content_hash": "<본문 해시>",
  "source_event": "<근거가 된 작업 이력 event_id>",
  "body": "<암호문>"
}
```

### 저장 (확정)

| 층 | 자리 | 규칙 |
|---|---|---|
| 로컬 원본 | `state.db` 테이블 `memory_events` | PK `memory_id`(UUIDv7). **INSERT 전용** — `UPDATE` · `DELETE` 는 트리거로 차단(작업 이력 `journal_events` 와 같은 모양). `kind` 는 위 세 값만 |
| 원격 보존 | `refs/hermes/sync` 의 `memory/<agent_id>/<memory_id>.json` | 이벤트 1개 = 파일 1개. `body` 는 암호문(6절) |

- **파일 이름이 곧 PK**라 두 컴퓨터가 동시에 저장해도 파일이 겹치지 않는다.
- 구버전 DB(`memory_events` 없음)에서는 훅이 죽지 않고 한 줄 알린 뒤 exit 0 하고, 첫 실행 때 테이블을 만든다.
- `about`: 무엇에 대한 기억인지 표시하는 주제 칸. 서로 다른 기억끼리의 모순을 찾는 데 쓴다.
- `source_event`: 이 기억이 어느 작업에서 나왔는지 작업 이력과 잇는다.

## 4. 내용 충돌 (확정)

PK는 파일 충돌을 없애지만 **내용끼리 맞지 않는 충돌**은 막지 못한다.

| 충돌 | 예 | 기계가 찾을 수 있나 | 보기의 판정 (고정) |
|---|---|---|---|
| 갈라짐 | 컴퓨터 A와 B가 같은 기억(`revises`가 같음)을 각자 다르게 갱신 | **예** — 같은 대상을 가리키는 갱신이 둘 이상 | **충돌** — 둘 다 표시 |
| 같은 주제의 모순 | A는 "상한 100", B는 "상한 50"을 각각 새로 추가 | `about`이 같으면 비교 가능 | **충돌** — 둘 다 표시 |
| 완전 중복 | 같은 기억이 두 곳에서 동시에 생김 | `content_hash`가 같음 | **합침** — 한 줄로 보이되 두 이벤트는 남는다 |

- 판정 이름은 이 셋(`충돌` · `충돌` · `합침`)뿐이다. **최신 자동 승리는 없다** — 어떤 경우에도 늦게 온 쪽이 이기지 않는다.

### 처리 순서

| 단계 | 처리 |
|---|---|
| 보기 만들 때 | 충돌을 발견하면 **어느 쪽도 버리지 않고 둘 다 "충돌" 표시로 보여 준다** |
| 다음 소환 때 | 에이전트가 충돌을 읽고 사실을 확인해 `memory.revised`로 정리 이벤트를 남긴다 |
| 에이전트가 판단 불가 | 사람에게 문의한다 |

**최신 것을 자동으로 이기게 하지 않는다.** 늦게 저장된 틀린 기억이 맞는 기억을 조용히 덮을 수 있기 때문이다. git이 병합 충돌을 사람에게 보여 주는 것과 같다.

### 기억이 규칙을 덮지 못한다 — 자기 중독

> ✅ 리뷰 확정 (2026-09-15, RV-11) — 근거: cumora K-2, 리뷰 G-25 연결

cumora 에서 한 에이전트가 "정체된 사슬에는 침묵하라" 는 기억을 새로 써서, 방금 만든 안전망을 무시하도록 **미래의 자신을 훈련**했다. 한 번의 특이한 게임(명시적 상한이 있던 카운팅)이 "절대 두 번 하지 않는다" 는 보편 규칙으로 기억에 굳은 것이다(`docs/COORDINATION.md` T6, "Memory files are state too"). 우리 쪽 같은 사고가 `repository-isolation-principle.md`(회사 층 폐기 → "다층 체계 금지" 로 과잉 일반화, L-04)다.

| 규칙 | 내용 |
|---|---|
| 기억은 규칙 아래다 | SOUL.md · 우주 공통 규칙 · 소우주 R 룰과 **모순되는 기억**은 보기에서 "규칙 충돌" 표시를 달고, 소환 시 기억보다 규칙을 먼저 읽게 한다 |
| 기계 탐지 | 기억 본문이 규칙 문서의 문장을 부정하는지(같은 `about` 키에 규칙이 있는지)를 결정화 게이트와 같은 자리에서 검사한다. 완전 탐지는 불가능하므로 표시가 목적이다 |
| 근거 하나짜리 기억 | `source_event` 가 하나뿐인 기억은 "단일 사례" 표시. 두 번째 근거가 붙을 때까지 규칙으로 승격(개인 스킬)하지 않는다 |
| 철회는 흔적을 남긴다 | `memory.retracted` 는 왜 틀렸는지(`revises` 대상과 사유)를 담아, 같은 기억이 다시 배워지면 "전에 철회됨" 이 보이게 한다 |

cumora 의 처리("파일을 감사하지 않고 지우지 말라 — 머리말을 읽어라")와 같이, 잘못된 기억도 지우지 않고 철회 표시로 남긴다. 결정화가 폐기된 결정을 규칙으로 굳히는 문제(G-25)와 같은 장치로 푼다.

## 5. MEMORY.md는 보기

- 유효한 기억(철회되지 않고, 갱신으로 대체되지 않은 것)만 모아 계산한다.
- 충돌 중인 기억은 충돌 표시와 함께 모두 보인다.
- 언제든 이벤트에서 다시 만들 수 있다. 사람이 직접 고치지 않는다.
- **git 추적하지 않는다.** 파생물이라 원본(`memory_events` · 원격 `memory/` 조각)에서 어느 컴퓨터든 다시 만든다. `.gitignore` 는 `!.hermes/agents/*/` 예외를 푼 **뒤에** `.hermes/agents/*/MEMORY.md` 로 재무시한다([identity.md](identity.md) 6절).

## 6. 보호 (확정)

- 기억 본문(`body`)은 자유 글이다. 작업 이력 자유 글 칸과 같은 규칙으로 **원격에 올릴 때 암호화**한다([encryption-keys.md](../protection/encryption-keys.md)).
- id · 시각 · 종류 · `about` · `revises` 같은 기계 칸은 평문이다.
- `about`에 민감한 내용이 들어가지 않도록 주제 키 형식을 정해야 한다(미정).
