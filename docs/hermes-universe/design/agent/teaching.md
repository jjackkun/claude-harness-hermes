# 가르침 — 리뷰가 기억이 되는 경로, 사람의 가르침, 직급별 모델

> 작성일: 2026-09-18
> 목적: 에이전트가 "쓸수록 똑똑해지는" 실체를 정한다 — 상급자의 리뷰와 사람의 가르침이 **그 에이전트의 기억**에 남고,
> 반복되면 개인 스킬로 굳는 경로. 그리고 직급·봉투 무게에 따른 모델 배정.
> 출처: 2026-09-18 대화(사용자 의견 — 수습봇·멘토, cumora 의 에이전트끼리 일하기 비유, "리뷰가 곧 가르침", "사람은 모든 에이전트를 가르친다").

## 개요

- 이미 있는 것: 수습 시작(C-04) · 개인 스킬 층(S-01 `agent`) · 기억 이벤트(D-01, `memory.added/revised/retracted`) ·
  조직 관계로 봉투 kind 를 기계가 정함(H-01: 위→아래 = 지시, 거절 불가) · 최상위 직급 `human` 은 기계가 고정.
- 빠진 것: **리뷰 결과가 리뷰받은 에이전트의 기억에 남는 규칙**, **사람이 특정 에이전트에게 직접 가르치는 짧은 경로**,
  **직급→모델 배정**, **봉투 무게→모델 라우팅**, **회의(순차 회람)**, **아카이브 = 소우주까지**. 여섯 다 2026-09-18 사용자가 확정했다(§3·§4 는 모양만, 값·임계는 09-29 관측 뒤).
- 2026-09-18 실측: 명부 필드는 `agent_id·name·status·created_by` 뿐, 소환 러너(`hermes-summon.py`)는 `--model` 을 넘기지 않아
  세션 기본 모델로 돈다. 학습 재료는 사람의 대화(Stop 훅 요약 → `main`)뿐이라 상급자 리뷰가 하급자에게 흐르는 길이 없다.

## 1. 모든 에이전트는 상급자에게 배운다 — 리뷰가 곧 가르침 (확정, C-21)

- 하급자가 봉투를 `finished` 로 닫으면, 같은 unit 의 **바로 위 rank** 에이전트에게 `review` 봉투가 **자동으로** 열린다(kind 는 지시 —
  상급자는 거절할 수 없고 `blocked` 로만 되돌릴 수 있다, H-01). 위 rank 가 없으면 사람에게 열린다(§2).
- 리뷰 봉투의 `inputs` 는 참조만: 원 봉투 id · 결과 커밋 해시 · `done_when` 재측정 결과. 원문 붙여넣기는 거부된다(H-02).
- 상급자는 `approved` 또는 `corrected(about=<주제>, body=<지적 한 줄>)` 로 닫는다. **닫는 순간 기계가 리뷰받은 에이전트의
  `memory_events` 에 기록한다** — `approved` 는 `memory.added(about, "…가 맞았다")`, `corrected` 는 `memory.added(about, 지적)`.
  이력(journal)에만 남는 리뷰는 가르침이 아니다 — 기억에 있어야 다음 소환에 주입된다.
- 같은 `about` 의 `corrected` 가 3회면(결정화 임계와 동일) 그 에이전트의 **개인 스킬**(`.hermes/agents/<id>/skills/`)로 결정화한다.
  기존 결정화 루프를 재사용하고, 철회 보류(`hermes_reversed_guard`)·도움률 강등(`hermes_skill_yield`)도 그대로 적용된다.
- 배움의 증거는 행동 변화다: 같은 `about` 지적이 다음 봉투에서 다시 나오지 않는 것. 같은 `about` 의 `corrected` 누적 수를
  대시보드 에이전트 판에 보인다(계획 `hermes-dashboard`).
- 이유: 상급자가 하급자의 리뷰어라는 관계는 조직 축으로 이미 성립한다(H-01). 리뷰를 기억으로 옮기는 규칙 하나가 "쓸수록 똑똑해진다"
  의 실체다. 틀렸을 때 손해: 리뷰 봉투가 소환 1회를 더 써 토큰이 늘고, 지적이 잘못되면 잘못이 기억에 남는다(철회로 되돌린다).

## 2. 사람은 모든 에이전트를 가르칠 수 있다 (확정, C-22)

- 사람은 조직의 최상위(`human`, 기계 고정)라 모든 에이전트에게 지시·리뷰할 수 있다. §1 의 리뷰 봉투가 사람에게 열리면 같은 방식으로 닫는다.
- 봉투 없이도 가르친다: `python3 scripts/hermes-agent.py teach "<이름>" --about <주제> "<한 줄>"` — 내부는 `memory.added`
  (`by=human:<이름>`, `source_event=teach`). 되돌리기는 `unteach` 가 아니라 기존 철회(`memory.retracted`)로 — 철회 뒤 같은 주제를 다시
  가르치면 `previously_retracted` 가 붙는다(기존 규칙).
- 스킬(`hermes-agent`)은 "게이트QA 한테 이거 가르쳐" 를 `teach` 로 옮긴다. 폼 방식(계획 `agent-hire-form`)과 같은 결로 대상·주제를 폼으로 받을 수 있다.
- 가르침도 `about` 이 필수다 — 주제 없는 문장은 결정화 키가 될 수 없고, 앞서 본 페이지명·일반 단어 키 사고(계획 `skill-yield-junk`)를 되풀이한다.
- 이유: 사람의 대화가 `main` 에게만 흐르는 지금 구조로는 담당 에이전트가 사람에게 직접 배울 길이 없다. 틀렸을 때 손해: 사람이 잘못 가르치면
  그대로 기억된다 — 철회 경로가 그 보험이다.

## 3. 직급이 모델을 정한다 (확정, C-23)

- 모델은 **직급(rank)** 에 붙인다: `organization.yaml` 의 `rank` 항목마다 `model`. 에이전트마다 따로 두지 않는다 —
  손잡이가 직급 수만큼이고, **승급(`promote`)하면 모델도 올라간다**(수습 → 정식이 곧 더 좋은 모델). 성장 서사와 맞물린다.
- 리뷰 봉투(§1)의 리뷰어는 자기 rank 모델을 쓰되 **최소 Opus 5** — 가르치는 쪽이 배우는 쪽보다 약하면 안 된다.
- 소환 러너가 명부→조직에서 rank 를 찾아 `claude -p --model <값>` 으로 넘긴다. 코드 변경은 러너 한 곳. 값이 없으면 지금처럼 기본 모델.
- **어느 직급에 어느 모델인지(값)는 이 문서가 정하지 않는다.** 잴 데이터가 없다(backlog `agent-model-routing-blindspot`, 2026-09-29 판단).
  값은 사람이 `organization.yaml` 에 선언하고 바꾼다. 관측이 생기면 그 표로 검증한다.
- 이유: 모델은 세션 시작 때 `--model` 로 고정되므로 "누가 어떤 모델로 뜨나" 는 소환 시점의 선언이어야 한다. 틀렸을 때 손해:
  같은 직급 안에서 차등이 필요하면 직급을 하나 더 나눠야 한다.

## 4. 과제 무게로 모델을 바꾸는 것은 러너가 한다, 에이전트는 상향만 요청한다 (확정, C-24)

- 사실: 모델은 세션이 시작될 때 고정된다. 세션 안의 에이전트가 스스로 모델을 갈아탈 방법은 없다 — 바꾸려면 **새 소환**이고, 새 소환은 봉투를 거친다.
- 그래서 **1차 결정은 소환 러너가 봉투로 한다**: `done_when` 종류·`inputs` 수·기한으로 무게를 어휘·숫자 규칙으로 산정해 §3 의 직급 모델에서
  한 단계 위/아래로 조정한다(예: `test:` 있고 inputs ≤ 3 → 한 단계 아래, `manual`·설계·리뷰 → 한 단계 위). 규칙은 모델 호출 없이(R3),
  결과는 `task.assigned` 에 `model=` 로 남겨 사후 대조한다.
- **에이전트는 상향 요청만 할 수 있다**: 과제가 무겁다고 판단하면 `question` 으로 되묻거나 상위 모델 재소환을 요청하고, 상급자(또는 사람)가
  승인하면 새 봉투로 재소환된다(C-21 의 리뷰 사슬과 같은 모양). **하향은 요청할 수 없다** — 스스로 싸게 가는 것은 품질 위험이고 검증할 수 없다.
- **임계(숫자)는 이 문서가 정하지 않는다** — §3 과 같이 2026-09-29 관측 뒤. 모양(러너 결정 + 상향 요청)만 확정한다.
- 이유: 판별을 에이전트에 맡기지 않는다는 C-19 와 같다 — 요청은 이력에 남아 되돌릴 수 있지만 "무겁다" 는 판단 자체는 검증할 근거가 없다.
  틀렸을 때 손해: 상향 요청이 잦으면 승인 봉투가 늘어 사람 손이 간다(요청 빈도를 대시보드에 보인다).

## 5. 회의는 순차 회람 — 자리 하나 = 세션 하나 (확정, C-25)

- 회의는 **동시(N:N)가 아니라 차례(순차 회람)** 다. `meeting` 봉투 = 안건(`goal`) + 참석자 목록 + 사회자(상급자 또는 사람).
  참석자마다 **따로 소환**돼(각자 세션 1개) 자기 지식 — 개인 스킬·기억 + 층 스킬 — 으로 의견을 덧붙인다. 한 세션에 여러 에이전트를 두지 않는다.
- **회람 순서: 낮은 직급 먼저 → 높은 직급 → 사회자.** 뒤 참석자는 앞 의견을 읽은 채 말하므로 순서가 곧 영향력이다. 실무자가 상급자 의견
  없이 사실을 먼저 내고, 상급자가 그것을 다 읽고 판단한다(정보가 위로 모인다). 같은 직급끼리는 안건 `about` 과 분야가 겹치는 쪽부터.
- **1인 1발언.** 재발언 없음 — 반박이 필요하면 사회자가 그 참석자에게 새 봉투(`question`)로 되묻는다. 그래서 소환 횟수 = 참석자 수로 비용이 정해진다.
- **사회자는 말하지 않고 닫기만 한다.** 사회자 의견이 필요하면 참석자로도 등록한다. 결론 봉투로 닫으면 결론은 이력에, **각 참석자의 기억에는
  자기 의견과 결론이** 남는다(§1 과 같은 규칙 — 회의도 가르침). 결론이 규칙이 될 만하면 승격 제안으로 아카이브(§6)에 올린다.
- **참석자가 없는 분야는 사람이 만든다.** 후보는 `match` 로 기존 담당을 찾고, 없으면 기존 `no-owner` 흐름대로 사람에게
  "이 분야 참석자를 아카이브 템플릿 X 로 입사시킬까요" 를 묻는다(C-03 — 자동 생성 안은 폐기됐다). 승인이 한 번이면 체감은 자동에 가깝지만 명부는 사람이 쥔다.
- 이유: 회의의 값은 여러 지식을 모으는 것인데 동시 세션은 행위자(A-03)·이력이 흐려지고 비용이 턴 수로 는다. 순차 회람은 같은 값을 이력이 남는 형태로
  준다. 틀렸을 때 손해: 실시간 토론은 못 한다 — 그건 사람이 사회를 본다.

## 6. 아카이브는 소우주까지 — 스킬과 기억 모두 (확정, C-26)

- 에이전트는 소우주 하나에만 속하므로(H-09) **아카이브의 꼭대기는 소우주 공통 층**이다: 개인(`agent`) → 조직(`unit`) → 소우주 공통.
  **우주(공장)는 아카이브가 아니다** — 거기로 올리는 것은 "다른 소우주와 공유하겠다는 제안"(제안서, S-06·R-leak)이라는 별개 행위다.
- 소우주 안은 같은 조직의 정보라 사내 정보 제거(R-leak)가 필요 없다. 남는 규칙은 **개인 사정 벗기기(S-02)** 뿐 — "결제담당이 지난주에" → "이 도메인에서는".
  안 벗기면 개인의 버릇이 소우주 규칙이 된다(zeroday 에서 페이지 이름이 규칙이 된 사고와 같은 꼴). 허가자는 소우주 안의 상급자 또는 사람(S-06).
- **기억도 아카이브에 올린다.** 소우주 기억 저장소는 이미 있다 — 세션 요약(`session_summary`)·`.hermes/vault/`(세션 노트). 빠진 것은
  "개인 기억 중 소우주가 알아야 할 것" 을 올리는 행위 하나: 개인 `memory.added` 를 소우주 층에 복사(사람 또는 상급자 허가, `about` 필수).
  우주로는 기억을 올리지 않는다(누출 경계).
- **회의 참석자 생성은 아카이브에서**: 소우주 공통 층의 해당 분야 스킬 + 소우주 기억을 템플릿으로 입사(사람 승인). 우주 템플릿(H-09)은 다른 소우주에서 쓸 때만.
- 이유: 아카이브를 별도 저장소로 두면 같은 지식이 두 곳에 생기고 승격 규칙(S-02~S-06)을 다시 쓰게 된다. 소우주 경계를 아카이브 경계로 두면
  누출 걱정 없이 기억까지 올릴 수 있다. 틀렸을 때 손해: 소우주 공통 층이 커지면 주입 상한(검색 상위 N)에서 밀리는 지식이 생긴다 — 도움률 강등이 정리한다.
