# 복사 설치 — symlink 설치 폐지

> 작성일: 2026-09-15
> 목적: 공통 스킬·규칙·에이전트를 소우주에 symlink로 연결하던 방식을 복사 설치로 바꾸는 이유와 변경 범위를 정한다.

## 개요

지금 Linux/macOS에서는 공장 `assets/`의 스킬·규칙·에이전트가 소우주에 **절대경로 symlink**로 연결된다.
그래서 소우주에서 고치면 공장 원본이 바뀌고, 공장의 작업 중 상태가 곧바로 모든 소우주에 퍼진다.
**symlink를 없애고 복사 설치 + 설치 목록 + 버전 기록으로 바꾼다(확정).**

## 1. 현재 설치 방식 (2026-09-15 실측)

| 대상 | 방식 | 근거 |
|---|---|---|
| 스킬 | Windows 경로면 `cp -r`, 아니면 `ln -s` | `lib/installers.sh:61-65` |
| 에이전트 | 같음 | `lib/installers.sh:86-90` |
| 규칙 | 같음 | `lib/installers.sh:112-116` |
| 훅·스크립트 | 항상 복사 | zeroday-frontend `scripts/hooks` 실파일 39, `scripts` 실파일 151 |

zeroday-frontend `.claude/`:

| 폴더 | symlink | 실제 항목 |
|---|---|---|
| `.claude/skills` | 22 | 28개 폴더 (소우주 자체 스킬이 한 폴더에 섞임, 전체 50) |
| `.claude/rules` | 6 | 0 |
| `.claude/agents` | 14 | 0 |

- 링크 대상 예: `backend-patterns -> /home/jjackkun/PROJECT/claude-harness-hermes/assets/skills/backend-patterns`
- **절대경로 symlink 41개가 zeroday-frontend git에 커밋되어 있다**(`git ls-files -s` 모드 120000). 무시 규칙은 없다.
- terminal-shipping도 `backend-patterns`, `database-migrations`, `fastapi-patterns`, `fastapi-testing` 등이 같은 방식으로 링크되어 있다.

## 2. symlink가 일으키는 문제

| 문제 | 무슨 일이 생기나 |
|---|---|
| **뒷문** | 소우주에서 공통 스킬을 고치면 제안·허가 없이 공장 원본이 바뀌고 모든 소우주에 즉시 퍼진다 |
| **공장의 작업 중 상태 = 운영 상태** | 공장의 커밋하지 않은 편집과 브랜치 전환이 그 즉시 모든 소우주에 반영된다. 예: 2026-09-15 세션 시작 시점에 커밋하지 않은 `assets/skills/hermes-loop/SKILL.md` 수정이 이미 링크로 전 소우주에 반영된 상태였다 |
| **버전 불명** | 소우주가 지금 어느 버전을 보는지 기록이 없다. 제안 봉투의 `base`를 채울 수 없다 |
| **다른 컴퓨터에서 깨짐** | 커밋된 절대경로 링크는 다른 컴퓨터나 팀원의 clone에서 없는 경로를 가리킨다 |

symlink의 장점("공장 수정이 재설치 없이 즉시 반영")이 곧 두 번째 문제다. 허가된 수정만이 아니라 모든 수정이 즉시 반영된다.

## 3. 검토한 선택지

| 안 | 내용 | 판정 |
|---|---|---|
| **A. 복사 + 버전 기록 + 변조 감지** | 설치 시 복사, 공장 커밋 기록, 복사본 해시 목록으로 소우주 편집 감지 | **채택** — 원격 배달, 기준 버전, 소우주 격리와 맞고 Windows 경로와 방식이 하나로 통일된다 |
| B. symlink 유지 + 편집 차단 훅 | 뒷문만 막음 | 나머지 세 문제가 남는다 |
| C. 공장이 버전별 읽기 전용 스냅샷을 만들고 링크 | 버전 문제 해결 | 공유 폴더라는 로컬 부작용과 다른 컴퓨터 깨짐이 남는다 |

| 8 | 테스트 | 복사 설치, 설치 목록 기반 정리(자체 스킬이 지워지지 않는지), 변조 감지 |

## 5. 복사 설치에서 따라오는 것

- **공통과 자체 스킬 구분:** 링크 여부라는 표시가 사라지므로 설치 목록으로 구분한다. 폴더를 나누는 방법은 스킬 로딩 위치 제약 확인이 필요하다([open-questions.md](../../open-questions.md) V-5).
- **공장 수정의 전파 시점:** 즉시가 아니라 `update-all`로 받을 때다. "소우주가 항상 최신을 받을지, 확인 후 받을지" 질문은 복사 설치로 사실상 "받을 때 받는다"로 정해진다.
- **공장이 로컬에 없는 컴퓨터:** 원래 symlink가 불가능해 복사본이었다. 이제 모든 컴퓨터가 같은 방식이 된다.

## 6. 예외 (Q-4, 확정)

원칙: **어느 설치물도 저장소 밖 경로를 가리키지 않는다.** 소우주는 복사본, 공장은 저장소 안 상대경로 링크.

### 공장 자기 설치 — 상대경로 링크

- 실측(2026-09-15): 공장 `.claude/`에 링크 스킬 12 · 규칙 2 · 에이전트 11, 모두 자기 `assets/`를 **절대경로**로 가리킴. git에 커밋된 링크 **25개**. 다른 컴퓨터·다른 경로에서 clone하면 공장 자체도 깨진다.
- 결정: 공장은 복사하지 않고(두 벌 관리 회피) **저장소 안을 가리키는 상대경로 링크**(`.claude/skills/x -> ../../assets/skills/x`)로 바꾼다. 소우주는 대상이 저장소 밖(공장)이라 상대경로가 불가능했지만, 공장은 대상이 저장소 안이라 가능하다.
- 상대경로는 저장소를 통째로 옮기거나(clone, 폴더 이동·이름 변경, 다른 사용자) 어디서 받아도 깨지지 않는다. 깨지는 경우는 **저장소 내부 구조**(`assets/` 이름, `.claude/` 깊이)가 바뀔 때뿐이고, 그것은 설치기 코드 변경이라 재설치 한 번으로 해결한다.
- 심링크에 변수(`$HOME` 등)는 넣을 수 없다. "바뀌면 따라가게"는 링크가 아니라 **멱등한 재설치**(`update-all.sh`)가 담당한다.
- **세션 시작 훅이 깨진 링크를 감지**해 "재설치 필요"를 알린다. 열쇠 없음 안내([handoff-contract.md](../agent/handoff-contract.md) 6절)와 같은 자리.

### 메모리 폴더 링크 — 범위 밖

- `lib/harness_installers.sh:667` `install_memory_symlink`: 방향이 반대다. `~/.claude/projects/<키>/memory` (Claude Code 기록 위치) → `<프로젝트>/.claude/memory` (git 추적 원본). 링크는 저장소 **밖** `~/.claude/`에 생기고 저장소에는 실제 파일만 있다.
- 공장 자산과 무관하고 뒷문·버전·clone 문제가 없다. 재설치하면 그 컴퓨터 경로로 다시 만들어진다. **이번 전환 범위에서 제외.**
- 이 Claude Code 메모리와 새 설계의 에이전트 기억([memory-events.md](../agent/memory-events.md))의 관계는 미정(G-26).
