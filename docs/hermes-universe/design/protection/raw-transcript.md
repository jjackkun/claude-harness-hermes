# 대화 원문 보호 — 경계 원칙과 두 벌 구조

> 작성일: 2026-09-15
> 목적: 대화 원문에 섞이는 민감정보가 반복해서 git에 올라가는 문제를 구조적으로 막는다.

## 개요

원문은 **그 소우주 저장소와 그 원격 주소 밖으로 나가지 않는다.** 원격으로 옮길 때는 한 턴을 **통째로
암호화한 금고본**만 올린다. 동료와 나누고 싶은 내용은 **사람이 골라 승인한 검은 박스 공개본**으로만
만든다. 민감한 부분만 골라 암호화하는 방식은 채택하지 않는다.

## 1. 원문이 지금 흘러가는 길 (2026-09-15 실측)

```text
[이 컴퓨터]
 대화 한 턴 끝
   │ Stop 훅 (매 턴)
   ▼
 ① state.db session_history        ← 마스킹 후 저장
   │ hermes-export-history.py      (assets/hooks/claude-stop-retrospective.sh:121)
   ▼
 ② .hermes/history/<세션>.jsonl    ← DB 내용을 파일로 통째 다시 씀
   │ .gitignore 가 이 폴더만 예외로 풂 (!.hermes/history/**)
   ▼
 ③ 사람이 코드를 커밋할 때 함께 실림 (자동 커밋은 없음. `git add .` 하면 같이 들어감)
   │ push
   ▼
[소우주 원격 — 코드 브랜치]
   │ 다른 컴퓨터에서 pull
   ▼
 ④ 세션 시작 훅(assets/hooks/claude-sessionstart-history-reindex.sh)이
    hermes-reindex.py 로 jsonl 을 그 컴퓨터 state.db 에 다시 채움
```

- 두 소우주 모두 `.gitignore`가 `.hermes/`를 막고 **`skills/`와 `history/`만 풀어 둔 상태**다.
- 커밋된 원문 파일: zeroday-frontend **235개**, terminal-shipping **31개**.

### 원문을 쓰는 기능은 git 파일을 읽지 않는다

회상(`hermes-recall`), 결정화 근거(`hermes-crystallize`), 패턴·신호 감지, 압축(`hermes-lifecycle`·`hermes-cleanup`),
재사용 판정은 모두 **① `state.db`를 읽는다.** ② jsonl을 읽는 것은 ④ 재색인뿐이다.
**git에 올린 원문 파일의 용도는 "다른 컴퓨터로 옮기기" 하나다.**

### 원문이 있는 곳 전체

| 위치 | 원격으로 나가나 | 비고 |
|---|---|---|
| `<소우주>/.hermes/state.db` | 아니오 (git 제외) | 평문 |
| `~/.claude/projects/<프로젝트>/*.jsonl` (Claude Code 자체 기록) | 아니오 | zeroday-frontend 3297개, terminal-shipping 1323개 |
| `<소우주>/.hermes/vault/*.md` (세션 요약 노트) | 아니오 (git 제외) | 이름과 달리 평문, `hermes-summarize.py:210` |
| `~/.hermes/global.db` `session_history` | 아니오 | 0행 |
| `<소우주>/.hermes/history/*.jsonl` | **예, 코드 브랜치로** | 이번 설계로 중단 |
| 요약·결정화 시 모델 호출 | 모델로 전송 | 암호화로 막을 수 없다. 마스킹만 가능 |

## 2. 반복된 사고

`docs/superpowers/specs/2026-08-10-hermes-secret-masking-design.md`:

- 2026-08-10 terminal-shipping `.hermes/history/*.jsonl`에서 **외부 시스템 계정 5종의 평문 자격증명**이 발견됐다. 값은 origin/main까지 올라가 있었다.
- **네 겹이 순서대로 뚫렸다.**
  1. `redact()`가 딱지(`label=value`)가 있어야만 가렸다.
  2. `SOME_PASSWORD=`처럼 접두어가 붙으면 경계 매치에 실패했다.
  3. export 단계에 마스킹이 아예 없었다.
  4. 커밋 스캐너가 연결되지 않았고, 한 줄에 `example`이 섞이면 줄 전체가 면제됐다.
- 네 겹 모두 보강했다. `.env` 실제 값 대조(`hermes_secret_values.py`), 형태 보강, export 재마스킹, 커밋 스캐너가 들어갔다.
- 그러나 같은 문서의 비목표가 **"`.hermes/history/` 커밋 관례 폐지"와 "대화 내용 저장 여부 재검토"**였다. 구멍은 막았지만 원문을 git에 싣는 구조는 남았다.
- 비밀 관련 수정 이력은 `hermes-scrub-history.py`(소급 제거 도구) 등 여러 커밋에 걸쳐 있다.

## 3. 원문 경계 원칙 (확정, T-02)
> **원문은 그 소우주의 저장소와 그 저장소에 연결된 원격 주소 밖으로 나가지 않는다.**

| 문제였던 것 | 원칙 판정 |
|---|---|
| 코드 브랜치에 평문으로 섞음 | 경계 안이지만 동료가 평문을 본다 → 중단 |
| 다른 주소로 반출(별도 비공개 저장소 등) | **경계 밖, 위반** → 폐기 |
| 그 소우주 원격에 **암호화해서, 코드와 분리해** 올림 | 경계 안, 동료는 암호문만 봄 → 채택 |

- git 자체를 쓰지 않겠다는 뜻이 아니다. 여러 컴퓨터를 오가는 소우주(zeroday-frontend, terminal-shipping)는 소우주 원격이 컴퓨터 사이를 잇는 유일한 길이다.
- zeroday-frontend는 사내 서버에만 두므로 회사 자료 반출 문제가 생기지 않는다.

## 4. 민감한 부분만 골라 암호화하지 않는 이유

### 방향이 반대다

사용자는 "정부 기밀 문서도 공개하되 민감한 곳은 검은 박스로 가린다"는 비유를 들었다. 정부 방식과 선택 암호화는 방향이 반대다.

| | 정부 기밀 해제 | 선택 암호화 |
|---|---|---|
| 기본 상태 | 전체 **기밀** | 전체 **공개(평문)** |
| 고르는 것 | **공개해도 되는** 부분 | **숨길** 부분 |
| 누가 고르나 | 훈련받은 **사람**, 여러 단계 승인 | **기계** 자동 탐지 |
| 빈도 | 문서마다 한 번, 의도적으로 | 매 턴 자동, 수천 번 |
| 놓치면 | 공개하지 않은 상태로 멈춤 | 모른 채 git에 영구히 남음 |
| 원본 | 금고에 보관 | 가린 것만 남음 |

사람이 검토하는 정부도 놓친다. 검은 박스 아래 글자가 PDF에서 복사되던 사고가 있었다(2019년 매너포트 재판 서류, 2009년 미국 교통보안청 검색 매뉴얼).

### 민감정보는 형태가 없는 경우가 많다

| 종류 | 기계가 찾을 수 있나 |
|---|---|
| `.env`에 있는 값 | 예 (값 대조) |
| 형태가 뚜렷한 토큰·전화번호 | 대체로 예 |
| `.env`에 없는 남의 계정(딱지 없는 `아이디 \| 비번`) | 자주 놓침. 조사한 공개 도구 중 확실히 잡는다고 밝힌 것이 없다 |
| 사내 주소·내부 시스템 이름 | 규칙을 만들면 일부 |
| 고객·동료 정보, 업무 맥락, 사적인 말 | 형태가 없어 거의 못 찾음 |

### 실패 방식이 다르다

| | 통째 암호화 | 선택 암호화 |
|---|---|---|
| 무엇이 뚫려야 새나 | 열쇠 하나 | 탐지기가 한 번이라도 놓치면 |
| 새면 알 수 있나 | 열쇠 유출은 인지 가능한 사건 | 놓친 줄은 아무도 모르게 올라감 |
| 되돌릴 수 있나 | 열쇠 교체로 앞으로는 막음 | 평문이 git에 영구히 남음 |

## 5. 두 벌 구조 (확정, T-05)
```text
원문 한 턴
  │
  ├──▶ ① 금고본: 턴 통째 암호화 → 소우주 원격 refs/hermes/sync   (항상, 자동)
  │        본인 열쇠(와 비상 열쇠)로만 열림
  │
  └──▶ ② 공개본: 검은 박스를 친 평문                             (선택, 사람이 결정할 때만)
           기계가 가릴 곳을 제안 → 사람이 확인·승인 → 그때만 올림
```

- ①은 탐지에 의존하지 않는다.
- ②는 매 턴 자동이 아니라 공유하고 싶은 대화를 사람이 골랐을 때만 만든다. 기계 탐지는 **제안**용이고, 최종 결정은 사람이다. 공개본에서 무언가 놓쳐도 금고본은 안전하다.
- 공개본을 만드는 사용자 흐름은 미정이다(G-7).

| 소우주 | ① 금고본 | ② 공개본 |
|---|---|---|
| terminal-shipping (혼자 씀) | 이식을 켜면 사용 | 볼 사람이 본인뿐이라 필요 없음 |
| zeroday-frontend (4명) | 이식을 켜면 사용 | 동료와 나누고 싶은 대화가 있을 때만 |

## 6. 무엇이 암호화되고 무엇이 안 되나

| 내용 | 있는 곳 | 암호화 | 누가 볼 수 있나 |
|---|---|---|---|
| 대화 원문(한 턴 전체) | 소우주 원격 `refs/hermes/sync` | **예, 통째로** | 열쇠를 가진 본인 |
| 대화 원문 | 로컬 `state.db`, Claude Code 기록 | 아니오 | 이 컴퓨터 사용자 |
| 작업 이력 기계 칸 | 원격 `refs/hermes/sync` | 아니오 | 저장소 접근자 |
| 작업 이력 자유 글 칸 3개 | 원격 `refs/hermes/sync` | **예** | 본인 |
| 스킬 | 원격 코드 브랜치 | 아니오 — 모델이 평문으로 읽어야 한다 | 저장소 접근자. **결정화 게이트로 막아야 한다** |

- 암호화는 **올라가는 사본에만** 적용된다. 다른 컴퓨터에서 받으면 본인 열쇠로 풀어 그 컴퓨터 `state.db`에 평문으로 다시 채운다.
- 암호문이라도 조각 개수·크기·올린 시각은 드러난다. 동료가 보려면 `refs/hermes/sync`를 일부러 fetch해야 한다.

## 7. 마스킹의 역할은 계속된다

| 보호 수단 | 지키는 것 |
|---|---|
| 암호화 | 밖으로 나간 사본 |
| 마스킹 | 모델(요약·결정화)과 스킬로 흘러가는 내용 |

암호화로는 모델 전송과 평문 스킬을 막을 수 없으므로 로컬 저장 전 마스킹(`.env` 값 대조 + 형태 기반)은 유지한다.

## 8. 이미 올라간 평문 (확정, T-03)
- 이미 커밋·push된 평문 원문(zeroday-frontend 235개, terminal-shipping 31개)은 **손대지 않는다.** 이력 재작성은 되돌릴 수 없고 모든 이력을 뒤흔든다.
- 추적 해제(`git rm --cached`)도 **하지 않는다.** 이력 재작성은 아니지만 동료 clone 의 작업 트리에서 파일을 지우는 부작용이 있다. 저장소별 사용자 판단으로 남긴다.
- 검증 기준: 무시 규칙을 바꾼 뒤에도 `git ls-files .hermes/history | wc -l` 이 zeroday-frontend **235** · terminal-shipping **31** 로 불변이다. 추적 중인 파일은 `.gitignore` 와 무관하므로 "새 파일이 무시되는가" 와 "기존 파일이 그대로인가" 를 따로 검증한다.
- zeroday-frontend의 235개는 동료 3명도 접근할 수 있는 상태다.
- 그 안에 지금도 유효한 자격증명이 있다면, 해당 비밀번호·토큰 **교체**로 노출값을 무력화할 수 있다. 이것은 저장소별 사용자 판단이다.

## 9. 코드 브랜치 원문 커밋 중단에 필요한 변경

| 변경 | 내용 |
|---|---|
| `.gitignore` | 설치기 마커에서 예외 **두 줄**(`!.hermes/history/` 와 `!.hermes/history/**`, `presets/workflow/hermes.conf:177-178`)을 지운다. `.hermes/*` 무시 아래서는 디렉터리와 내용물을 따로 풀었기 때문에 한 줄만 지우면 남는다. 재설치 후 `git check-ignore .hermes/history/new.jsonl` 이 무시로 판정돼야 한다(새 파일만). 각 소우주의 `.gitignore` 변경 커밋은 사용자가 한다 |
| export | 매 턴 세션 파일 전량 재작성 → 턴 단위 조각 `history/<session_id>/<순번>.enc` 추가 + 암호화 ([sync-transport.md](sync-transport.md)). 암호 조각은 `hermes-sync.py tombstone` 경로로만 지운다. `hermes-scrub-history.py`(평문 소급 제거 도구)는 레거시 jsonl 전용으로 남기고 조각에 맞게 고치지 않는다 |
| 재색인 | git 파일이 아닌 `refs/hermes/sync`의 새 조각을 복호화해 채움. 옛 jsonl 경로는 "레거시 읽기 전용" 분기만 남긴다 |
