# 암호화와 열쇠 — age, 컴퓨터별 열쇠, 비상 열쇠

> 작성일: 2026-09-15
> 목적: 금고본과 작업 이력 자유 글 칸을 무엇으로 잠그고, 열쇠를 어떻게 만들고 보관하며, 잃었을 때 어떻게 되는지 정한다.

## 개요

잠그고 푸는 계산은 **검증된 파일 암호화 도구 age**에 맡기고, 헤르메스 코드는 **언제·누구의 자물쇠로·어디에**
잠글지만 정한다. 열쇠는 컴퓨터마다 따로 두고, 소우주마다 컴퓨터 밖에 보관하는 비상 열쇠를 하나 더 둔다.
열쇠는 AI 세션 밖에서만 다룬다.

## 1. age 기반의 뜻 (확정)

### age란

- 파일 하나를 암호화하는 작은 도구다. 공개 저장소 `github.com/FiloSottile/age`, 형식 사양 공개, 유지보수 중(조사 기준 v1.3.2).
- 한 파일에 **받는 사람(자물쇠)을 여러 개** 걸 수 있다.

| age 용어 | 비유 | 성질 |
|---|---|---|
| 공개키 (`age1…`) | **자물쇠** | 남에게 줘도 안전하다. 잠글 수만 있다 |
| 개인키 (`AGE-SECRET-KEY-1…`) | **열쇠** | 밖에 두면 안 된다. 이것이 있어야 열린다 |

```bash
age-keygen -o <열쇠 파일>                    # 열쇠를 만들면 자물쇠(공개키)도 함께 출력된다
age -r <자물쇠> -r <자물쇠2> -o <조각>.enc <조각>   # 여러 자물쇠로 잠금
age -d -i <열쇠 파일> <조각>.enc              # 열쇠로 풂
```

### 역할 분담

| 맡는 쪽 | 하는 일 |
|---|---|
| age | 암호화·복호화 계산, 암호문 파일 형식 |
| 헤르메스 코드 | 매 턴 조각 만들기, 소우주 × 사람의 자물쇠 목록으로 잠그기, `refs/hermes/sync`에 올리기, 받아서 풀어 `state.db`에 넣기, 열쇠가 없으면 멈추기 |

### 암호를 직접 만들지 않는 이유

암호 구현은 겉으로 동작해도 속에 약점이 숨기 쉽고 스스로 검증하기가 거의 불가능하다. 조사 후보였던
Python `cryptography`(Fernet)는 대칭키만 있어 사람별 자물쇠 구조를 직접 짜야 하므로 age보다 뒤로 밀렸다.
작업 트리 필터 방식인 git-crypt·transcrypt는 우리 저수준 커밋 경로에서 암호화가 조용히 빠질 수 있어
부적합하다([existing-tools-research.md](../../evidence/existing-tools-research.md)).

### 설치 상태 (2026-09-15)

| 항목 | 상태 |
|---|---|
| `age` CLI | 없음 |
| Python `pyrage` (age 바인딩) | 없음 |
| Python | 3.10.12 (pyrage 요구 3.10 이상) |

- 설치는 WSL 환경 규칙에 따라 **사용자가 직접** 한다.
- CLI를 subprocess로 부를지(기존 헤르메스 스크립트 방식과 같음), pyrage를 쓸지는 구현 계획에서 정한다(V-6).

## 2. 열쇠 단위 (확정·합의)

| 규칙 | 상태 | 이유 |
|---|---|---|
| **소우주 × 사람** 단위로 자물쇠를 건다 | 합의 | 같은 소우주를 쓰는 동료끼리 서로의 원문을 풀 수 없게 |
| **컴퓨터마다 자기 열쇠**(B) | 확정 | 한 대를 잃어도 나머지로 계속 연다 |
| **소우주마다 비상 열쇠 하나** | 확정 | 비상 열쇠 하나가 새도 한 소우주만 노출 |

```text
jjackkun 이 zeroday-frontend 에서 만든 턴 조각 하나에 거는 자물쇠
 ├─ 컴퓨터 A 자물쇠   (일상용, 열쇠는 컴퓨터 A 안)
 ├─ 컴퓨터 B 자물쇠   (일상용, 열쇠는 컴퓨터 B 안)
 └─ 비상 자물쇠       (평소에 안 씀, 열쇠는 컴퓨터 밖)
동료 choijh15 의 자물쇠는 걸지 않는다 → 동료는 이 조각을 못 연다
```

- 열쇠 파일 위치(안): `~/.hermes/keys/<universe_id>/` 아래. 저장소 밖이며 git에 절대 올리지 않는다.
- 자물쇠 목록을 어디에 둘지는 미정이다(G-3). 자물쇠는 공개돼도 안전하다.

### 컴퓨터 id 와 재암호화 비용

> ✅ 리뷰 확정 (2026-09-15, RV-02 · RV-03) — 근거: [2026-09-15 리뷰](../../../audits/2026-09-15-hermes-universe-design-review.md) R-2 · R-3. 지문은 사람에게 읽히지 않으므로 등록할 때 적은 별명(예: "노트북")을 화면에 함께 보인다.

**컴퓨터 id = 자물쇠 지문.** 열쇠 파일 이름의 `<컴퓨터 id>` 는 hostname 이 아니다. hostname 은 겹치고 바뀐다(cumora 도 같은 hostname 두 기기 문제를 미확인으로 남겼다). 자물쇠(공개키)의 지문을 그대로 컴퓨터 id 로 쓰면 별도 등록부 없이 자물쇠 목록이 곧 컴퓨터 목록이 된다.

**새 컴퓨터가 과거 조각을 읽는 비용.** 지금 표의 B 안은 "기존 컴퓨터가 다시 잠가 줘야 읽음" 인데, 그것은 **과거 조각 전부를 새 자물쇠로 재암호화해 다시 올리는 일**이다. 컴퓨터를 하나 더할 때마다 저장소가 조각 수만큼 불어난다. 열쇠에 한 층을 더 두면 피할 수 있다.

```text
소우주 × 사람 마스터 열쇠 (age 키쌍 하나)
  ├─ 마스터 열쇠 파일을 컴퓨터 A 자물쇠로 감싼 것   ─┐
  ├─ 마스터 열쇠 파일을 컴퓨터 B 자물쇠로 감싼 것    ├─ keys/<사람 id>/master.<자물쇠 지문>.age  (원격, 평문 아님)
  └─ 마스터 열쇠 파일을 비상 자물쇠로 감싼 것       ─┘
조각은 마스터 자물쇠 **하나**로만 잠근다
```

| | 지금 안 (조각마다 자물쇠 N개) | 마스터 열쇠 감싸기 |
|---|---|---|
| 컴퓨터 추가 | 과거 조각 전부 재암호화 | 마스터 열쇠 파일 하나를 새 자물쇠로 감싸 올림 |
| 컴퓨터 분실 | 그 자물쇠만 목록에서 뺀다. 분실 컴퓨터는 과거 조각을 계속 풀 수 있다 | 마스터 열쇠를 교체하고 새 조각부터 새 마스터. 분실 컴퓨터는 과거 조각을 계속 풀 수 있다(모든 방식 공통) |
| 비상 열쇠 | 조각마다 걸림 | 마스터 열쇠를 감싼 것 하나에만 걸림. 비상 열쇠로 여는 절차가 "마스터 풀기 → 조각 풀기" 두 단계 |

- T-09(컴퓨터마다 자기 열쇠 · 소우주별 비상 열쇠)는 그대로다. 마스터 열쇠는 그 위에 얹는 구현 층이다.
- 손해: 마스터 열쇠가 하나 더 생긴다. 이것도 저장소에는 감싼 형태로만 올라가고, 풀린 형태는 컴퓨터 열쇠와 같은 곳(`~/.hermes/keys/`)에만 있다.
- 자물쇠 등록·폐기를 이벤트(`key.registered` · `key.revoked`, 기계 칸 평문)로 남기면 G-3 의 "자물쇠 목록 위치" 가 `refs/hermes/sync` 안 `keys/` 로 정리된다. cumora 의 기기 제거 = kill switch 와 같은 자리다.

### 검토한 여러 컴퓨터 방식

| | A. 같은 열쇠를 컴퓨터마다 복사 | **B. 컴퓨터마다 자기 열쇠 (채택)** |
|---|---|---|
| 설정 | 한 번 만들어 복사 | 컴퓨터 추가 시 자물쇠 목록에 등록 |
| 한 대를 잃으면 | 열쇠가 샜으니 전부 교체 | 그 컴퓨터 자물쇠만 목록에서 뺀다 |
| 새 컴퓨터가 과거 조각 읽기 | 바로 읽음 | 기존 컴퓨터가 다시 잠가 줘야 읽음 → RV-03(아래 "마스터 열쇠 감싸기")으로 **마스터 열쇠 파일 하나만** 다시 감싸면 됨 |

## 3. 비상 열쇠 (확정)

### 누가 주나

**누구도 주지 않는다. 사용자 컴퓨터에서 직접 만들어진다.** 서버·공장 저장소·AI는 이 열쇠를 갖지 않는다.

### 받는 절차 — 소우주마다 이식을 처음 켤 때 한 번

```text
사용자가 AI 세션 밖 터미널에서 이식 켜기 명령 실행 (명령 이름 미정)
  │
  ① 비상 열쇠 생성          age-keygen. 파일로 저장하지 않고 메모리에만 둔다
  ② 화면에 한 번만 표시      AGE-SECRET-KEY-1… 한 줄
  ③ 사용자가 옮겨 적음      종이 인쇄 + 비밀번호 관리자 (둘 다 권장)
  ④ 옮긴 것이 맞는지 검사    옮겨 둔 열쇠를 다시 붙여넣게 함
                            → 시험용 암호문을 실제로 풀어 봄
                            → 성공해야만 다음 단계
  ⑤ 개인키 폐기             컴퓨터 어디에도 남기지 않음
  ⑥ 자물쇠만 등록           비상 자물쇠를 자물쇠 목록에 추가
  │
이식 켜짐
```

- ④가 핵심이다. "적었다"만 믿으면 오타 난 열쇠를 보관하다가 정작 필요할 때 못 연다.

### 보관

| 방법 | 장점 | 약점 |
|---|---|---|
| 종이 인쇄 → 금고·서랍 | 해킹당하지 않는다 | 분실·화재 |
| 비밀번호 관리자 | 편하다 | 관리자 주 비밀번호를 잊으면 함께 잃는다 |

- 저장소나 컴퓨터 안에는 **절대 두지 않는다.** 조사한 enclaude는 백업 열쇠를 저장소에 함께 올렸다. 이 방식을 참고만 하기로 한 이유 중 하나다.

### 쓴 뒤

비상 열쇠로 한 번 열면 그 열쇠는 컴퓨터에 한 번 들어간 셈이다. **같은 절차로 새 비상 열쇠를 만들고**,
앞으로의 조각은 새 비상 자물쇠로 잠근다. 옛 비상 열쇠는 과거 조각을 열 때 필요하므로 계속 보관한다.

> ✅ RV-03 에 따라(2절 마스터 열쇠 감싸기) 비상 열쇠가 여는 것은 조각이 아니라 **마스터 열쇠를 감싼 파일**이다. 여는 절차는 "비상 열쇠로 마스터 열쇠 풀기 → 마스터 열쇠로 조각 풀기" 두 단계이고, ④ 시험 복호화도 이 두 단계를 그대로 돌린다. 비상 열쇠를 쓴 뒤에는 새 비상 자물쇠로 마스터 열쇠를 다시 감싸기만 하면 된다(조각 재암호화 없음). 세부는 G-28.

## 4. 열쇠는 AI 세션 밖에서만 (확정)

AI 세션 안에서 열쇠를 만들거나 붙여넣으면 그 글자가 대화 원문으로 기록된다.

| 기록되는 곳 | 결과 |
|---|---|
| `state.db` 대화 원문 | 평문으로 남음 |
| Claude Code 기록 `~/.claude/projects/` | 평문으로 남음 |
| 요약·결정화 | 모델로 전송될 수 있음 |

- 열쇠 생성과 붙여넣기는 **AI 세션이 아닌 별도 터미널 창에서 사용자가 직접** 한다. 세션 안 `!` 접두어 실행도 출력이 대화에 남으므로 안 된다.
- **기계 강제:** 훅이 AI 세션 안의 `age-keygen` 실행이나 `AGE-SECRET-KEY-` 글자를 발견하면 차단한다.

> ✅ 리뷰 확정 (2026-09-15, RV-04) — 한계 명시: 이 차단은 **Claude Code 훅**이다. Codex 세션에서는 헤르메스 훅이 돌지 않으므로(CLAUDE.md "Codex 세션에서는 미동작") 이 규칙은 사람 규율로만 남는다. cumora 도 Codex 를 `--ignore-user-config --ignore-rules` 로 띄워 훅·규칙 층을 아예 뺀다(`docs/BYOA.md` "Secure default"). Codex 지원이 들어오기 전까지 열쇠 취급은 "AI 세션 밖" 이 유일한 방어다.

## 5. 잃어버렸을 때

외워야 할 비밀번호는 없다. 매일 쓰는 것은 컴퓨터에 저장된 열쇠 파일이다.

| 상황 | 결과·대비 |
|---|---|
| 컴퓨터 한 대 고장 | 다른 컴퓨터 열쇠로 계속 연다. 고장 난 컴퓨터 자물쇠만 목록에서 뺀다 |
| 모든 컴퓨터를 한꺼번에 잃음(WSL 전부 재설치 등) | 비상 열쇠로 연다 |
| 비상 열쇠까지 잃음 | 원격 암호문 원문을 영구히 못 연다 |

열쇠를 전부 잃어도 사라지지 않는 것:

| 대상 | 영향 |
|---|---|
| 코드 | 없음 |
| 스킬 | 없음 (평문) |
| 작업 이력 기계 칸 | 없음 (평문) |
| 남아 있는 컴퓨터의 `state.db` 원문 | 없음 (로컬 평문) |
| 원격 암호문(원문, 이력 자유 글 칸) | **열 수 없음** → 새 컴퓨터에서 과거 대화 회상을 이어받지 못함 |

원격 암호문은 컴퓨터 사이를 오가는 **운반용 사본**이지 유일한 원본이 아니다.

## 6. 키 교체

- age에는 교체 명령이 없다. 열쇠를 바꾸면 **새 조각부터 새 자물쇠**로 잠근다.
- 옛 조각은 옛 열쇠로만 열리므로 옛 열쇠를 버리면 안 된다.
- 이미 원격에 올라간 옛 암호문은 옛 열쇠를 가진 사람이 계속 풀 수 있다. 모든 도구에 공통인 한계다.
- 세부 절차는 미정이다(G-4).
