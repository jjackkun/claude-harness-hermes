소우주에서 에이전트와 일하는 일곱 단계

전부 대화로 합니다. 각 단계의 첫 칸에 적힌 말을 세션에서 하면, hermes-agent 스킬이 뒤에서 명령을 대신 실행하고 이력에 남깁니다. 명령과 출력은 "무슨 일이 일어나는지" 를 보여드리려고 적은 것이지, 직접 치라는 뜻이 아닙니다.

기준 소우주 terminal-shipping 실측일 2026-09-17 출력은 소우주 사본에서 그대로 가져옴

00조직 축을 정한다 — 한 번만

에이전트는 경로를 갖지 않고 세 축의 값만 갖습니다: 분야(discipline) · 직급(rank) · 조직(unit). 이 축이 비어 있으면 입사가 거부됩니다. 설치 직후의 소우주는 비어 있습니다.

말한다사람이

우리 조직은 백엔드·프론트엔드·QA, 직급은 리드·담당, 조직은 선적이랑 공통이야.

스킬은 축 값을 추측해 넣지 않습니다. 값이 불확실하면 되묻고, 사람이 정해 주면 파일을 채웁니다.

일어난다뒤에서

.hermes/organization.yaml 이 채워집니다. 허용 형식은 평면 목록과 2단 맵뿐입니다(앵커·별칭·다중 문서 거부 — 표준 모듈에 YAML 이 없어 자체 파서로 읽습니다).

# .hermes/organization.yaml
discipline: [백엔드, 프론트엔드, QA]
rank: [리드, 담당]            # 위에서 아래 순. 맨 위 human 은 기계가 붙인다
unit:
  선적: {code: [src/shipping/**]}
  공통: {code: [src/shared/**]}
보인다화면에

축 없이 입사를 시도하면 이 한 줄이 돌아옵니다 — 그때가 이 단계를 할 때입니다.

$ python3 scripts/hermes-agent.py hire "유저스담당" --org "backend/staff/users"
[hermes-agent] 거부: discipline 'backend/staff/users' 은 organization.yaml 에 없다
확인넘어가기 전
  • .hermes/organization.yaml 에 세 축이 다 있다
  • 영역과 경로의 연결(code:)은 조직(unit)에만 적었다 — 폴더가 바뀌어도 에이전트는 안 고친다

01입사시킨다

이름은 명부에서 유일해야 하고(은퇴자 포함), 조직 값은 0단계의 축에 있어야 합니다. 처음 상태는 probation(수습)입니다.

말한다사람이

선적 담당 QA 한 명 뽑아. 이름은 선적QA.

일어난다뒤에서
python3 scripts/hermes-agent.py hire "선적QA" --org "QA,담당,선적"

주의 --org 는 쉼표로 나눕니다(분야,직급,조직). 빈 칸은 비워 둘 수 있습니다(QA,,선적).

보인다화면에
입사: 선적QA (01a0ae58-6aa6-7202-ae81-7d27af7b5617) status=probation org={'discipline': 'QA', 'rank': '담당', 'unit': '선적'}
정체성: .hermes/agents/01a0ae58-6aa6-7202-ae81-7d27af7b5617/  — SOUL.md 를 채우십시오(사람 승인으로만 수정)

정체성 폴더가 생깁니다. SOUL.md 는 사람이 채우는 파일입니다 — 에이전트가 자기 정체성을 쓰지 않습니다. MEMORY.md 는 기계가 이벤트에서 계산해 쓰므로 손대지 않습니다.

# .hermes/agents/01a0ae58-…/SOUL.md 머리
---
agent_id: 01a0ae58-6aa6-7202-ae81-7d27af7b5617
name: 선적QA
status: probation
org: {"discipline": "QA", "rank": "담당", "unit": "선적"}
created_by: human:jjackkun
---
확인넘어가기 전
  • 출력에 status=probation 과 정체성 경로가 있다
  • SOUL.md 에 이 에이전트가 무엇을 맡고 무엇을 하지 않는지 사람이 적었다

02명부를 보고 담당을 찾는다

읽기 전용이라 확인 없이 바로 실행됩니다. 맞는 담당이 없으면 스킬은 아무나 고르지 않고 ask: 로 사람에게 돌립니다.

말한다사람이

명부 보여줘.

이 결제 버그 누가 맡지?

일어난다뒤에서
python3 scripts/hermes-agent.py list

확인넘어가기 전
  • 후보가 여럿이면 목록에서 사람이 고른다
  • ask: 가 나오면 1단계로 돌아가 입사시킨다

03지금 일을 시킨다 — 소환

그 에이전트 명의로 별도 세션을 띄워 한 가지 일을 시킵니다. 빠르지만 성공 기준이 느슨합니다. "이게 되면 끝" 이라는 기준이나 기한이 있으면 4단계(인계)를 씁니다.

말한다사람이

선적 조회 화면 회귀 테스트, 선적QA 한테 지금 넘겨.

일어난다뒤에서
python3 scripts/hermes-summon.py run "선적QA" --task "선적 조회 화면 회귀 테스트 작성"

러너가 하는 일, 순서대로: ① 명부에서 에이전트를 찾고 1회용 토큰(nonce)을 발급 → ② 이력에 task.assigned 기록 → ③ claude -p "[소환] 당신은 선적QA (agent:01a0ae58-…) 입니다.\n\n<task>" 를 HERMES_AGENT_ID 환경변수와 함께 실행 → ④ 종료 코드를 task.finished 로 기록. 은퇴자는 소환할 수 없고, 이름 대신 축 값(--discipline QA)으로 고를 수도 있습니다.

가드 세션 안에서 claude -p 를 직접 부르면 소환 가드가 막습니다. 토큰은 러너만 발급하므로 에이전트가 자기를 사칭할 수 없습니다.

보인다화면에
[hermes-summon] 선적QA 종료 rc=0 task=<task_id>

소환된 세션은 시작 훅(claude-sessionstart-agent-soul.sh)이 그 에이전트의 SOUL.md·MEMORY.md 를 세션 문맥에 넣어 주고 시작합니다 — 머리에 [헤르메스 출근] 선적QA (agent:…) 한 줄이 붙습니다. 각 4,096 B 상한이며 넘치면 잘라 원문 경로를 남깁니다. 은퇴한 에이전트는 넣지 않습니다.

확인넘어가기 전
  • rc=0 이면 완료 주장, 아니면 실패 — 둘 다 이력에 남는다
  • 결과가 "확실히 됐는지" 기계가 재야 하면 소환이 아니라 인계였다

04기준을 적어 넘긴다 — 인계

봉투에 goal(무엇을)과 done_when(무엇이 되면 끝)이 없으면 기계가 막습니다. 원문 붙여넣기도 막힙니다 — inputs 에는 파일 경로나 이벤트 id 같은 참조만 둡니다.

말한다사람이

이 결제 리팩터 선적QA 한테 인계해. 회귀 테스트 통과하면 끝이고, 금요일까지.

"통과하면 끝", "금요일까지" — 기준과 기한이 나오는 순간 스킬은 소환이 아니라 인계를 고릅니다.

일어난다뒤에서
from hermes_handoff import open_handoff
hid = open_handoff(".hermes/state.db", ".", "선적QA",
  {"goal": "결제 리팩터 QA",
   "done_when": "test:tests/payments-regression.sh",
   "inputs": ["src/payments/refactor.md"],
   "expires_at": "2026-09-19T00:00:00Z"},
  by="human:jjackkun")
done_when 형식뜻판정
test:<이름>그 테스트의 종료 코드pass / fail
file:<경로>파일 존재pass / fail
gate:<규칙>.harness/gate-events.jsonl 최근 판정pass / fail
commit:<해시|HEAD>저장소에 그 커밋이 있는가pass / fail
manual사람이 잰다none

이 다섯 형식만 허용됩니다. manual 만 기계가 재지 않습니다.

보인다화면에

받는 쪽은 봉투를 검사하고 시작하며, 넷 중 하나로 닫습니다: finished(완료 — done_when 을 기계가 다시 재서 검증값을 채움) · declined(거절, 사유 필수) · question(되묻기, 사유 필수) · expired(만료).

from hermes_handoff import resolve
resolve(".hermes/state.db", ".", "<handoff_id>", "finished", "agent:01a0ae58-…")

만료는 시간 데몬이 아니라 세션 시작 훅이 처리합니다. 기한이 지났는데 시작도 되묻기도 없는 봉투에 다음 세션 시작 때 자동으로 handoff.expired 가 붙고 알림이 뜹니다. 사람이 손댈 일은 없습니다.

확인넘어가기 전
  • done_when 이 다섯 형식 중 하나다 — 산문("잘 되면")은 거부된다
  • 기한이 있으면 expires_at 을 ISO 8601 UTC 로 적었다

05승급 · 은퇴 · 복직

은퇴는 되돌리기 어려운 판단이라 스킬이 대상과 영향(매칭·소환·스킬 주입에서 빠짐)을 사람에게 확인한 뒤 실행합니다. 파일은 남으므로 복직으로 되돌립니다.

말한다사람이

선적백엔드 수습 끝났어, 정식으로 올려.

선적QA 은퇴시켜.

선적QA 다시 복직시켜.

일어난다뒤에서
python3 scripts/hermes-agent.py promote "선적백엔드"   # probation → active
python3 scripts/hermes-agent.py retire  "선적QA"      # 확인 뒤. 명부에서 빠지고 파일은 남는다
python3 scripts/hermes-agent.py rehire  "선적QA"
보인다화면에
promote: 선적백엔드 → active
확인넘어가기 전
  • 은퇴 전에 그 담당에게 열린 인계 봉투가 없는지 명부·이력으로 본다

06내가 누구인지, 무엇이 남는지

모든 입사·소환·인계는 CLI 를 거쳐 이력(journal_events)에 남습니다. 손으로 SQL 을 넣지 않는 이유가 이것입니다 — CLI 가 검증·토큰·이력을 책임집니다.

말한다사람이

지금 나 누구야?

일어난다뒤에서
python3 scripts/hermes-agent.py whoami   # HERMES_AGENT_ID 기준
보인다화면에

A파일 지도

소우주 루트 기준. 굵은 것만 사람이 편집합니다.

.hermes/ ├── organization.yaml 세 축 정의 — 0단계에서 사람이 채움 ├── agents.json 명부 — CLI 만 쓴다 ├── agents/<id>/ │ ├── SOUL.md 정체성 — 사람 승인으로만 수정 │ ├── MEMORY.md 기억 — 기계가 이벤트에서 계산 │ └── skills/ 그 에이전트 개인 스킬 ├── state.db 이력(journal_events)·인계 봉투·스킬 색인 ├── summons/<nonce>.pending 소환 토큰 — 러너가 남기고 시작 훅이 검증 └── universe.id scripts/ ├── hermes-agent.py hire · match · list · whoami · promote · retire · rehire ├── hermes-summon.py run — 소환 러너 └── hermes_handoff.py open_handoff · resolve — 인계 봉투 .claude/skills/hermes-agent/SKILL.md 자연어 → 위 명령 대응표

B지금 알려진 구멍 (2026-09-17 실측)

숨기지 않고 적는 자리입니다. 2026-09-17 기준 남은 구멍은 없습니다 — 같은 날 발견한 둘(스킬 문서의 --org 구분자, 소환 세션의 SOUL.md 미주입)은 공장에서 고쳐 전파했습니다.
