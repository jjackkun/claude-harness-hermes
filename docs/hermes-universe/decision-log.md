## 개요

- 각 항목은 `결정 — 이유 — 틀렸을 때 손해` 형식을 따른다.
- 상태: **확정**(사용자 명시) · **합의**(명시 확정은 없으나 이후 논의가 그 전제 위에서 진행) ·
  **폐기**(뒤집힘. 무엇으로 바뀌었는지 함께 적음).
- 날짜는 2026-09-15 한 번의 논의다. 순서가 곧 시간순이다. 계획서 작성 뒤 추가한 항목(T-14 · T-15 · T-16 · C-18)은 결정 칸 앞에 `(2026-09-16)` 을 붙였다.

## 결정 ID (접두어 표 — 이 원장이 정본)

`<접두어>-<두 자리 순번>`. 접두어는 주제 글자, 번호는 접두어 안에서 유일하며 재사용하지 않는다(뒤집힘은 `폐기 → 새 ID`).
설계 문서의 "(확정)"·"(합의)" 절 제목은 이 표의 ID 를 단다(`## 3. 입사 경로 (확정, A-02 · A-03)`). `R-design-cover`
판정기는 접두어 목록을 손으로 들고 있지 않고 **이 파일의 `| X-NN |` 행에서 읽는다** — 새 주제는 행을 추가하면 곧 등록된다.
질문(`Q-`·`G-`, open-questions.md)과 외부 참조(`K-` cumora, `ZD-` zeroday 실측)는 결정이 아니므로 절 제목에 달지 않는다.
