# 느린 함수 하나만 찾아 바꾸고, 원래 답과 하나하나 대조해 같을 때만 바꾼다

## 개요

- 제목: 파이썬 앱 103배 빨라짐? 느린 5%만 Rust로 #Claude #AI
- 채널: 찐AI · 길이 0:51(쇼츠) · 올린 날 2026-11-24
- URL: https://www.youtube.com/watch?v=G07UbhYSw2g
- 소개 도구: fast-anything (https://github.com/EL4CTEO/fast-anything)

영상에 따르면, 앱 전체를 다른 언어로 다시 짜지 않고 프로파일러로 가장 느린 함수 하나를 찾아 그 함수만
Claude Code·Codex 가 Rust 로 옮긴다. 실제 호출을 최대 500번 기록해 원래 코드와 답을 하나씩 비교하고,
하나라도 다르거나 더 느리면 바꾸지 않는다.

### 타임라인

- 00:00 파이썬 앱 5.05초 → 49ms, 103배(화면: `python app.py is 103x faster end to end`)
- 00:05 앱 전체를 다시 짠 게 아니라 느린 함수 하나만 바꿨다
- 00:11 전부 Rust 로 옮기면 몇 달 — 시간은 함수 몇 개가 먹는다(화면: find_duplicates 99.9% / 나머지 0.1%)
- 00:15 먼저 앱을 돌려 제일 느린 함수를 찾는다(화면: 프로파일 표 `fuzzy.find_duplicates 99.9%`)
- 00:19 Claude Code·Codex 가 그 함수만 Rust 로 옮긴다
- 00:20 핵심은 검증 — 실제 호출 최대 500번 기록, 원래 코드와 답 비교
- 00:27 데모에서 500번 중 148번 틀린 것을 잡았다(화면: levenshtein 이 바이트 단위로 세서 한글·악센트 이름에서 답이 다름)
- 00:29 답이 하나라도 다르거나 더 느려지면 바꾸지 않는다
- 00:32 Python·JavaScript·Java·Go·PHP·C# 지원, 언제든 되돌릴 수 있다
- 00:40 빨라지는 정도는 제각각 — 공식 결과 PHP 55배, Go 21배, Java 3배

## 걸러 들어야 할 부분

- 103배·55배·21배는 영상이 "공식 데모·공식 결과" 로만 보인 숫자다. 우리가 재지 않았다.
- 103배는 한 함수가 시간의 99.9% 를 먹는 데모 앱 기준이다. 시간이 고르게 퍼진 앱에서는 이만큼 나오지 않는다.

## 본 프로젝트와의 접점

- **옮긴 것 — 프로파일로 범인 하나 찾기**: 공장 설치(`project-claude.sh`)를 `bash -x` + `EPOCHREALTIME` 으로
  줄 단위 프로파일했다. `manifest_add` 가 설치 시간의 53~55%(설치 1회 347번 호출, 호출마다 python 기동).
- **옮긴 것 — 원래 답과 대조해 같을 때만 바꾸기**: 고치기 전 설치 5장면의 파일 432개 해시와 설치 목록을 기준선으로
  찍고, 고친 뒤 바이트까지 같은지 대조했다. 계획: `docs/exec-plans/active/2026-11-25-manifest-batch-write.md`
- **옮기지 않은 것 — 다른 언어로 다시 쓰기**: 우리 쪽 느린 원인은 계산이 아니라 프로세스 기동 횟수였다.
  언어를 바꿔도 줄지 않고, 호출을 묶어야 줄어든다. fast-anything 은 bash 를 지원하지 않는다.
- 설치 밖(작업 중 훅·커밋 게이트·학습 루프·스킬 스크립트)은 모두 0.3초 아래이거나 백그라운드였다.
