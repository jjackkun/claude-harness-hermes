# 2026-09-23-test-suite-parallel — 전체 시험 묶음을 병렬로 돌린다

## 1. 동기 (Why)

**실측 2026-09-23**: `bash tests/run-all.sh` 107개가 **35분**(09:41 → 10:16, 107/107 통과).
백로그 `test-suite-parallel.md` 참조. 느린 시험 하나가 아니라 구조다 — 17개가
`project-claude.sh` 전체 설치(파일 95개 복사 + settings·CLAUDE.md 생성)를 하고 **순차로** 돈다.

진짜 비용은 35분이 아니라 **"도는 동안 저장소를 못 고친다 × 반복 횟수"** 다.
한 세션에서 4번 돌려 3번을 중간에 죽였다(도중에 파일을 고쳐 결과가 무의미해짐).
사용자가 "26분째 하고 있어. 이게 맞아?" 라고 물었다.

## 2. 목표 (검증 가능한 형태)

- [ ] 목표 1 — `HARNESS_TEST_JOBS=1`(기본)이면 **동작이 지금과 완전히 같다**.
      검증: `tests/run-all-parallel-test.sh` — 기본값에서 출력 형식(`── RUN/PASS/FAIL:`)과
      요약 줄이 그대로이고, 실패 1건을 심으면 rc 1 · 실패 목록에 그 이름.
- [ ] 목표 2 — `HARNESS_TEST_JOBS=N`(N>1)이면 **판정 집합이 같다**.
      검증: 같은 시험 — 일부러 깨뜨린 시험 1개를 포함한 픽스처 목록을 순차/병렬로 돌려
      통과·실패 이름 집합이 일치.
- [ ] 목표 3 — 병렬에서도 **한 시험의 출력이 통째로** 읽힌다(섞이지 않는다).
      검증: 같은 시험 — 두 시험이 각각 여러 줄을 내도록 하고, 각 `── RUN: X ──` 와
      `── PASS/FAIL: X ──` 사이에 다른 시험의 줄이 끼지 않음을 단언.
- [ ] 목표 4 — 실제 묶음이 **10분 이내**. 검증: `time bash tests/run-all.sh` (JOBS 기본을 N 으로 올린 뒤).

- 시험을 지우거나 단언을 줄여 시간을 버는 것. 107개는 이 세션에서 실제로 결함 3건을 잡았다.
- 설치 자체(파일 95건 복사)를 빠르게 만드는 것 — 별건, 위험이 크다.

- CI 이관. CI 는 60회 연속 실패한 이력이 있다 — 로컬에서 돌 수 있어야 한다.
