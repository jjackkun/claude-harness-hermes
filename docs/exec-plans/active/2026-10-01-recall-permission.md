# 2026-10-01-recall-permission — recall 을 헤르메스 프리셋의 허용 목록에 넣고, 안내가 토큰을 덜 쓰게 한다

> 작성일: 2026-10-01
> 목적: auto mode 가 아닌 사용자도 에이전트가 기억을 찾을 때마다 승인 질문을 받지 않게 한다. 안내 문구가 낱말을 한 번에 넣도록 이끌어 호출당 토큰을 줄인다.
> 앞선 계획: `docs/exec-plans/completed/2026-10-01-agent-recall.md` — §7 "실제 세션 실측" 의 미해결 발견이 직접 근거다. 사용자 결정(2026-10-01): "넣어야 한다고 생각해."

## 1. 동기 (Why)

실제 세션 실측에서 에이전트가 `python3 scripts/hermes-agent.py recall …` 을 스스로 불렀다. 그런데:

- 설치기가 미리 허용하는 Bash 규칙 29개(`assets/permissions/base.json`)에 이 명령이 없다. 실측은 사용자 계정의 **auto mode** 가 실행을 허용해("Allowed by auto mode classifier") 질문이 없었지만, **auto mode 가 아니면 호출마다 승인을 묻는다.** 기억을 찾는 도구가 매번 질문을 부르면 에이전트가 덜 쓰게 된다.
- `recall` 은 읽기 전용(`mode=ro`)이라 허용해도 안전하다. `base.json` 은 헤르메스가 없는 프로젝트에도 머지되므로 **헤르메스 프리셋 전용 파일**로 둔다(파이썬 프리셋은 이미 `Bash(python3:*)` 전체를 허용한다 — 허용 범위는 더 좁게).
- 같은 실측의 토큰 기록: 기억 찾기 한 번이 컨텍스트에 더한 입력은 **+765 토큰**(두 낱말, 맞음 2건) ~ **+2,047 토큰**(상한 4,096B 근처). 음성 대조에서 에이전트가 **낱말마다 호출을 따로**(`for k in 배포 일정 요일 deploy`) 해 한 질문에 약 4,100 토큰을 썼다. `recall` 은 낱말 여러 개를 한 번에 받아 맞는 낱말 수로 순위를 매기므로 한 번에 넣는 것이 싸다.

> 여기까지 다시 읽었다: 이 계획은 권한 한 줄과 안내 문구 한 줄이다. 권한은 **읽기 전용 명령 하나**만 열고 다른 `hermes-agent.py` 하위 명령(`teach` `retire` …)은 열지 않는다.

## 2. 목표 (What — 검증 가능한 형태)

- [x] 목표 1 — **헤르메스 프리셋이 설치된 프로젝트의 `settings.json` 허용 목록에 recall 규칙이 있고, 헤르메스가 없는 프로젝트에는 없다.** 규칙은 `Bash(python3 scripts/hermes-agent.py recall:*)` 하나. 검증: `bash tests/hermes-permissions-test.sh` — `harness hermes` 설치 → 규칙 1개 · `harness` 만 설치 → 0개.
- [x] 목표 2 — **허용 범위가 recall 하나뿐이다.** `hermes-agent.py` 의 다른 하위 명령을 여는 규칙(`Bash(python3 scripts/hermes-agent.py:*)` · `Bash(python3 scripts/*)` 등)이 이 파일에 없다. 검증: 같은 시험 — `hermes.json` 의 allow 가 정확히 그 한 줄이고 `teach`·`retire`·`approve-soul` 을 여는 규칙이 없다.
- [x] 목표 3 — **주입 안내가 낱말을 한 번에 여러 개 넣도록 이끈다.** 안내 줄이 `recall <호출명> "<낱말을 한 번에 여러 개>"` 꼴이다. 길이 ≤ 300B 유지. 검증: `bash tests/hermes-soul-inject-test.sh` — 안내 줄 단언(호출명 있음·없음)과 300B 단언.
- [ ] 목표 4 — **전파된 곳의 설정에 들어간다.** 헤르메스 프리셋이 있는 소우주에 `update-all` 을 돌린 뒤 `settings.json` 허용 목록에 그 규칙이 있다. 검증: 설치 후 각 곳의 `.claude/settings.json` 을 읽어 규칙 유무를 센다(헤르메스 프리셋이 없는 `rim-kanban`·`teulankkae` 는 0개여야 한다).
- [x] 목표 5 — **실제 세션에서 승인 질문 없이 도는 것을 확인한다(auto mode 아님).** 검증: 일회용 프로젝트에 설치한 뒤 `claude --permission-mode default --agent backlog-manager` 로 열어 방 안에서 기억을 물으면 recall 이 **승인 질문 없이** 실행된다 — 규칙 없이(전)는 질문이 뜨는 것도 함께 본다.

## 3. 비목표 (Out of Scope)

- `hermes-agent.py` 의 다른 하위 명령 허용 — 쓰기 명령(`teach` `note` `pin` `retire` …)은 승인 질문이 맞다.
- `base.json` 변경 — 헤르메스가 없는 프로젝트에 영향을 주지 않는다.
- auto mode 분류기 설정.

## 6. 의사결정 로그

- 2026-10-01: **헤르메스 프리셋 전용 권한 파일** — 근거: `base.json` 은 모든 프리셋에 머지돼 헤르메스가 없는 프로젝트에도 규칙이 들어간다. 기존 관례(`python.json` · `node.json` · `pm2.json`)와 같다. 손해: 파일 하나가 늘고 프리셋 conf 에 한 줄이 늘어난다.
- 2026-10-01: **허용은 `recall` 하위 명령 한 개** — 근거: 읽기 전용(`mode=ro`)이고 출력이 4,096B 로 묶여 있다. 쓰기 하위 명령은 승인 질문이 안전장치다. 손해: 에이전트가 `recall` 이 아닌 `hermes-agent.py` 명령을 부르면 여전히 질문이 뜬다 — 의도한 것이다.
- 2026-10-01: **안내 문구는 "낱말을 한 번에 여러 개"** — 근거: 실측에서 낱말마다 호출을 따로 해 한 질문에 약 4,100 토큰을 썼다. `recall` 은 모든 낱말을 한 번에 받아 맞는 수로 순위를 매긴다. 손해: 안내가 약 30B 늘어난다(≤ 300B 안).

## 7. 발견·예외

- 2026-10-01 **토큰 실측(사용자 질문 "기억을 가져오는 데 토큰을 많이 쓰나?")** — 실제 세션 기록(`usage`)에서 recall 호출 다음 호출의 입력 증가를 쟀다(캐시 읽기 포함 총 입력 토큰). 기준 입력은 호출마다 약 7.7만~9.1만 토큰(시스템·도구·스킬·하네스 문맥)이라 기억 찾기는 그 위의 작은 증분이다.
  | 상황 | 호출 | 입력 증가 |
  | --- | --- | --- |
  | 양성: "결제"·"수수료" 두 낱말, 맞음 2건(방 C) | 1회(복합 명령) | **+765** |
  | 음성 대조: "배포 일정 요일 deploy" 를 낱말마다 따로 | 4회 | **+2,047 · +2,100** (일정이 필러 요약에 맞아 상한 4,096B 근처) |
  | 규칙 설치 후: 낱말 5개를 **한 번에**(맞음 4건) | 1회 | **+947** |
  교정: 한국어 텍스트에서 **약 2 B/토큰**(4,096B 상한 ≈ 2,000 토큰 — 상한 근처 출력의 실측 +2,047 과 맞다). 세션 시작 주입 6.7KB ≈ 3.3K 토큰이 이미 있던 것이고, 이 계획이 더한 안내 줄은 257B ≈ 130 토큰이다. **기억을 찾을 때만** 호출당 약 0.8K~2.1K 토큰이 컨텍스트에 더해져 그 세션이 끝날 때까지 남는다(다음 호출부터는 캐시 읽기).
- 2026-10-01 **실제 세션 확인(목표 5)** — 일회용 프로젝트, `claude --setting-sources project --permission-mode default`(사용자 전역 설정을 빼고 승인 질문이 뜨는 모드):
  1. **대조군(규칙 없음)**: recall 호출에 "This command requires approval — Do you want to proceed?" 질문이 떴다(거부하고 닫음).
  2. **규칙 설치 후**: 같은 질문에 recall 이 **승인 질문 없이** 실행되어 "토스, 2.9%" 를 찾아 답했다. 낱말을 한 번의 호출에 모았다(새 안내 문구의 효과).
  **주의 — 이 계정의 전역 설정에는 `Bash(python3:*)` 가 이미 있어서** 전역 설정을 쓰는 평소 세션에서는 규칙 없이도 질문이 안 뜬다(처음 대조군이 그래서 무의미했다). 이 규칙은 **전역에 그런 허용이 없는 사용자**와 파이썬 프리셋이 없는 헤르메스 프로젝트를 위한 것이다. `--setting-sources project` 가 전역 설정에 오염되지 않는 시험 방법이다.


- 2026-10-01 **구현 리뷰(`code-reviewer`, 보안 관점) — 승인(차단 0 · 경고 0 · 참고 3).** 확인된 것: recall 은 끝까지 읽기 전용(모든 경로 `mode=ro` · 실제 `state.db` 체크섬 전후 동일) · `--project` 는 서브명령 **앞**의 최상위 인자라 `recall … --project /다른경로` 는 argparse 오류로 끝난다 · `recall x '$(touch …)'` 는 인자 문자열로만 처리 · 규칙 문자열과 안내 문구의 상대 경로가 같다 · `update-all` 은 하네스 소유 항목을 걷어낸 뒤 다시 더하고 `dict.fromkeys` 로 중복을 없애 규칙이 한 번만 들어간다(헤르메스 프리셋을 빼면 회수) · 다른 시험(preset-integrity · update-all-roundtrip 34/0)은 영향 없음. 참고: ① 규칙은 프로젝트 루트에서 실행할 때만 맞는다(상대 경로) ② 사용자가 같은 규칙을 직접 적어 두면 프리셋을 뺄 때 하네스 소유로 보고 함께 지워진다 ③ 읽기 전용 연결에서도 `state.db-shm` 의 mtime 은 바뀐다(내용 변경 아님) — "파일이 하나도 안 바뀐다" 고 쓰면 부정확하다.
