## 1. 동기 (Why)

`hermes-agent` 스킬은 자연어 → CLI 대응표만 있고(2026-09-18 확인, 폼 지시 0줄), 사용자가 분야·직급·조직·이름을 한 문장에 정확히
담아야 한다. 반면 `/hermes-loop` 는 "먼저 옵션 폼을 보여주고 필수만 채우게 한 뒤 실행" 이 스킬에 명시돼 있어 명령을 외울 필요가 없다.
두 스킬의 진입 경험이 다르다. 또 이 저장소의 `organization.yaml` 은 빈 조직(discipline·rank·unit 전부 [])이라 지금은 `hire` 자체가
거부된다 — 첫 실행은 조직 정의부터 폼으로 받아야 한다.

C-19 는 "자연어를 축 값으로 판별하는 모델 호출을 두지 않는다" 고 정했다. 폼은 그 반대편에 있다: 사람이 **정의된 축 값 중에서 고르므로**
판별이 필요 없고, CLI 인자는 그대로 검증된다. 폼은 C-19 와 충돌하지 않고 오히려 C-19 가 남긴 "오판 → 잘못된 인자" 위험을 없앤다.

## 7. 발견·예외

- 2026-09-19 시연(이 저장소): 조직 정의 폼 → 사용자 답 "둘 다 + 무엇이든 가능" → `organization.yaml` 에 제품형+사무형 합침(분야 10·직급 6·조직 4)
  → `hire "게이트QA" --org "QA,담당,공통"` 성공(probation, `unit_id` 자동 부여) → 같은 이름 재입사 `exit 2` 거부 실측. 목표 1~4 충족.
- 사용자 피드백: 선택지 폼을 연달아 띄우자 "의미 없는 질문" — 값이 자유라고 답하면 더 묻지 않는다. 스킬 0-1·0-2 에 "어떤 값이든·새 값 추가" 명시.
- `AskUserQuestion` 은 질문당 선택지 4개 한도 — 축 값이 그보다 많으면 질문 본문에 전부 나열하고 선택지엔 4개만(스킬 0-2 에 기록).
- `hire` 의 `ensure_unit_ids` 가 `organization.yaml` 을 다시 쓰면서 머리말 주석이 사라진다 — 값은 보존. 룰 후보 아님(파생 파일).
- 목표 5(SOUL 세 답): 폼 대신 산문으로 한 번에 받기로 — 사용자 답 대기.
- 목표 6(run_eval): 세션 안에서 12 질의 전부 0% — 헤드리스 claude 호출 직접 프로브는 summon-guard(RV-06) 가 차단해 진단 불가(우회 안 함).
  실행은 세션 밖 터미널에서: `cd <빈 루트> && PYTHONPATH=<skill-creator> python3 -m scripts.run_eval --eval-set assets/skills/hermes-agent/evals/trigger-eval.json --skill-path assets/skills/hermes-agent`.
