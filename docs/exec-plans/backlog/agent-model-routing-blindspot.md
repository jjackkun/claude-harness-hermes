# 에이전트 모델 선언이 맞는지 관측할 데이터가 없다

## 무엇

`assets/agents/` 15종이 각자 `model:` 을 선언한다. 2026-09-08 실측:

| 모델 | 개수 | 대표 |
|---|---|---|
| opus | 2 | architect · planner |
| sonnet | 11 | code-reviewer · 언어별 리뷰어 · tdd-guide |
| haiku | 1 | doc-updater |
| inherit | 1 | fullstack-developer |

**이 배분이 맞는지 판단할 데이터가 한 건도 없다.**

`.harness/gate-events.jsonl`(2026-09-08 기준 376건, 매 Bash 호출마다 늘어난다) 에서 `R-pipe` 15건이 리뷰어 dispatch 를 빚 청산으로
기록하지만, **어느 에이전트를 불렀는지도 어느 모델이 돌았는지도 남지 않는다.**

## 왜 문제인가

선언은 도메인 지식으로 한 번 정한 값이고, 그 뒤로 검증된 적이 없다. 지금 상태로는
다음 질문 중 어느 것에도 답할 수 없다.

- `sonnet` 으로 박아둔 리뷰어가 실제로는 `opus` 여야 하는가 (놓친 결함이 있는가)
- `haiku` 인 `doc-updater` 가 계속 헛일을 하고 재실행을 부르는가
- 15종 중 실제로 불리는 것은 몇 개인가 — 한 번도 안 불린 에이전트가 있는가

**장치는 있는데 관측이 없다.** 이 저장소가 반복해서 만난 유형이다
(2026-09-08 `docs/audits/2026-09-08-plan-gate-firing.md` — 게이트 절반이 계장 없이
"관측 중" 으로 보였던 건과 같은 모양).

## 어디서 나왔는가

2026-09-08 `experientiallabs/experiential`(LLM 라우팅 게이트웨이, Apache 2.0) 검토 중
발견했다. 그 도구는 **채택하지 않는다** — OpenAI 호환 게이트웨이라 붙이려면
`ANTHROPIC_BASE_URL` + API 키가 필요한데 이 환경은 구독 OAuth 다. 게이트웨이를 거치는
순간 구독이 아니라 종량제로 청구되고, R3(모든 LLM 호출은 구독 CLI 어댑터 경유)와
충돌한다. 프리셋에 넣으면 12곳의 인증·청구 경로를 프리셋이 소유하게 된다.

라우팅 자체는 이미 하고 있고, 트래픽 학습보다 도메인 지식 선언이 낫다.
**가져올 것은 도구가 아니라 "라우팅이 맞는지 재고 있는가" 라는 질문 하나다.**

## 왜 지금 하지 않는가

`R-out`(`docs/exec-plans/active/2026-09-08-tool-output-budget.md`)이 아직 데이터를
모으는 중이다. 2026-09-08 기준 실사용 120건 전부 `pass`, `warn` 1건은 시험으로 만든
발화(15,000 B)이므로 **실사용 발화는 0건**이다. 판단일은 2026-09-29 다.

같은 자리에 검증되지 않은 계장을 하나 더 심으면 둘 다 미검증인 채로 12곳에 퍼진다.
그리고 "계장이 늘어서 느려졌다" 와 "계장이 값을 한다" 를 구분할 수 없게 된다.

## 2026-09-29 에 함께 볼 것

`R-out` 목표 5 를 판단하는 자리에서 **한 번에** 묻는다:

1. `R-out` 은 값을 했는가 — 발화율·바이트 분포·체감 지연(47 ms × Bash 호출 수)
2. 그 결과가 "계장을 늘리는 것이 값을 한다" 를 지지하는가
3. 지지한다면 이 항목을 계획서로 승격, 아니면 backlog 에 그대로 둔다

**2번이 부정이면 이 항목은 진행하지 않는다.** 관측을 늘리는 것 자체가 목적이 되면
`R-out` 이 답하려던 질문을 무의미하게 만든다.

## 승격 시 후보 (아직 설계 아님)

`claude-pretooluse-agent-guard.sh` 가 이미 `tool_input.subagent_type` 을 읽고 있다.
`gate_emit` 을 붙이면 dispatch 대상은 셀 수 있다. 다만 **실제로 어느 모델이 돌았는지는
훅 페이로드에 없을 가능성이 높다** — 착수 전에 페이로드 실측이 먼저다
(`R-out` 때 `tool_response` 스키마를 실측으로 알아낸 것과 같은 순서).

"모델을 셀 수 없다면 dispatch 횟수만으로 무엇을 판단할 수 있는지" 를 먼저 정할 것.
셀 수 있는 것을 세고 답을 못 내는 것이 이 항목이 피하려는 실패다.
