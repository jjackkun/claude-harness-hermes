# redact-name-in-identifier — 이름 마스킹이 식별자 속 이름까지 가린다

> 출처: `completed/2026-09-29-privacy-gate-hardening.md` §7 (2026-09-29 발견).
> 측정: 공장 요약 3문장 · terminal-shipping 1문장에서 `jjackkun_bot`(프로젝트 이름)이 `[REDACTED]_bot` 으로 저장돼 회상 때 프로젝트 이름이 사라진다.

## 문제

`hermes_redact._mask_known_names` 가 마스킹 정답지(`hermes_known_values`)에 든 사람 이름을 문장 어디서든 가린다. 이름이 프로젝트·저장소 이름 같은 식별자의 일부이면(`jjackkun_bot`, `home-jjackkun-project-…`) 식별자까지 훼손된다. 요약을 나중에 읽는 쪽(회상·스킬)은 어느 프로젝트인지 알 수 없게 된다.

## 후보

- 이름이 **낱말 경계**에서만 가려지게 한다: 앞뒤가 영문·숫자·`_`·`-` 이면 식별자의 일부로 보고 가리지 않는다. 손해: `kim_test` 처럼 이름을 밑줄로 이은 별칭은 새 규칙에서 가려지지 않을 수 있다 — 정답지 값 목록으로 따로 확인해야 한다.
- 식별자 목록(프로젝트 폴더 이름 · 저장소 이름)을 예외로 등록한다.

## 착수 조건

게이트가 이제 "지금 규칙으로 다시 가리면 달라지는 문장"을 막으므로(같은 계획 B 단계), 규칙을 바꾸면 모든 소우주의 지식 파일이 다시 가려져야 한다. 착수하면 전파 순서(`hermes-privacy-scrub.py files` → 재판정)를 함께 계획한다.
