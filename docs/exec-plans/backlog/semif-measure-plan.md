# 2026-09-22-semif-measure — SemIf 로컬 판단 실측 (스킬 검색 빈손 폴백)

> 작성일: 2026-09-22
> 목적: Jev API 대신 로컬 SemIf(구 OpenJev)로 스킬 검색 빈손 구간을 메울 수 있는지, 두 컴퓨터에서 **재서** 정한다.
> 상태: **보류 (2026-09-22 사용자 "지금 이야기는 접어").** Step 1 판정 초안까지 진행 — 사용자 검토·설치 전. 재개 시 §7 부터 읽는다.
> 상위 문서: `docs/typesafe-jev/proposal.md` (P0~P3 는 Jev API 기준이었다. 이 계획은 그 P0·P1 을 로컬 모델로 바꾼다)

---

## 1. 동기 (Why)

- Jev 기획은 D2(프롬프트 외부 전송)에서 막혔다. TypeSafe 는 보관 기한이 사실상 없고 삭제 옵션이 없다.
  가명 치환은 탐지 누락 한 건이 영구히 남으므로 기존 판단("고객 데이터가 섞일 수 있는 입력은 보내지 않는다")을 뒤집지 못한다.
- 같은 모양의 판단(상황·질문·선택지 → 선택지별 확률)을 **로컬에서** 하는 SemIf 가 있다는 것을 2026-09-22 확인했다
  (`github.com/TheoLeeCJ/SemIf`, MIT, `news.hada.io/topic?id=33891`). 외부 전송이 0 이면 D2 가 사라진다.
- 그러나 **착수 전 조사에서 빈손 구간 자체가 대부분 스킬이 필요 없는 짧은 동의였다**(§2-bis). 그래서 모델을 깔기 전에
  "메울 가치가 있는 빈손" 이 몇 건인지부터 사람이 판정한다. 이것이 0 에 가까우면 설치 없이 여기서 접는다(기획서 §8 첫째 조건).

## 2. 목표 (What — 검증 가능한 형태)

- [ ] 목표 1 — 빈손 131건(2026-09-22 스냅샷)의 사람 판정표가 있다. 검증: `.harness/semif-eval/labels.jsonl` 131행이 `by: user` 로 확정됨, 행마다 `need`(아래 §5 Step 1 의 세 값 중 하나).
- [ ] 목표 2 — 두 컴퓨터에서 SemIf 의 **첫 로드 시간**과 **판단 1건 시간**(중앙값·p95)이 값으로 있다. 검증: §5 Step 3 결과표가 이 문서 §7 에 채워진다.
- [ ] 목표 3 — Step 1 에서 `skill` 로 판정된 행에 대해 SemIf 가 고른 스킬의 적중 수가 있다. 검증: §7 에 `적중 / 대상` 과 신뢰도 구간별 적중이 있다.
- [ ] 목표 4 — "훅에 붙인다 / 접는다" 를 사용자가 정할 근거가 한 쪽에 모여 있다. 검증: §6 에 사용자 결정 한 줄.

직전 어시스턴트 답까지 넣으면 판단은 가능해지지만 입력이 길어지고, 지금 검색 훅이 쓰지 않는 입력이다(Step 1 에서 함께 판정).

## 5. 단계 (Steps)

### Step 1. 빈손 131건 사람 판정 — 설치 없음 [단순]

- 입력: `extract_empty.py` 가 뽑은 행(2026-09-22 스냅샷 **131행** — 세션 중 로그가 늘었다). 행마다 프롬프트 원문 + 직전 어시스턴트 답 **끝** 300자. 스킬 목록은 판정 시점의 현재 목록(`.claude/skills/` 16 + `.hermes/skills/` 33).
- 판정 값 (`need`):
  - `none` — 스킬이 필요 없는 요청(동의·진행·잡담)
  - `skill` — 목록에 맞는 스킬이 **있었고** 넣었어야 했다 → 어느 스킬인지 `expected` 에 적는다
  - `missing` — 스킬이 필요했지만 목록에 맞는 것이 없었다
- 판정 기준은 시작 전에 이 절에 적어 둔다(한 사람이 판정하는 치우침 대응 — 기획서 §7).
  - `skill` 은 강도를 함께 적는다: `strong` = 요청한 행동을 직접 다루는 스킬(예: "전파해" → `update-all`), `weak` = 관련은 있으나 없어도 답에 지장 없음(예: 모든 커밋 요청 → `verify-git-add-completeness`). `needs_prev` = 프롬프트만으로는 알 수 없고 직전 답이 있어야 판정되는 행.
  - **판정자**: 사용자. 에이전트가 초안 판정을 채우고 사용자가 `skill`·`missing` 행과 무작위 `none` 행을 검토한다(초안을 그대로 확정하지 않는다).
- **멈추는 조건**: `skill`·`strong` 행이 전체 검색 902회의 **1% (9건) 미만**이면 여기서 접는다.
  - 1% 는 기획서 §8 이 "앞단 게이트웨이를 다시 연다" 에 쓴 기준과 같은 값이다. 빈손을 메워 얻는 것이 그 정도도 안 되면 모델을 상주시킬 이유가 없다.
- 산출: `labels.jsonl`, §7 에 `none / skill / missing` 건수.

### Step 2. 설치 — 사용자 [단순]

Step 1 을 통과했을 때만 한다. 이 PC 와 젠북에 각각:

```bash
python3 -m venv ~/semif-venv && . ~/semif-venv/bin/activate
git clone https://github.com/TheoLeeCJ/SemIf ~/SemIf && cd ~/SemIf
# 이 PC (RTX 4070, CUDA): 기본 설치 = PyTorch 백엔드
pip install -e '.[test]'
# 젠북 (외장 GPU 없음): llama.cpp CPU 백엔드
pip install -e '.[test,llamacpp]'
# 젠북 모델 파일: bartowski/Qwen_Qwen3.5-4B-GGUF 의 Qwen_Qwen3.5-4B-Q4_K_M.gguf (3.01 GB)
```

- 검증: 저장소 동봉 예제 `semif-score --mode direct --model Qwen/Qwen3.5-4B --input examples/decisions.jsonl` 가 두 컴퓨터에서 점수를 낸다.
- 이 PC 에서 BF16 4B(약 8 GB)가 VRAM 8 GB 에 올라가지 않으면 GGUF Q4 로 바꾸고 §6 에 적는다.

### Step 3. 속도 — 두 컴퓨터 [단순]

- 입력: Step 1 의 `skill` 행 전부(없으면 `none` 행 무작위 동수로 속도만 잰다). 만든 문장은 쓰지 않는다.
- 잴 것: ① 프로세스 시작~모델 로드 끝(첫 로드) ② 판단 1건(중앙값·p95) ③ 최대 메모리.
- 젠북 CPU 는 `--llama-threads` 를 기본값과 코어 수(16)로 두 번 잰다.
- 판단 기준:
  - 훅에서 매번 모델을 새로 올리는 구조가 가능한가 = ①+② 로 본다.
  - **①+② 가 30초 이상이면 즉시 중단** — 폴백을 끈 이유(`claude -p` 30초 대기)와 같은 값이다.
  - 그 아래는 수치를 보고 사용자가 정한다. 로드만 크고 판단이 빠르면 "상주 서버가 필요하다" 로 적고 다음 계획으로 넘긴다.

### Step 4. 적중 — 이 PC [Plan/Impl/Review]

- 입력: `build_decisions.py` 가 만든 JSONL. `state` = 프롬프트 + 직전 어시스턴트 답 끝 300자, `question` = "이 요청에 맞는 스킬은?", `options` = 스킬 목록(이름 + description 첫 줄) + `없음`.
- 두 조건을 모두 돈다: (가) 프롬프트만 (나) 프롬프트 + 직전 답. 지금 훅은 (가)만 쓴다.
- 잴 것: `skill` 행의 적중 수(최고 확률 선택지 = `expected`), `none` 행에서 `없음` 을 고른 수(오주입 방지), 신뢰도 구간별 적중(보정 — README 도 원본 신뢰도가 보정되지 않았다고 적었다).
- **멈추는 조건**: 신뢰도가 높은 구간일수록 적중이 높다는 관계가 없다 → 기준값 τ 를 정할 수 없다(기획서 P1 과 같은 조건).
- 검증: `score_report.py` 결과를 §7 에 옮긴다. 판정 행의 무작위 5건을 손으로 대조해 스크립트가 맞게 셌는지 본다.

### Step 5. 결정 [단순]

- §7 의 수치로 사용자에게 셋 중 하나를 묻는다: 접는다 / 상주 서버 계획을 쓴다 / 훅 주입 계획을 쓴다(이때 R3 문구를 함께 정한다).
- 결과를 `docs/typesafe-jev/proposal.md` 에 보정 문단으로 남기고, 이 계획을 회고 후 `completed/` 로 옮긴다.

## 6. 의사결정 로그

- 2026-09-22: Jev API 대신 로컬 SemIf 를 잰다 — 근거: 외부 전송 0 이면 D2 가 사라진다. 가명 치환은 탐지 누락이 영구히 남는다.
- 2026-09-22: 설치보다 사람 판정을 먼저 한다 — 근거: 복원한 빈손 129건의 중앙값이 8자이고 상위가 동의 표현이다. 메울 대상이 없으면 설치가 헛수고다.
- 2026-09-22: 측정 단계는 R3 에 걸리지 않는다고 본다 — 근거: 저장소 코드에 호출을 넣지 않고 저장소 밖 CLI 로 잰다. 훅에 붙이기 전에는 사용자가 R3 문구를 정한다.
- 2026-09-22: 직전 답은 앞이 아니라 **끝** 300자를 쓴다 — 근거: 동의("그러자")가 무엇에 대한 것인지는 답 끝의 "다음 행동" 줄에 있다.
- 2026-09-22: 멈추는 조건은 `strong` 행만 센다 — 근거: `weak`(커밋 요청 → git add 스킬) 40건을 넣으면 기준을 쉽게 넘어 판단이 무의미해진다.
- 2026-09-22: 젠북은 CPU 백엔드로만 잰다 — 근거: 외장 GPU 가 없고, Arc 140T 가속은 깨진 출력·충돌 보고가 있어 재도 판단을 흐린다. CPU 결과가 기준을 넘지 못할 때만 SYCL 을 추가로 잰다.
