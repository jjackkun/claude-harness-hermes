# skill-yield-signal — "도움" 판정을 키워드 겹침 대신 더 나은 신호로

> 출처: `docs/exec-plans/completed/2026-09-29-skill-yield-integrity.md` §6·§8 (재판정 실측).
> 측정 도구: `python3 scripts/hermes_yield_replay.py` (읽기 전용, 모델 호출 0).

## 문제

현재 판정(스킬 키워드와 세션 도구 낱말이 2개 이상 겹치면 "도움")은 진짜 짝 0.98 대 가짜 짝 0.91 이다(2026-09-29, 사람 세션 17개·짝 260개).
다른 세션의 활동에 갖다 대도 거의 다 "도움" 이 되므로 도움/소용없음 누계는 정보가 거의 없다.
비율·흔한 낱말 제외·우연 기대치 배수 후보 13종을 재 봤지만 중간 크기 세션(100~999 낱말)에서 진짜율이 가짜율 아래로 무너져 채택하지 못했다 — 스킬 키워드가 중앙값 67개·최대 1,015개로 길기 때문이다.

## 후보

- 스킬 안내를 실제로 따랐는지 보는 신호(안내에 적힌 명령·파일을 세션이 실제로 다뤘는가). 키워드 전체가 아니라 안내의 *행동 항목* 을 대조한다.
- 스킬 키워드를 짧게 다듬기(길이 상한) — 긴 키워드 목록이 판정을 무너뜨리는 원인이라면 색인 쪽에서 고친다.

## 착수 조건

표본이 커질 때까지(사람 세션 40개 이상) 기다렸다가 `hermes_yield_replay.py` 를 다시 돌려 후보 규칙을 함께 잰다. 그 전에는 강등 근거로 "도움=0" 을 신뢰하지 않는다.
