# hermes-pipeline-test 20·21 절이 초 단위 시각에 의존해 간헐 실패한다

> 목적: dream 워터마크 시험의 간헐 실패를 없앤다.

## 관측 (2026-09-09)

`tests/hermes-pipeline-test.sh` 의 두 단언이 드물게 실패한다.

- `--apply 는 junk 스킬 삭제`
- `정정 요약 → 진화 1건 기록`

실패 시 덤프:

```
session_summary: [('dsess1','01:19:03'), ('dsess3','01:19:03'), ('dsess2','01:19:04')]
dream_log(wm):   [(1,1,'01:19:03'), (2,1,'01:19:04')]
```

`dsess3` 이 워터마크(`01:19:04`)보다 이른 초로 기록돼 dream 이 "새 요약 없음" 으로
조용히 끝난다. 같은 시험을 연속 3회 돌리면 3회 모두 통과한다 — 재현이 불안정하다.

## 원인 가설 (미확정)

`session_summary.updated_at` 이 `CURRENT_TIMESTAMP`(초 단위)이고 워터마크 비교가
`>` 라서, 한 초 안에 두 사건이 들어가면 순서가 사라진다. `bump_clock` 이
`time.sleep(1.1)` 로 초를 벌리지만 앞 단계 소요가 흔들리면 경계에 걸린다.

## 왜 지금 고치지 않았나

2026-09-09 헤르메스 스킬 생애주기 작업 중 이 실패를 만나 `hermes-cleanup.py` 의
(e) 단계를 원인으로 **잘못 지목했다**. (e) 를 빼고 1회 통과한 것을 근거로 삼았는데,
(e) 를 되돌린 뒤 3회 연속 통과해 인과가 없음이 드러났다. 한 번의 통과·실패로
원인을 단정한 것이 오판의 형태다.

## 고칠 방향

- 시각을 실시간에 맡기지 말고 시험이 `updated_at` 을 명시적으로 지정한다.
- 또는 워터마크 비교를 초가 아니라 단조 증가 id 로 바꾼다(스키마 변경이라 무겁다).

전자가 시험만 고치면 되므로 먼저 본다.
