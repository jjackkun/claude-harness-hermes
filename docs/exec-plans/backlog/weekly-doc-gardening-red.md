# weekly-doc-gardening-red — 주간 문서 점검 워크플로가 매주 실패한다

> 출처: 2026-09-21 CI 복구 뒤 실행 목록을 보다가 발견. `CI`(push) 는 초록이 됐지만 `weekly-doc-gardening`(schedule) 은 08-30 · 09-06 · 09-13 · 09-20 네 번 연속 failure 다(그 이전은 미확인).

## 확인된 것

- 실패 지점은 편차(drift) 를 계산해 `GITHUB_OUTPUT` 에 `has_drift` 를 쓰는 단계 — `shell: bash -e` 아래에서 `Process completed with exit code 1`.
  편차 탐지 스크립트가 "편차 있음" 을 종료코드 1 로 돌려주면 `-e` 때문에 출력을 쓰기 전에 단계가 죽는 모양으로 보인다(**추정** — 재현 명령 없음).
- 이 워크플로는 실패해도 아무에게도 알리지 않는다. 주간 점검이 네 주 동안 돌지 않은 것과 같다.

## 할 일

- 로컬에서 같은 명령을 돌려 종료코드·출력을 확인하고, 편차 있음(정상 결과)과 실행 실패를 종료코드로 구분한다.
- 세션 시작 훅의 주기 점검(기본 7일)이 같은 일을 하고 있으므로, CI 워크플로가 실제로 필요한지도 같이 판단한다.
