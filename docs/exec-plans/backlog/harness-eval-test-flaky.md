  - 실패한 서버만 다시 돌리자 초록. 두 번 모두 **1번 샤드** · 영수증만 바뀐 커밋 — 우연인지 1번 샤드 묶음 구성 탓인지는 모른다.

- 로컬 단독 107초, 병렬 11에서 141~161초 — 묶음에서 가장 긴 시험 셋 중 하나다.

## 조사 (2026-09-27)

- **호출 0회의 뜻:** 러너는 가짜 `claude` 를 부르기 **전에** 픽스처를 만든다(`_build_template`: 실제 `project-claude.sh` 설치 + 첫 커밋).
  여기서 실패하면 RuntimeError 로 rc 1 · 호출 0 · 표·JSON 빈 값 — CI 증상과 모양이 같다. 설치기를 일부러 깨뜨린
  사본으로 돌리면 정확히 같은 ✗ 들이 나온다(`blocked: 호출 2회` expected=2 actual=0).
- **시간 한도 가설은 약하다:** 한도(`--timeout 30`)는 `claude` 호출에만 걸린다. 한도에 걸렸다면 호출 표식은 남는다(표식은 가짜의 첫 줄).
- **부하 재현 실패:** 픽스처 만들기만 12개 동시 — 22코어 0/12 실패(23.7초), 4코어 고정(`taskset -c 0-3`) 0/12 실패(45초).
- **공유 자원 없음:** 설치 등록은 `HERMES_NO_REGISTER=1` 로 꺼져 있고, CI 거부 분기는 시험이 `unset CI` 로 끈다.
- **진단 추가:** 시험이 러너 stderr 를 호출마다 모아 **실패 때만** 끝에 찍는다. 전에는 r1 은 파일로만, r2(1회차의 violate)는
  `/dev/null` 로 버려 CI 로그에 사유가 없었다. 다음 흔들림 때 CI 로그의 `── 진단:` 아래를 읽으면 된다.
