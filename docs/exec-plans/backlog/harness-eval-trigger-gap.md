# harness-eval 이 불리지 않는다 — 지속 트리거·지표 임계의 부재

> 출처: 2026-09-21 반대 심문(devil-advocate) 시험 1. 반증 조건을 실제로 돌려 **세 건 모두 성립**을 확인했다.
> 기록: `docs/audits/2026-09-21-devil-advocate-trial.md`

## 확인된 사실 (2026-09-21 실측)

| # | 지적 | 확인 방법 | 결과 |
|---|---|---|---|
| 1 | 룰·훅을 바꿔도 harness-eval 을 부르는 장치가 없다 | `grep -rn 'harness-eval' assets/hooks/pre-commit.sh …reminders.sh` | **0줄** — 사람의 기억에만 걸려 있다 |
| 2 | `attempt_rate` 에 임계·경고가 없다 | `grep attempt_rate … \| grep -iE 'thresh\|warn\|임계'` | **0줄** (계산만 2곳) |
| 3 | 야간 금지의 비용 산식이 실제 기본값과 어긋난다 | `scripts/harness-eval.py` `--k` 기본 3 | 6×3×3=54회/일 = 월 1,620회. 문서 가정은 월 600~1,500 |

## 왜 중요한가

이 평가 도구를 만들게 한 사건이 **"규칙이 실제로 작동하는지 잰 적이 없어 두 달 몰랐다"** 였다.
그런데 새 도구의 실행 트리거가 "사람이 기억해서 수동으로" 뿐이면 같은 사각지대를 상속한다.
R3 는 CI 에서 API 키를 못 쓴다는 제약이지, 지속 트리거를 두면 안 된다는 제약이 아니다.

## 고칠 때 후보

- pre-commit 경고 한 줄: `assets/rules/`·`assets/hooks/` 의 룰 문구가 바뀐 커밋에서 "harness-eval 을 돌린 지 N일" 을 알린다(차단 아님).
- `harness_eval_grade.py` 에 `attempt_rate` 상승분 경고 — 직전 실행 대비 올랐으면 표 위에 한 줄.
- 설계 문서의 비용 산식을 실제 기본값(k=3, 시나리오 6, 단계 3)으로 갱신.

## 착수 조건

없음. 1번은 값싸고 효과가 분명하다. 2·3번은 1번과 같은 계획에서 함께.
