# agent-messenger — 터미널쉬핑에 에이전트 메신저를 만들고, 모델은 내 Claude Code 구독으로 부른다

> 작성일: 2026-10-02
> 목적: 사람과 에이전트가 메신저처럼 1:1 · 팀 · 에이전트끼리 대화하는 웹 화면을 터미널쉬핑에 만들고, 일은 내 PC 의 Claude Code 세션이 한다. 이 문서는 착수 전 근거와 결정을 모아 둔 것이며 계획서가 아니다.
> 근거 문서: `docs/audits/2026-10-02-multi-agent-collab-direction.md` (조사·실측 전체 — §4 Grok Bot, §6 논문·Muse, §7 cumora, §8 Gemini, §9 세션 간 메시지, §10 구독 기준)

## 1. 사용자가 정한 것 (2026-10-02)

| 결정 | 내용 |
| --- | --- |
| 어디에 | 메신저 화면은 **terminal-shipping** 에 만든다 (공장 저장소가 아니다) |
| 모델 | 지금의 GPT API 대신 **내 Claude Code 구독**으로 부른다 |
| 누가 쓰나 | **현재 사용자 혼자.** 고객(운송사)이 쓰는 기능이 아니다 — 고객용이 되면 구독 방식은 쓸 수 없고 API 키로 분리해야 한다(`legal-and-compliance` 원문) |
| 방 모양 | 사람 ↔ 에이전트 1:1, 사람 + 에이전트 팀, 사람 없이 에이전트끼리 |
| 문지기 | **느슨한 쪽** — 사람이 켠 방에서는 에이전트끼리 자유롭게 말하게 하고, **연속 응답 횟수와 방별 토큰 예산으로 막는다.** 봉투가 열려 있을 때만 허용하는 엄격한 쪽은 택하지 않았다 |
| 선례 | `jjackkun_bot`(텔레그램 + 본인 구독 `claude -p`)을 약 2년 운영 중. 이는 안정적으로 돈다는 근거이지 약관 허용 확정은 아니다 |

## 2. 실측으로 확인된 사실

| 사실 | 값 · 근거 |
| --- | --- |
| 방 ↔ 방 메시지가 된다 | `ListAgents` + `SendMessage`. 쉬는 받는 방이 메시지로 **스스로 새 턴을 시작**해 답함. 받는 쪽 입력 +1,641, 보내는 쪽 세션 목록 조회 +2,600 (방향 문서 §9) |
| 채널로 쉬는 세션에 외부 메시지를 넣을 수 있다 | 공식 `fakechat` 시험: 도착 → 새 턴 시작 → **채널 `reply` 로 답이 돌아오기까지 약 1.7초.** 메시지당 입력 증가 약 100~250 토큰, `reply` 도구 첫 사용에 1회성 약 +11,000 |
| 지금 `jjackkun_bot` 이 느린 이유 | 받는 쪽 대기 10초 + cron 30초 간격 + `claude -p` 새로 시작이 겹침(코드). 같은 조건으로 재진 않음 |
| 이 PC 의 모든 세션이 서로 보인다 | 한 세션이 다른 프로젝트의 진행 중 세션에도 메시지를 보낼 수 있다 → 에이전트가 보낼 수 있는 대상을 제한해야 한다 |
| `--name` 이 적용되지 않은 경우가 있었다 | 대화 중인 세션 안에서 시험 세션을 띄웠을 때. 원인 미확인 |

## 3. 터미널쉬핑에서 확인된 접점 (읽기 전용 조사, 일부 미확인 표시)

- **모델 호출은 한 곳**: `backend/app/features/credential/brain/call.py` 의 `말을_건다(쓸것, *, system, 말들) -> 답`. 반환 `답(ok, text, reason, provider_said, input_tokens, output_tokens, seconds)`, 예외 없이 실패도 `답`으로. 지금은 `httpx` 로 공급사 API 를 부른다.
- **공급사가 닫혀 있다**: `credential/platform_brain_model.py` 의 `PROVIDERS=("OpenAI","Anthropic")` 과 DB CHECK 제약, `secret_ciphertext` NOT NULL. 새 공급사(`local-claude-cli`)를 꽂으려면 이 셋과 `check.py` 의 연결 확인 분기를 함께 바꿔야 한다(마이그레이션의 CHECK 와 `check.py` 내용은 미확인).
- **방 모델**: `Room` · `RoomMember`(member_type, user_id/agent_id) · `RoomMessage`(author_type, payload JSONB, idem_key). 모두 회사 단위 RLS. 발송은 `POST /rooms/{id}/messages`.
- **`@` 가 있어야 답한다**: `room_agent_reply._불린_직원` 이 `@` 가 없으면 `None`. 1:1 방에서 `@` 없이 답하게 하려면 호출 판정(`mention.py` 순수 함수)을 손봐야 한다.
- **답은 동기식**: HTTP 요청 안에서 모델 응답을 기다린다. 대기 상한 60초(`call.py`)가 CLI 응답에 빠듯할 수 있다.
- **갱신은 5초 폴링**: `GET /rooms/{id}/updates?since=` 를 `live_poll.svelte.js` 가 5초마다 호출. WebSocket/SSE 는 못 찾았으나 `EventSource` 를 grep 하지는 않았다(미확인).
- **BYOA 갈래가 설계서에 이미 있다**: `docs/design-docs/agent-connection.md` 표에 "그 사람의 기계 CLI, 그 사람의 구독" 갈래가 있고 구현은 `PROVIDERS` 에 없다.
- **방어 장치가 걸려 있다**: `chat-ui.md` §8-3 은 모델 등급(gpt-5-mini 고정)에 "모르면 모른다고 하는가" 방어가 걸려 있다고 한다. 모델을 바꾸면 무너질 수 있다 — 재검증 필요.
- **에이전트 개념**: `conversation/agent_model.py` 의 `Agent` 에 `name`·`persona`·`soul`(아직 화면에 안 열림)·`profile` 이 있어 헤르메스 명부 에이전트의 이름·SOUL 과 대응 가능. 스킬 매핑은 별도 설계가 필요.
- **배포**: PM2 로 `uvicorn` 을 `127.0.0.1` 에서 실행, 설계서는 "집 운영 PC(우분투)". PM2 프로세스의 사용자와 `claude` 로그인 계정이 같은지는 미확인.

## 4. 목표 후보 (검증 가능한 형태로 다듬을 것)

- [ ] 1단계 — **사람 ↔ 에이전트 1:1 방이 내 구독으로 답한다.** `local-claude-cli` 공급사를 `말을_건다` 한 곳에 추가. 검증: 가짜 `claude` 로 `답` 필드(text·토큰·seconds)가 채워지는 단위 시험 + 실제 `claude` 1회 왕복.
- [ ] 2단계 — **상주 세션 + 채널로 지연을 줄인다.** 방마다 `claude --agent <호출명> --name <방>` 상주 세션을 두고 웹 서버가 채널(또는 세션 간 메시지)로 넣는다. 검증: `jjackkun_bot` 방식(매번 `claude -p`)과 같은 질문의 왕복 시간·토큰 비교.
- [ ] 3단계 — **팀 방.** 사람 한 마디에 지목된 에이전트만 답한다(`@이름`). 검증: 지목하지 않은 에이전트는 모델을 부르지 않는다.
- [ ] 4단계 — **에이전트끼리 대화 + 느슨한 문지기.** 연속 응답 횟수 상한과 방별 토큰 예산을 코드로(모델 없이) 건다. 검증: 상한에 닿으면 멈추고 방에 이유가 남는다, 예산 소진 시 더는 안 부른다.
- [ ] 5단계 — 모든 호출을 한 장부에 적는다(cumora 의 `llm_calls` 처럼). 기존 `usage_service` 와 합친다.

## 5. 비목표

- 고객(운송사)용 에이전트 대화 — 구독으로 대신 호출하는 것은 약관상 불가, 필요하면 API 키 공급사를 따로.
- 작은 모델 문지기 — 규칙으로 못 가르는 경우가 실제로 쌓인 뒤에 추가한다.
- 에이전트 간 공유 작업 기록 설계 — 이 문서 밖(방향 문서 §2 의 "공유 작업 기록 + 봉투 릴레이"), 먼저 1~3단계가 돈 뒤.

## 6. 위험 · 운영 주의 (실측·문서에서 나온 것)

- **권한 질문이 세션을 멈춘다**: 채널 `reply` 도구 첫 사용에 승인 질문이 떠 세션이 대기했다. 무인 운영에는 허용 규칙이 필요하다. `--dangerously-skip-permissions` 는 계정·토큰이 뚫리면 PC 가 뚫린다는 뜻이다.
- **포트 충돌·잔존 프로세스**: 세션을 바로 다시 띄우면 채널 MCP 서버가 포트 충돌로 실패(✘)했고(`/mcp` 재연결로 복구), 세션을 닫아도 `bun server.ts` 가 남았다. 상주 운영에는 기동·정리 절차가 필요하다.
- **채널은 연구 미리보기**: 플래그와 규약이 바뀔 수 있다(`--channels` 는 `--help` 에 안 나온다). 세션이 열려 있어야만 받는다.
- **상주 세션 비용**: 대화가 쌓이면 입력이 커지고 자동 압축이 일어난다. 재지 못했다.
- **답이 채널로 가려면** 모델이 `reply` 도구를 써야 한다. 첫 메시지에서는 터미널에만 출력했다 — 지시문에 명시해야 한다.
- **약관 해석의 불확실성**: 무인으로 오래 도는 개인 사용이 "평범한 개인 사용" 한도 안인지는 문서에 숫자가 없다. 집행은 사전 통지 없이 가능하다고 적혀 있다.

## 7. 아직 모르는 것 (착수 때 가장 먼저 잴 것)

1. `--agent` 에이전트 방에 `--channels` 를 붙였을 때 동작.
2. 하네스·헤르메스 주입이 있는 환경에서 채널·세션 간 메시지의 토큰(이번 시험은 주입 없는 환경, 첫 입력 46.6K).
3. `claude -p --output-format json` 이 토큰 사용량을 주는지 — 이 저장소의 소환 가드가 세션 안에서 막아 못 잼(별도 터미널이나 러너로).
4. 공식 텔레그램 플러그인 실물 — 봇 토큰이 필요해 사용자가 BotFather 로 만들어야 한다.
5. 상주 세션이 하루 동안 쌓는 입력량과 압축 빈도.
6. PM2 서버와 `claude` 로그인이 같은 계정인지.
