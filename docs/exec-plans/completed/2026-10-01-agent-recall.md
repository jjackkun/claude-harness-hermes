# 2026-10-01-agent-recall — 에이전트가 다른 방에서 한 일을 스스로 기억에서 꺼내 온다

> 작성일: 2026-10-01
> 목적: 방(세션) A 에서 나눈 대화를 방 C 에서 물으면 에이전트가 모르는 문제를, 에이전트가 쓸 수 있는 **기억 검색**으로 푼다.
> 앞선 계획: `docs/exec-plans/completed/2026-09-28-agent-conversation-memory.md`(C-29, 대화 요약에 에이전트 키) · `docs/exec-plans/completed/2026-09-28-hermes-chat.md`(방·기억 층).

## 1. 동기 (Why)

사용자 시나리오(2026-10-01): 방이 세 곳(A·B·C)이고 같은 에이전트(백로그 관리자)가 각 방에서 대화하고 있다. A 에서 한 대화를 B·C 는 모른다. 그런데 C 에서 사용자가 A 의 일을 물으면 에이전트가 모를 수 있다. **모르면 기억에서 꺼내 와야 한다.**

지금 구조(2026-10-01 코드 확인):
- 세션 시작 때 에이전트 기억(`MEMORY.md`)과 나눈 대화 요약이 **최근 것부터 각 4,096B 까지** 주입된다. 넘는 옛것은 지워지지 않지만 주입에서 밀린다.
- 대화 요약은 `Stop` 훅이 **매 응답이 끝날 때마다** 새 대화만 갱신한다(`hermes-summarize.py`) — 그래서 A 방이 열려 있어도 A 의 마지막 응답까지는 이미 요약에 들어 있다.
- **꺼내 볼 길이 없다.** `/hermes-recall` 은 사용자가 치는 명령이고, 에이전트 대화 요약은 **일부러 공통 회상에서 뺐다**(`agent_id IS NULL` 만 검색 — `hermes-recall.py`). `hermes-search.py` 는 스킬 검색이다.

> 여기까지 다시 읽었다: 기억은 **"바탕은 항상, 나머지는 필요할 때"** 로 설계됐는데 뒤의 반쪽(필요할 때)이 없다. 4KB 상한을 올리는 것은 답이 아니다 — 모든 세션의 시작 비용이 늘고 R-out 이 보여 준 컨텍스트 낭비가 커진다. 이 계획은 **찾는 길**을 만든다.

## 2. 목표 (What — 검증 가능한 형태)

- [x] 목표 1 — **다른 방의 기억을 찾는다(사용자 시나리오 그대로).** 같은 에이전트의 방 A·B·C 요약이 있고 A 에만 있는 낱말로 찾으면 A 의 요약이 나온다. 검증: `bash tests/hermes-agent-recall-test.sh` — 픽스처 3방(+ `@` 호출 1건) 중 A 낱말 → A 블록, C 낱말 → C 블록, 둘 다 있는 낱말 → 점수·최근 순.
- [x] 목표 2 — **못 찾으면 못 찾았다고 말한다(지어내지 않게).** 맞는 것이 없으면 "찾지 못했습니다" 와 **어디를 찾았는지**(요약 N개 · 기억 M개)를 한 줄로 낸다. 검증: `bash tests/hermes-agent-recall-test.sh` — 없는 낱말 → 그 문장·개수. 빈 질문 → 사용법 한 줄.
- [x] 목표 3 — **범위가 새지 않는다.** 찾는 것은 **물어본 그 에이전트 것만** · **부른 사람 본인과 나눈 것만**(주입과 같은 규칙, 복원된 행은 `person` 칸이 비어도 이 컴퓨터 것으로) · 공통 요약(`agent_id` 없음) 제외 · 철회된 기억 제외. 검증: 시험 — 다른 에이전트·다른 사람(`person`)·공통 요약·철회 기억에만 있는 낱말은 0건 · `person` 이 비어 있는 복원 행은 잡힌다.
- [x] 목표 4 — **한 번의 호출이 컨텍스트를 태우지 않는다.** 출력 ≤ **4,096B** — 세션 주입 구획과 같은 값(새 숫자를 만들지 않는다)이고 R-out 임계 8,192B 의 절반이라 한 번 불러도 경고가 안 뜬다. **개수로 자르지 않고 바이트로** 채워 가며, 넘치면 마지막 줄에 "… 외 N건 — 낱말을 좁혀 다시 찾는다". 검증: `bash tests/hermes-agent-recall-test.sh` — 큰 요약 20개 → 출력 바이트 ≤ 4,096 · 마지막 줄에 "외 N건" · 요약 2,000개 + 기억 2,000개 DB 에서 1초 안(측정값을 §7 에 적는다).
- [x] 목표 5 — **낱말 맞춤이 한국어 조사에 견딘다.** 질문 낱말(한글 3자 이상)은 그대로, 끝 1글자를 뗀 것(를·은·는·이·가·의·도·에·로·와·과), 끝 2글자를 뗀 것(에서·으로·에게·까지·부터·처럼)으로 본문과 맞춘다 — 뗀 뒤 2자 이상일 때만. 맞는 낱말 수가 많은 것이 먼저, 동점이면 최근. 모델 호출 없음(R3). 검증: `bash tests/hermes-agent-recall-test.sh` — "백로그를"·"백로그에서"·"백로그" 가 같은 요약을 찾는다 · 낱말 둘 중 하나만 맞는 것과 둘 다 맞는 것의 순서 · 2자 낱말("방")은 조사 떼기를 안 한다.
- [x] 목표 6 — **에이전트가 이 길을 안다.** 세션 시작 주입 본문(방·`@` 호출·소환 모두 같은 렌더러 `render_soul`)에 안내 한 줄: 옛 대화·기억이 필요하면 `python3 scripts/hermes-agent.py recall <호출명> "<낱말>"`, 모르는 것은 지어내지 말고 먼저 찾는다. 호출명이 없는 에이전트(slug 는 선택)는 **`agent_id`** 를 박는다 — `recall` 은 호출명·이름·id 셋 다 받는다. 호출명이 박힌 최종 글자 기준 ≤ 300B. 검증: `bash tests/hermes-soul-inject-test.sh` 에 안내 줄 단언(slug 있음 · 없음) · 기존 단언 불변.
- [x] 목표 7 — **실패가 세션을 흔들지 않고, 실패와 "없음" 을 구분한다.** 저장소 파일이 없으면 "기억 저장소가 없습니다" 한 줄 rc 0 · **DB 를 읽지 못하면(잠김 등) "읽지 못했습니다(사유)" rc 1** — 거짓으로 "찾지 못했습니다" 라고 하지 않는다 · 모르는 에이전트는 거부 rc 2 · 깨진 `slots_json` 행은 건너뛴다. 검증: 시험 — DB 없음 · 잠긴 DB(쓰기 트랜잭션을 열어 둔 채) · 이름 틀림 · 깨진 행.
- [x] 목표 8 — **설치된 곳에서 돈다.** 새 모듈이 설치본에 복사된다(`hermes.conf` 복사 배열). 대상은 공장 + 레지스트리의 소우주 8곳(`zeroday-frontend` `novel-ab` `novel-bc` `rim-kanban` `jjackkun_bot` `teulankkae` `upbit-ai-trading` `kis-trading`, terminal-shipping 은 사용자 몫). 검증: 설치 뒤 각 곳의 **실제 설치된 `scripts/hermes-agent.py`** 를 일회용 픽스처 프로젝트(`--project <임시폴더>`, 합성 요약·기억)에 돌려 결과가 나온다 — 그 소우주의 실데이터는 건드리지 않고 설치된 코드만 검증한다.

- [x] 목표 9 — **다른 컴퓨터에서 들여온 요약도 찾는다.** `hermes-knowledge-files.py import` 로 파일에서 복원된 행도 같은 규칙(에이전트·사람)으로 검색에 잡힌다. 검증: 시험 — 픽스처 파일을 `import` 한 뒤 `recall` 이 그 요약을 낸다.

## 6. 의사결정 로그

- 2026-10-01: **상한을 올리지 않고 "찾는 길" 을 만든다** — 근거: 상한을 올리면 모든 세션 시작 비용이 늘고, R-out 실측이 보여 준 컨텍스트 낭비가 커진다. 필요한 것은 "항상 들고 있는 최근 것 + 필요할 때 찾는 나머지". 손해: 에이전트가 찾아야 한다는 것을 알아야 한다 → 주입에 안내 한 줄(목표 6).
- 2026-10-01: **하위 명령 `hermes-agent.py recall <호출명> "<낱말>"`** — 근거: 방 주인(`--agent`)은 환경변수 `HERMES_AGENT_ID` 가 없어 "나" 를 스스로 알 수 없다. 주입 안내가 **호출명을 박아 주면** 에이전트가 그대로 복사해 쓴다. 손해: 안내 줄에 호출명이 들어 렌더러가 slug 를 알아야 한다(이미 안다).
- 2026-10-01: **조회는 주입과 같은 규칙 재사용 — `_rows` 를 공개 함수 `agent_summary_rows(project, agent_id, who)` 로 승격(읽기 실패는 예외로 알림), 기억은 `current_memories`** — 근거: "이 에이전트가 이 사람과 나눈 대화" 의 정의가 두 곳에 있으면 갈린다. 주입은 읽기 실패를 삼켜 빈 결과로 돌려주는데(세션이 서야 하므로 옳다) 검색에서 그러면 **거짓 "찾지 못했습니다"** 가 된다 — 그래서 검색용은 실패를 구분한다(리뷰 지적). 손해: 주입 쪽은 기존대로 삼키는 얇은 래퍼로 남는다. `current_memories` 는 이벤트 전량을 읽는다 — 이 저장소 규모에서는 목표 4 의 성능 시험이 지킨다.

## 8. 회고

- 잘된 것: **사용자가 시나리오(방 A·B·C)로 요구를 말해 준 덕에** "찾는 길" 이라는 빠진 반쪽이 분명해졌다. 요구 전에 코드를 읽어 DB 와 파일 두 곳 저장·요약이 매 응답 갱신된다는 사실을 확인했고, 사용자의 "예전엔 DB 인데 이제는 다른 곳" 지적으로 "원본은 파일" 이라는 표현을 바로잡았다. 시험을 먼저 쓰고(RED) 변이 검사 4종으로 시험의 힘을 확인했으며, **리뷰 전에 스스로 정밀도 결함(라벨이 검색 본문에 섞임)을 잡았다.** 계획·구현 리뷰 두 번이 각각 실결함을 찾았다.
