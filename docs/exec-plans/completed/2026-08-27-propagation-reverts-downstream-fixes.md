# 2026-08-27-propagation-reverts-downstream-fixes — 전파가 하류의 수정을 되돌린다

> 작성일: 2026-08-27
> 목적: 전파(`update-all.sh`)가 하류의 것을 덮을 때 **무엇을 덮었는지 말하게** 한다.
> 발견: `terminal-shipping` 에 전파한 직후 (2026-08-27)

---

## 1. 동기 (Why)

`terminal-shipping` 에 전파했더니 **세 가지가 되돌아갔다.** 셋 다 하류가
이유를 대고 고쳐 둔 것이었고, 되돌아간 것을 **아무도 알려 주지 않았다.**

### 1-0. 먼저 — 무엇이 어디서 덮는가

⚠️ **`update-all.sh` 만 봐서는 원인을 못 찾는다.** 실제로 덮는 곳은 두 층 아래다.

```
update-all.sh                     .installed-projects 를 훑는다
  └ project-claude.sh             프로젝트 하나
      ├ install_harness_hooks     assets/hooks/*  →  <프로젝트>/scripts/hooks/
      │                           ★ 조건 없는 cp. 무엇을 덮었는지 안 말한다
      └ install_harness_pre_commit assets/hooks/pre-commit.sh → .git/hooks/pre-commit
                                  ★ 통째로 갈아친다. 마커도 백업도 없다
```

★ **`update-all.sh` 를 쓰는 것은 옳다.** 그것이 정상 경로다 — 이 계획은
**그 경로를 바꾸자는 것이 아니라, 그 경로가 무엇을 덮었는지 말하게** 하자는 것이다.

⚫ 두 자리의 성격이 다르다.

```
scripts/hooks/*        하류가 그 파일을 고쳤을 때만 잃는다
.git/hooks/pre-commit  하류가 단계를 얹었으면 언제나 잃는다
```

### 1-1. 🔴 `plan_state.py` 의 `[~]` 지원이 사라졌다

계획 계수기가 체크박스를 셀 때 `[~]`(진행 중)를 **목록에 넣지 않으면 그 항목을
아예 안 센다.** 남은 것이 전부 `[x]` 로 보여 **계수기가 "완료" 라고 말한다.**

하류에서 실제로 겪은 사고다 — 사람이 할 일 하나가 `[~]` 로 남아 있는 계획을
계수기가 완료로 판정해 **`completed/` 로 옮기라고 막았다.**

```
상류        CHECKBOX_RE = r"^\s*-\s*\[( |x|X)\]\s"
하류(수정)  CHECKBOX_RE = r"^\s*-\s*\[( |x|X|~)\]\s"  + DONE_MARKS = ("x","X")
```

⚠️ **전파가 그 수정과 근거 주석·감사 문서 링크까지 통째로 지웠다.**

★ **세는 것을 빠뜨리는 계수기는 틀린 답을 자신 있게 낸다.** 안 세면 0 이 되고,
0 은 "없다" 로 읽힌다 — 침묵보다 나쁜 조용한 오답이다.

⚫ 하류에서 되살렸지만 **다음 전파가 또 되돌린다.** 상류를 고쳐야 끝난다.

### 1-2. ⚫ 생성 블록과 prettier 가 빈 줄 하나를 두고 다툰다

`core-beliefs.md` 의 `HARNESS-RULES` 블록은 **목록으로 끝나고 바로 END 마커**가
온다. 마크다운에서 목록 뒤에 HTML 주석이 붙으면 **prettier 가 빈 줄을 넣는다.**

```
assets/docs-templates/.../core-beliefs.md.tmpl:50   - R-retro {#r-retro} …
assets/docs-templates/.../core-beliefs.md.tmpl:51   <!--===HARNESS-RULES:END===-->
                                                    ↑ 사이에 빈 줄이 없다
```

```
전파       빈 줄을 지운다
prettier   다시 넣는다
결과       전파 직후 첫 커밋이 R-fmt 로 막힌다
```

⚠️ **해는 없지만 원인을 모르면 엉뚱한 데를 찾는다.** 자기가 안 건드린 파일이
포맷 위반으로 뜨기 때문이다.

### 1-3. 🔴 `pre-commit` 을 얹어 쓰는 하류는 매번 조용히 잃는다

`install_harness_pre_commit` 은 `.git/hooks/pre-commit` 을 **통째로 갈아친다.**
그래서 **하네스가 주는 것 말고 더 얹은 프로젝트는 전파할 때마다 그것을 잃는다.**

`terminal-shipping` 이 그렇다.

```
하네스가 까는 것    4단 검사
그 프로젝트가 쓰는 것 시크릿 스캔 + 4단 검사 + 문서 링크 검사
```

⚠️ **4단 검사가 빠지면 티가 난다 — 커밋이 안 막힌다.** 그런데 **시크릿 스캔은
빠져도 아무 일도 안 일어난다.** 평소와 똑같이 커밋되고, 다른 점은
**자격증명이 그냥 들어간다**는 것뿐이다. git 히스토리는 되돌릴 수 없다.

⚫ 그 프로젝트는 되얹는 스크립트(`scripts/install-git-hooks.sh`)를 갖고 있고
그것을 전파 뒤에 부르면 된다. **다만 그것은 사람이 기억해야 하는 절차다.**
⚠️ **기억에 기대는 방어는 방어가 아니다** — 하물며 빠져도 안 보이는 것이라면.

★ **여기서도 답은 같다: 덮었으면 말한다.** 갈아쳤다는 한 줄과
_"얹은 단계가 있었다면 다시 얹으라"_ 는 한 줄이면 사람이 기억할 필요가 없다.

⚫ **하네스가 하류의 단계를 지켜 주려 애쓸 필요는 없다.** 무엇을 얹었는지는
하류만 안다. 하네스는 **덮었다는 사실만** 말하면 된다.

### 1-4. ★ 세 자리가 같은 모양이다

**상류가 하류를 덮어쓰는데, 무엇을 덮었는지 말하지 않는다.**

이 저장소는 같은 함정을 이미 안다 — 시크릿 검사기 사본 둘이 갈라져
_"한쪽만 고쳐 놓고 고쳤다고 믿은"_ 일, 계획 계수기 사본이 갈라져 게이트가
**옛 판정을 계속 본** 일. 그때 답은 _"사본을 만들지 않는다"_ 였다.
**여기서는 사본을 안 만들 수 없다** — 전파가 곧 복사다.
그러면 남는 답은 **덮은 것을 말하는 것**이다.

## 5. 단계 (Steps)

### Step 1. `[~]` 를 센다 [Impl]

- `CHECKBOX_RE` 에 `~` 를 넣고, **완료로 세는 표시를 따로 둔다**(`DONE_MARKS`)
  ⚠️ `~` 를 정규식에만 넣고 완료 판정을 `!= " "` 로 두면 **`[~]` 가 완료로
  세어진다** — 지금보다 나쁘다
- 세는 곳이 셋이다(`count_boxes`·`pending_items`·`_goal_items`). **한 곳만
  고치면 목록과 개수가 어긋난다**
- 근거 주석을 함께 옮긴다 — 왜 `~` 가 있는지 모르면 다음 사람이 또 지운다
- 검증: **G1**

### Step 2. 사본 갈라짐을 기계가 막게 한다 [Impl]

- `assets/hooks/` 와 `scripts/hooks/` 의 **동명 파일 전부**를 대조하는
  `tests/hook-copy-sync-test.sh` 를 만들고 `tests/run-all.sh` 에 등록한다
- 🔴 **링크로 묶지 않는다.** `lib/harness_installers.sh:4` 가 이미 반대로 결정했다 —
  _"모두 *복사* 사용 (심볼릭 X, 이유: 사용자 편집 + WSL 호환)"_.
  그 결정을 뒤집을 근거가 이 계획에 없다
- ⚫ **`plan_state.py` 만 검사하지 않는다.** 갈라지는 것은 이 파일의 성질이 아니라
  *복사로 배포한다*는 구조의 성질이다. 동명 파일을 전부 본다
- 검증: **G2**

### Step 3. 빈 줄 하나 + 그것을 지키는 게이트 [Impl]

- `.tmpl` 의 END 마커 앞에 빈 줄을 넣는다
- ⚠️ **블록을 뽑는 `awk` 가 BEGIN~END 를 그대로 나르므로** 원본만 고치면 된다
  (`harness_sync_marker_block` 의 `$0==b{f=1} f{print} $0==e{f=0}` — 확인함)
- 🔴 **빈 줄만 넣고 끝내면 세 번째가 온다.** 이것은 새 발견이 아니라 `f1afb8c`
  ("템플릿이 설치 프로젝트의 prettier 를 위반하지 않게 한다", 2026-08-25) 가
  `*...*`→`_..._` 를 잡으면서 **놓친 잔여분**이다. 같은 부류가 두 번 났다
- 그래서 `tests/update-all-roundtrip-test.sh` §5 에 **배치된 `core-beliefs.md` 를
  `prettier --check` 로 보는 단언**을 더한다. 그것이 §7 이 말하는 _"세 번째가 없게"_ 다
  ⚫ prettier 가 없는 환경에서는 그 단언만 SKIP 한다 — 러너 전체를 죽이지 않는다
- 검증: **G3**

### Step 4. 하류가 고친 훅만 골라 말한다 [Impl] ★ 설계가 바뀐 자리

- 🔴 **`cmp src dest` 는 쓰지 않는다.** 그것은 두 가지 다른 사실을 한 값으로 뭉갠다:

  ```
  dest != src  →  ① 하류가 고쳤다      ← 말해야 하는 것
               →  ② 상류가 훅을 개정했다 ← 말하면 안 되는 것 (평범한 갱신)
  ```

  ②가 압도적으로 흔하다. 훅 하나만 개정해도 **다음 전파에서 12 개 프로젝트 전부가**
  그 파일을 "덮었다" 목록에 띄운다 — G6 가 막으려던 바로 그것이다
- ⚫ **이 저장소는 이미 이 문제를 풀었다.** `harness_template_sha` 의 주석:
  _"`cmp -s` 와 달리 템플릿이 개정돼도 판정이 유지된다."_ 같은 판정을 재사용한다
- 판정 규칙 — 매니페스트(`<프로젝트>/.claude/harness-hooks.lock`)에 상류가 **마지막에 깐**
  본문의 sha256 을 이름별로 적어 둔다:

  ```
  dest 해시 != 매니페스트 기록  →  하류가 고쳤다      →  목록에 담는다
  dest 해시 == 매니페스트 기록  →  상류만 바뀐 것이다  →  조용히 덮는다
  기록이 없다(첫 도입)          →  판정 불가          →  조용히 기록만 한다
  ```

  ⚠️ **셋째 줄이 의도적인 손실이다.** 첫 도입 때 하류 수정 한 번을 못 잡는다.
  대신 "모르면 경고" 를 택하면 첫 전파에서 12 개 프로젝트가 전부 울어 G6 가 깨진다.
  ⚫ 이 저장소가 `HARNESS_LEGACY_TEMPLATE_SHAS` 로 겪은 것과 같은 갈림길이고,
  거기서는 목록을 유지하는 쪽을 골랐다. 훅은 파일이 25 개라 그 방식이 안 맞는다
- 덮은 **뒤** 매니페스트를 새 sha 로 갱신한다 — 안 그러면 다음 전파에서 같은 파일이 또 뜬다
- ⚠️ **막지 않는다.** 덮는 것이 전파의 일이다 — 다만 **조용히 덮지 않는다**
- ⚫ 문구에 무엇을 담을지가 값이다: _"덮었다"_ 만으로는 부족하고
  **어느 파일인지**와 **되돌리려면 무엇을 보라**(하류의 `git diff`)까지 말한다
- 검증: **G4 · G6**

### Step 5. `pre-commit` 을 갈아쳤다고 말한다 [Impl] ★ 이 계획의 값이 여기서 나온다

- `install_harness_pre_commit` 도 갈아치기 전에 **다른지 본다**
- ⚫ **구현하며 바뀐 것 — 여기서도 매니페스트를 쓴다.** 처음에는 `cmp` 로 충분하다고
  적었으나, 그러면 **하네스가 `pre-commit.sh` 를 개정할 때마다** 아무것도 안 얹은
  프로젝트까지 _"다시 얹으십시오"_ 를 듣는다. G4 에서 버린 것과 같은 잡음이다.
  매니페스트로 보면 얹은 프로젝트만 걸리고, **얹은 것을 되얹는 한 전파마다 계속 걸린다** —
  원하던 동작이 그대로 나온다. 판정 장치는 하나로 족하다
- ⚠️ **여기서는 "다르다" 의 뜻이 다르다.** 훅 파일은 *하류가 고쳤다*는 뜻이지만,
  `pre-commit` 은 **하류가 단계를 얹었다**는 뜻일 때가 많다
- 그래서 문구가 하나 더 붙는다 — _"얹은 단계가 있었다면 다시 얹으십시오"_
  ⚫ 무엇을 어떻게 얹는지는 **하류가 안다.** 상류는 그것을 짐작하지 않는다
- 🔴 **잃는 것이 조용한 쪽일 수 있다.** 실제로 `terminal-shipping` 은 시크릿
  스캔을 얹어 두었는데, 그것이 빠지면 **아무 일도 안 일어난 것처럼 보인다**

구현을 끝낸 뒤 스스로 검토해 **다섯 자리를 더 닫았다.** 셋은 이번에 넣은 코드의

  문자열 정확 비교로 바꿨다. 지금 이름들로는 충돌이 안 나지만 **이름을 늘리는
  사람이 그 사실을 알 방법이 없다**는 것이 고친 이유다.
- 🟠 **`.git/hooks/` 부수 파일 7 개가 여전히 조용히 덮이고 있었다** —
  `check-secrets.py` · `plan_state.py` · `complexity.py` · `coverage_probe.py` ·
  `depcheck.py` · `check-component-structure.mjs` · `hermes_secret_values.py`.
  ⚫ **pre-commit 바로 아래 같은 함수 안이었다.** §1-3 이 "빠져도 티가 안 나는 것"
  으로 지목한 시크릿 스캔이 정확히 이 목록에 있다.
  ⚠️ 여기는 pre-commit 보다 **더 조용하다** — `.git/hooks/` 는 추적되지 않아
  `git diff` 로도 안 보인다. 그래서 보고 문구에 그 사실을 한 줄 넣었다.
  ⚫ 일곱 벌로 흩어져 있던 블록을 한 루프로 모았다. 그중 둘은 복사 실패를 말하지도
  않고 있었다 — **같은 일을 하는 코드가 갈라지면 한쪽만 고쳐진다**(§1-4 와 같은 모양).
- 🟡 **은퇴한 훅의 기록이 매니페스트에 영원히 남았다** — 파일이 사라진 경로의 기록을
  버리게 했다. 판정에 해롭지는 않았지만 **읽을 수 없이 자란 파일은 고쳐지지도 않는다.**
- 🟡 **CRLF 매니페스트에서 판정이 조용히 죽었다** — `\r` 이 붙으면 비교가 빗나가
  "기록 없음" 으로 떨어진다. 안전한 쪽으로 무너지지만 **조용히** 무너진다.
  이 저장소는 CRLF `.gitignore` 로 이미 한 번 당했다.
- ⚫ **키를 이름에서 프로젝트 상대경로로 바꿨다.** `plan_state.py` 는 실제로 두 자리에
  깔린다(`scripts/hooks/` 와 `.git/hooks/`). 이름을 키로 두면 둘이 충돌한다.
  경로로 두니 충돌이 사라지고, 보고 문구가 곧 경로가 되고, 기록 정리가
  "그 경로에 파일이 있는가" 한 줄이 됐다 — **세 문제가 한 결정으로 풀렸다.**
