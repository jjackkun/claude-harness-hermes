## 1. 동기 (Why)

R-doc 은 README·CLAUDE.md·`presets/workflow/harness.conf` 의 수치 블록(훅·게이트·스킬·에이전트·테스트 개수)이 소스와 같은지 커밋 때 검사해, 다르면 **막는다**. 수치 자체는 기계가 센다(`assets/hooks/doc_counts.py`). 그런데 파일에 쓰는 일은 사람이 `bash scripts/sync-doc-counts.sh` 를 직접 돌려야 한다.

- 시험·스크립트를 하나 추가할 때마다 커밋이 막히고 명령을 한 번 더 돌린다. 2026-09-29 하루 동안 이 세션에서만 커밋 3건 앞에서 같은 명령을 돌렸다.
- 막는 이유(틀린 숫자가 12개 소우주로 퍼진 일, 2026-09-08)는 그대로 유효하다. 고치는 일까지 사람에게 시킬 이유는 없다 — 생성물이므로 기계가 갱신해도 정보가 사라지지 않는다.

> 여기까지 다시 읽었다: 없앨 것은 "막는 것"이 아니라 "사람이 명령을 대신 돌리는 일"이다. 틀린 숫자가 올라갈 수 없다는 보장은 유지한다.

## 2. 목표 (What — 검증 가능한 형태)

- [x] 목표 1 — **낡은 수치 블록을 커밋 검사가 갱신하고 스테이징한다.** 수치가 낡고 대상 파일에 스테이징 안 된 변경이 없으면 `sync-doc-counts.sh --stage` 가 그 파일의 마커 블록만 다시 쓰고 `git add` 한다. 커밋은 막히지 않고 무엇을 갱신했는지 한 줄로 알린다. 검증: `bash tests/doc-counts-autofix-test.sh` §1(낡음 → 갱신·스테이징·마커 밖 내용 보존).
- [x] 목표 2 — **사용자의 스테이징 안 된 변경을 함께 올리지 않는다.** 대상 파일에 스테이징 안 된 변경이 있으면 그 파일은 건드리지 않고 지금처럼 차단하며 안내한다. 검증: 같은 시험 §2(변경 있음 → 파일 무변경·미스테이징·비영 종료).
- [x] 목표 3 — **갱신할 수 없거나 갱신 뒤에도 다르면 지금처럼 차단한다.** 마커 중복 등으로 쓰기가 실패하거나, `scripts/sync-doc-counts.sh` 가 없거나, 부분 커밋(임시 색인)이거나, 갱신 뒤 재검사가 실패하면 막고 안내한다(조용히 통과 금지). 검증: 같은 시험 §3(마커 2쌍 → 비영 종료) · §4(훅 분기를 잘라 내 태운다: 갱신 스크립트 없음 → 차단, 재검사 실패 → 차단, 재검사 통과 → 통과 + 알림, 부분 커밋 → 차단) · 기존 `doc-counts-gate-test.sh` 통과.
- [x] 목표 4 — **배선과 문서.** `pre-commit.sh` R-doc 분기가 `--stage` 를 부르고(넘기는 파일은 게이트가 검사하는 `DOC_TARGETS` 만), `core-beliefs.md#r-doc`·README 의 "고치는 법" 문구를 맞춘다. 검증: `grep -c "sync-doc-counts.sh --stage" assets/hooks/pre-commit.sh` 가 1(안내 문구에 같은 문자열을 넣지 않는다) · `bash tests/doc-counts-gate-test.sh` 통과 · 공장 `.git/hooks/pre-commit` 이 새 원본과 `diff` 로 같다 · `bash tests/run-all.sh` 마지막에 한 번.

## 5. 단계 (Steps)

### Step 1. 시험 먼저 [Impl]
- `tests/doc-counts-autofix-test.sh` §1~§3 을 쓰고 실패(RED)를 확인한다.

### Step 2. `--stage` 구현 [Impl]
- `--stage` 는 **첫 인자로만** 인식한다(뒤의 파일 인자 처리는 그대로 — 기존 시험이 파일 하나를 넘기는 호출을 한다). 스테이징 안 된 변경이 있는 파일(`git diff --quiet -- <파일>` 이 실패, `git add -p` 로 일부만 올린 파일 포함)은 건너뛰고 알린다 · 갱신한 파일만 `git add` · 마지막에 넘긴 파일 전체의 대조 결과로 종료코드를 낸다(건너뛴 파일이 낡았으면 비영).
- 검증: 시험 §1~§3.

### Step 3. 게이트 배선 · 문서 · 전체 시험 [Review]
- R-doc 분기 case 1 에서: `scripts/sync-doc-counts.sh` 가 있고 부분 커밋이 아니면(`GIT_INDEX_FILE` 이 없거나 이름이 `index`) `--stage "${DOC_TARGETS[@]}"` 를 `|| rc=$?` 로 받아 부른 뒤 같은 검사를 다시 돌린다. 통과하면 `[R-doc] 문서 수치를 자동 갱신하고 스테이징했습니다: <파일들>` 한 줄 + `gate_add R-doc pass`. 그 밖에는 기존 차단 문구 그대로.
- 제약: 기존 시험이 분기를 `^  DOC_OUT=` 에서 `^  esac$` 까지 잘라 내므로 두 앵커를 바꾸지 않는다. 새 코드는 `X_OUT=$(...)` 맨 대입을 쓰지 않는다(`set -e` 조기 종료 방지, 기존 시험이 검사).
- 재검사가 실패하면 이미 스테이징된 올바른 갱신은 남기고(되돌리지 않는다) 차단한다.
- 공장 `.git/hooks/pre-commit` 재설치, 전체 시험은 마지막에 한 번.

## 6. 의사결정 로그

- 2026-09-29: 차단을 없애지 않고 "갱신 후 재검사" 로 바꾼다 — 근거: 수치는 기계가 확인·산출하므로 오탐 비용이 없고, 틀린 숫자가 올라갈 수 없다는 보장이 R-doc 의 존재 이유다. 손해: 훅이 파일을 고치므로 놀랄 수 있다 → 무엇을 갱신했는지 출력에 남긴다.
- 2026-09-29: 훅에 로직을 넣지 않고 `sync-doc-counts.sh` 에 `--stage` 를 둔다 — 근거: `pre-commit.sh` 가 967줄이고, "쓰기는 한 곳(sync)" 이라는 기존 원칙(같은 것을 두 곳에서 정의하면 갈라진다)을 지킨다.
- 2026-09-29: 스테이징 안 된 변경이 있는 파일은 자동 갱신하지 않는다 — 근거: `git add` 가 사용자의 다른 편집을 같이 올려 버린다. 그때는 지금처럼 차단하고 안내한다.

## 7. 발견·예외

- 부분 커밋(`git commit <경로>`·`-a`)은 git 이 임시 색인으로 훅을 돌려 훅 안의 `git add` 가 커밋에 안 실린다. `GIT_INDEX_FILE` 로 감지해 그때는 자동 갱신을 하지 않고 예전처럼 차단한다(위 Step 3).
- `sync-doc-counts.sh` 의 기본 대상에는 CLAUDE.md 가 있지만 게이트는 README.md·harness.conf 만 검사한다. 훅은 검사하는 파일만 넘겨 CLAUDE.md 를 건드리지 않는다. 그래서 CLAUDE.md 의 수치는 여전히 수동 실행 때 갱신된다 — 게이트 대상에 넣을지는 별도 판단(후속 후보).

## 8. 회고 (완료 시 작성)

- 잘된 것: 시험을 먼저 써서 수정 전 6건 실패를 확인한 뒤 구현했다. 실제 커밋으로 끝에서 끝까지 확인했다 — 낡은 수치를 일부러 스테이징하고 커밋하자 검사가 `[R-doc] 문서 수치가 낡아 자동 갱신하고 스테이징했습니다` 를 내고 README·harness.conf 를 같은 커밋에 실었다(231b4e5). 부분 커밋은 `GIT_INDEX_FILE` 로 정확히 가려 자동 갱신하지 않는다. 전체 시험 118개 통과.
- 잘못된 것: 훅 분기 시험의 첫 모의 함수가 카운터를 서브셸 안에서 올려(`$(...)`) 두 번째 검사도 실패로 나왔다 — 카운터를 파일로 바꿔 고쳤다. 계획 검토가 지적한 "부분 스테이징·부분 커밋·기존 시험 앵커" 세 가지는 착수 전에 계획서에 반영했다.
- 다음 룰 후보: CLAUDE.md 의 수치 블록은 게이트 대상이 아니어서 수동 실행 때만 갱신된다(§7). 게이트 대상에 넣을지 판단한다.
- 전파: 게이트는 마커가 있는 공장에서만 켜지므로 소우주 전파는 필요 없다(`pre-commit.sh` 원본은 다음 전파 때 함께 간다).
