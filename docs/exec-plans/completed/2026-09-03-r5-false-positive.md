# 2026-09-03-r5-false-positive — R5 우회 탐지의 오탐 제거

## 1. 동기 (Why)

게이트 발화 관측(`gate-telemetry` 계획)을 켜자마자 R5 가 **발화율 100%** 로 나왔다.
`docs/audits/2026-09-03-gate-firing-first-observation.md` 실측: 관측된 20건이 **전부 오탐**이며
이 세션에서 `--no-verify` 는 한 번도 시도되지 않았다.

원인은 `claude-pretooluse-bash-guard.sh` 의 탐지 정규식이다:

```bash
grep -Eq -- '(^|[[:space:]])(-n|--no-verify)([[:space:]]|$)'
```

`-n` 을 명령 문맥과 무관하게 단어 단위로 잡으므로 `grep -n`·`sort -n`·`head -n` 이
모두 발화한다. `-n` 이 `--no-verify` 의 약어인 것은 **`git commit` 문맥에서만**이다.

**왜 지금까지 안 보였나**: 이 훅은 차단하지 않고 컨텍스트만 주입한다. 매 턴 조용히 붙는
텍스트라 "원래 그런 것" 으로 넘어갔다. 횟수를 세기 시작하자 한 번에 드러났다.

**왜 고쳐야 하나**: `core-beliefs.md#r-iface` — "과발화하는 차단은 우회를 학습시키며,
그 학습은 되돌리기 어렵다." R5 는 우회를 막는 룰인데 그 경고가 상시 배경 소음이 되면
진짜 우회 시도가 섞여 들어와도 눈에 띄지 않는다. 경보가 무의미해진다.

## 2. 목표 (What — 검증 가능한 형태)

- [x] 목표 1 — `git commit` 이 아닌 명령의 `-n` 은 발화하지 않는다.
      검증: `bash tests/r5-detection-test.sh` — `grep -n`·`sort -n`·`head -n` 무발화 단언.
- [x] 목표 2 — 진짜 우회는 여전히 전부 잡는다 (재현율 유지).
      검증: 같은 테스트 — `git commit --no-verify`, `git commit -n`, `git commit -nm x`,
      `git -c user.email=x commit -n` 발화 단언.
- [x] 목표 3 — 기존 스위트 회귀 없음.
      검증: `bash tests/run-all.sh` 전체 통과.

## 3. 비목표 (Out of Scope)

- R5 를 경고에서 **차단으로 승격**하지 않는다. 오탐을 없애는 것과 등급을 올리는 것은 별개이며,
  승격 판단은 오탐 제거 후의 발화율 데이터를 보고 한다.
- 다른 게이트의 임계·정규식은 건드리지 않는다.
- 커밋 메시지 본문에 들어간 `-n` 문자열(`git commit -m "fix -n bug"`)은 이번에도 오탐이다.
  명령 문자열만으로 인자와 메시지 본문을 가르려면 셸 파서가 필요하고, 그 비용이
  이득을 넘는다. 알려진 한계로 남기고 문서화한다.

## 5. 단계 (Steps)

### Step 1. 탐지 규칙 교체 [Impl]

- 입력: 현재 정규식
- 산출: `--no-verify` 는 문맥 무관 탐지 유지. `-n`(및 `-nm` 같은 묶음 단축 플래그)은
  명령이 `git ... commit` 일 때만 탐지.
- 검증: `bash tests/r5-detection-test.sh` 통과.

### Step 2. 회귀 확인 [Review]

- 입력: Step 1
- 산출: 기존 스모크(`harness-hooks-smoke.sh` §4) 및 전체 스위트 통과 확인
- 검증: `bash tests/run-all.sh`

## 6. 의사결정 로그

- 2026-09-03: **`--no-verify` 는 문맥 무관 유지** — 근거: 이 문자열은 git 외에 쓰임이 거의 없고,
  재현율을 잃는 쪽이 정밀도를 잃는 쪽보다 나쁘다. 우회 1건을 놓치는 비용이 오탐 1건보다 크다.
- 2026-09-03: **`-n` 은 `git commit` 문맥으로 한정** — 근거: `-n` 이 `--no-verify` 를 뜻하는 것은
  그 문맥뿐이다. 다른 문맥의 `-n` 은 전혀 다른 의미(줄번호·숫자정렬·개행억제)다.
- 2026-09-03: **묶음 단축 플래그(`-nm`)도 잡는다** — 근거: `git commit -nm "x"` 는 유효한
  우회이고 현재 정규식은 이를 놓친다. 오탐을 줄이면서 재현율은 오히려 올린다.

## 7. 발견·예외

- **신규 테스트 6개가 `tests/run-all.sh` 에 등록되지 않아 한 번도 CI 에서 돌지 않는 상태였다.**
  이 저장소의 러너는 자동 탐색이 아니라 **명시 목록**이다. `gate-*` 4개, `mutation-trigger`,
  `r5-detection` 전부 누락돼 있었고, 개별 실행으로만 통과를 확인하고 있었다.
  이것이 바로 이 저장소가 반복해 겪은 **조용한 건너뜀**이다 — 테스트는 존재하는데 아무도 돌리지 않는다.
  등록 후 전체 40 → 46개, 전부 통과.
  근본 대응(러너에 고아 테스트 검사 추가)은 이 계획의 범위 밖이라
  `docs/exec-plans/backlog/run-all-orphan-test-guard.md` 로 넘긴다.
- **code-reviewer 가 남은 오탐 1종을 잡았다 (HIGH).** 최초 수정은 명령 *전체*에서
  "git commit 이 있는가" 와 "-n 이 있는가" 를 따로 물었다. 그래서
  `git log -n 5 && git commit -m x`·`grep -n foo f; git commit -m x` 가 여전히 발화했다 —
  두 조건이 **서로 다른 명령**에서 충족되기 때문이며, 이 수정이 없애려던 오탐과 같은 종류다.
  내 테스트는 이 조합을 한 건도 다루지 않아 통과하고 있었다.
  수정: `;` `&&` `||` `|` 로 세그먼트를 나눠 **같은 세그먼트 안에서** 둘이 함께
  성립할 때만 발화한다. 체이닝 케이스 6건을 테스트에 추가(15 → 21 단언).
- 오탐 제거가 재현율을 오히려 **올렸다**. 문맥을 보게 되면서 묶음 단축 플래그
  (`git commit -nm x`)를 잡을 수 있게 됐다 — 이전 규칙은 이 유효한 우회를 놓치고 있었다.

## 8. 회고 (완료 시 작성)

- **잘된 것**: 관측 장치를 켠 첫날에 룰 하나의 오탐을 데이터로 확정했다. 발화율이라는 숫자가
  없었으면 "원래 그런 경고" 로 계속 흘렀을 것이다. 테스트를 먼저 써서 현재 코드가
  8건 실패하는 것을 확인한 뒤 고쳤고, 그래서 무엇이 고쳐졌는지가 증거로 남았다.
- **잘못된 것**: 신규 테스트를 러너에 등록하지 않았다. 여섯 개를 만드는 동안 한 번도
  눈치채지 못했고, R5 회귀 확인차 `run-all.sh` 를 돌려보다가 우연히 드러났다.
  "테스트를 만들었다" 와 "그 테스트가 돌고 있다" 는 다른 사실이며, 이 저장소는 그 간극에서
  이미 여러 번 다쳤는데 같은 자리를 또 밟았다.
- **잘못된 것 2**: 오탐을 고치면서 오탐을 남겼다. 단일 명령만 놓고 생각했고 체이닝을
  테스트하지 않았다. "고쳤다" 는 판단의 근거가 내가 쓴 테스트뿐이면, 테스트가 놓친 것은
  그대로 남는다. 리뷰어를 부른 것이 이번 결정 중 가장 값이 컸다.
- **다음 룰 후보**: `tests/*-test.sh` 중 `run-all.sh` 에 등록되지 않은 파일이 있으면
  러너가 실패한다. 고아 테스트는 없는 테스트와 같다.
