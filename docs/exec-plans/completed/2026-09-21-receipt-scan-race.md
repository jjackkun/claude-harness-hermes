# 2026-09-21-receipt-scan-race — 설치 영수증 스캔이 사라지는 임시 파일에 걸려 설치 전체를 실패시킨다

> 출처: 2026-09-21 전파(12곳) 중 zeroday-frontend 1곳 실패. 로그에 `find: './.hermes/state.db-shm': No such file or directory` 두 줄 뒤 `✗ 실패`.

## 1. 동기 (Why)

`receipt_end` 는 설치가 쓴 파일을 모으려고 프로젝트 전체를 `find` 로 훑는다. 그런데 같은 설치가 바로 앞에서
`.hermes/state.db` 를 초기화하고, SQLite 가 만든 `-wal`·`-shm` 사이드카는 체크포인트 뒤 **사라진다**.
`find` 가 디렉터리 목록을 읽은 뒤 stat 하려는 순간 파일이 없으면 rc 1 을 낸다.
`project-claude.sh` 는 `set -euo pipefail` 이므로 그 rc 가 설치 전체를 죽인다.

설치의 **마지막 보고 단계**가 설치 성공을 뒤집는다. 실제로 이 실행에서 zeroday-frontend 는 모든 파일이 정상 배치된 뒤 실패로 기록됐다.

## 2. 목표 (What — 검증 가능한 형태)

- [x] 목표 1 — 스캔 중 파일이 사라져도 설치가 실패하지 않는다. 검증: 경합 재현 시험이 rc 0.
- [x] 목표 2 — 사라져서 영수증이 불완전해졌다면 **조용히 넘어가지 않는다**. 검증: 시험이 경고 문구를 확인.
- [x] 목표 3 — SQLite 사이드카는 애초에 영수증 대상이 아니다. 검증: 시험이 `-wal`·`-shm` 미포함 확인.
- [x] 목표 4 — zeroday-frontend 재설치가 성공한다. 검증: `project-claude.sh` rc 0 + doctor 깨끗.

## 3. 비목표 (Out of Scope)

- `find` 를 다른 도구로 갈아타기 — 원인은 도구가 아니라 rc 처리다.
- `2>/dev/null` 로 덮기 — 실패를 조용히 삼키는 것은 이 저장소가 금지한다(silent-failure).

## 7. 발견·예외

- **같은 모양의 둘째 지뢰를 옆에서 찾았다.** 필터로 쓰던 `grep -vxF` 는 남는 줄이 없으면 rc 1 을 낸다.
  설치가 아무 파일도 쓰지 않은 경우(재설치 직후 등) 같은 `set -euo pipefail` 에 또 걸린다.
  경합과 별개로 터질 수 있던 자리라 `awk` 로 바꿨다. 시험이 고치기 전 코드에서 이 건도 빨갛게 잡는다.
- **실패가 12곳 중 1곳에서만 났다.** 코드는 12곳 모두 같고 타이밍만 달랐다. "11곳이 통과했으니 코드는 괜찮다" 가
  성립하지 않는 종류의 결함이다 — 경합은 통과율로 판단할 수 없다.
- 시험은 파일 4,000개를 지우며 스캔해 경합을 **실제로** 일으킨다. 경합이 안 걸린 실행에서도 단언이 성립하도록
  갈래를 나눴다(걸렸으면 경고 1줄, 안 걸렸으면 0줄). 타이밍 의존 시험이 가끔 빨개지는 것을 막는다.
