# 2026-09-23-r-lock — 설치 구성(presets.lock)은 저장소에 둔다

## 1. 동기 (Why)

**2026-09-22 실측 사고.** 공장 자기 재설치를 `project-claude.sh . harness hermes adhd` 로 돌리자
**git 에 추적된** 심링크 `mcp-builder`·`skill-creator` 와 CLAUDE.md 의 두 절이 지워졌다.
설치기는 설계대로 동작했다 — "프리셋에서 빠진 항목은 제거"(`_cleanup_stale_assets`,
`tests/copy-install-test.sh` 3절이 이미 단언).

원인은 **입력과 결과가 다른 곳에 산다**는 것이다.

| | 어디에 사는가 | 그때 값 |
| --- | --- | --- |
| 입력: `.claude/presets.lock` | **`.gitignore`**(설치기가 넣는다, `lib/harness_installers.sh:635`) | 3줄 |
| 결과: `.claude/.factory-manifest.json` | 커밋됨 | 95항목, 스킬 14개 (`mcp-builder`·`skill-creator` 포함) |
| 결과: `.claude/skills/*` 심링크 · CLAUDE.md 절 | 커밋됨 | 5개 프리셋 분량 |

`project-claude.sh:181` 은 lock 을 **명령줄 인자 그대로** 덮어쓴다 — 저장소도 매니페스트도 보지 않는다:

```bash
printf '%s\n' "${PRESETS[@]}" > "$CLAUDE_DIR/presets.lock"
```

즉 lock 은 "이 프로젝트의 구성" 이 아니라 "이 컴퓨터에서 마지막으로 친 인자" 다.
`update-all.sh` 는 그것을 정본으로 읽는다(없으면 스킵). clone 한 컴퓨터는 lock 을 못 받으므로
누가 한 번 적은 수로 설치하면 그 값이 굳고, 다음 재설치가 **커밋된 것을 지운다.**

> 이 컴퓨터의 lock 이 언제 3줄이 됐는지는 기록이 없다(설치는 훅 로그에 안 남는다). 확실한 것은 메커니즘이다.

## 3. 비목표

- `.installed-projects` 를 커밋 대상으로 바꾸는 것. 그것은 **컴퓨터의 속성**이다(어느 프로젝트를 이 기계가 관리하는가).
  `presets.lock` 은 **프로젝트의 속성**이다. 이 구분이 이번 룰의 경계다.
- 프리셋 제거를 **차단**하는 것. 의도적으로 뺄 수 있어야 한다 — 경고까지다.
- `.hermes/universe.id`·`agents.json` 의 컴퓨터 간 갈림
  (→ `docs/exec-plans/backlog/identity-guard-blocks-cross-machine-sync.md`, 별건).
- 옛 설치본의 lock 을 자동으로 git add 하는 것. 무시만 풀고, 커밋은 사람이 한다.

## 6. 의사결정 로그

- 2026-09-23: **경고만 붙이는 안을 기각하고 무시 해제까지 간다** — 근거: 경고는 clone 한 컴퓨터가
  처음부터 잘못된 집합으로 까는 것을 막지 못한다. 사고를 늦출 뿐이다.
  틀렸을 때 손해: lock 이 저장소에 들어가 커밋 잡음이 는다(설치할 때만 바뀌는 3~5줄 파일).
- 2026-09-23: **차단이 아니라 경고** — 근거: 프리셋을 빼는 것은 정당한 작업이다. 차단하면 `--force` 류
  우회 인자를 만들게 되고 그것이 새 구멍이 된다. 틀렸을 때 손해: 경고를 못 보고 지나칠 수 있다.
- 2026-09-23: **`.installed-projects` 는 건드리지 않는다** — 근거: 그것은 기계의 속성이다.
  틀렸을 때 손해: 대시보드의 소우주 목록이 컴퓨터마다 계속 다르다(별건 백로그에 있음).

## 7. 발견·예외

- **내 단언이 두 번 헐거웠다.** ① "경고에 이름이 있다" 가 경고 없이도 통과했다 — 로그의
  `removed → mcp-builder` 에 걸렸다. 경고 줄 **안**에서 찾도록 좁혔다.
  ② "미추적 제거는 조용하다" 가 빨갰는데 **제품이 옳고 시험 셋업이 틀렸다** — 앞 절의 삭제를
  커밋하지 않아 경로가 색인에 남아 "추적됨" 이었다. 제품이 아니라 셋업을 고쳤다.
- **도구가 있다고 끌어 쓰면 질문이 뒤틀린다.** 어제 만든 `git_ignore_judge`(무시되는가)를 쓰려다
  멈췄다. 이 자리의 질문은 **추적되는가**이고 그것은 `ls-files` 가 답한다. 선언만 한 변수를 지웠다.

## 8. 회고 (2026-09-23)

- 잘된 것:
  - **사고가 난 그 자리에 강제 장치를 박았다.** 오늘 실제로 커밋된 것을 지운 코드 경로
    (`_cleanup_stale_assets` 의 `rm`) 바로 앞에 판정을 넣었다.
  - 세 건을 **한 룰로 묶지 않았다.** `.installed-projects` 는 기계의 속성이라 로컬이 맞다 —
    "프로젝트의 속성인가, 기계의 속성인가" 라는 경계를 감사 기록에 남겼다.
  - 차단이 아니라 경고로 멈췄다. 차단했으면 `--force` 류 우회 인자를 만들게 됐을 것이다.
- 잘못된 것:
  - 애초에 이 사고는 **내가 프리셋 인자를 lock 을 읽지 않고 넣어서** 났다. 룰은 그 실수가
    다시 나도 사람이 보게 할 뿐, 실수 자체를 없애지는 않는다.
  - 시험 단언 두 개가 헐거웠다(§7). "빨강을 봤다" 만으로는 부족하고 **왜 빨간지**를 봐야 한다.

  차이를 먼저 보이고 진행한다(지금은 결과가 지워질 때만 보인다). 근거: 09-22 사고의 시작점은
  삭제가 아니라 **인자를 잘못 준 순간**이었다.
