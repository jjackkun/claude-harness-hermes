# 2026-09-21-gateguard-fact-force — 편집 전 사실 확인을 기계로 요구할 것인가

> 출처: backlog `gateguard-fact-force` (ECC 결핍 #4, 가치 중) → 2026-09-21 사용자 "진행하자".
> 착수 조건이 문서에 박혀 있었다: **"측정 없이 훅을 늘리지 않는다(C-계열 원칙)"**. 그래서 이 계획의 첫 단계는 구현이 아니라 측정이다.

## 1. 동기 (Why)

`assets/rules/harness/rules.md` 는 "수정 전 import 그래프 1회 확인 — 파일명 추론 금지" 를 요구한다. 그러나 이것을 확인하는 장치는 없다.
훅은 형식만 본다(`iface-guard` 공개 심볼 수 · `plan-declare` 계획서 선언 · `dead-file-warn` 실사용 여부).
ECC v2.2.1 은 `gateguard-fact-force.js` 로 Edit 전에 importer 목록 인용을 **요구**하고 자체 벤치에서 +2.25점을 주장한다(검증 안 됨).

그 주장이 이 저장소에서도 성립하는지는 **재 보면 안다**. 세션 트랜스크립트가 4,756개 남아 있다.

## 2. 목표 (What — 검증 가능한 형태)

- [x] 목표 1 — 훅을 만들지 말지를 **실측**으로 정한다. 검증: 실 트랜스크립트 전수(표본 아님) 집계값이 §2-bis 에 값으로 남는다.
- [x] 목표 2 — 그 측정을 저장소 자산으로 남겨 **다시 잴 수 있다**. 검증: `python3 scripts/edit_factcheck_rate.py --json` rc 0, `edits` > 0.
- [x] 목표 3 — 판정 두 갈래(내용 봄 / 맨눈)를 시험이 가른다. 검증: `bash tests/edit-factcheck-rate-test.sh` 초록.
- [x] 목표 4 — 결정과 근거가 감사 문서로 남고 백로그가 닫힌다. 검증: `docs/audits/2026-09-21-...md` 존재 + backlog 파일 삭제.

전수 집계 — 트랜스크립트 4,756개, 도구 호출 전부.

| 확인한 것 | 결과 |
| --------- | ---- |
| 기존 파일 수정(Edit 계열) 건수 | **911건** (같은 세션에서 방금 만든 파일을 고친 605건은 제외, Write 총 1,035건) |

남은 4.3% 도 다수가 **긴 세션 후반·압축 이후**라 PreToolUse 훅이 잡으면 대부분 오탐이 된다
(앞선 조사가 이미 컨텍스트 밖으로 밀려난 상태를 "안 봤다" 로 읽는다).

## 7. 발견·예외

- **정의 하나가 결론을 뒤집었다.** 첫 집계는 "편집 전 파일을 읽었다" 를 `Read` 도구로만 셌고 **18.4%** 가 나왔다.
  `cat`·`sed -n` 같은 Bash 읽기를 포함하자 **95.7%** 가 됐다. 18.4% 였다면 훅을 만들었을 것이다.
  측정으로 정하기로 한 판에서, 정의를 한 번 더 의심하지 않았으면 측정이 오히려 틀린 결론을 줬다.
- **맨눈 39건이 전부 도구 호출 11회 이후**에서 나왔다. 이것이 "압축으로 조사 기록이 밀려났다" 는 해석의 근거다.
  세션 초반 맨눈 편집이 한 건도 없다는 것은 에이전트가 시작부터 추측으로 고치지는 않는다는 뜻이다.
- 계측기를 시험할 때 **가짜 위반을 심어 빨간지 확인**했다(`_saw` 를 항상 참으로 변이 → 2건 빨강, 원복 후 11/11).
  통과만 보는 검증은 silent-skip 을 못 잡는다는 이 저장소의 기존 교훈을 따랐다.
- 다음으로 흘릴 것: `backlog/council-review.md` 도 ECC 출처 항목이다. 같은 방식으로 **먼저 재고 나서** 결정한다.
