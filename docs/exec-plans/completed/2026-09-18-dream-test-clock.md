# 2026-09-18-dream-test-clock — dream 워터마크 시험의 벽시계 의존 제거

> 출처: `docs/exec-plans/backlog/dream-test-clock-flake.md` (본 계획으로 승격, backlog 파일 삭제)
> 설계 결정 인용: 없음 — 시험 픽스처의 결정성 수정. 원장 결정과 무관.

## 1. 동기 (Why)

`tests/hermes-pipeline-test.sh` 20·21 절이 드물게 실패한다(2026-09-09 관측). 실패 덤프에서 dsess3 의
`updated_at`(01:19:03)이 **1.1초 먼저 넣은** dsess2(01:19:04)보다 이르다 — `sleep` 부족이 아니라 벽시계가 뒤로 간
것(WSL2 의 주기적 시계 보정은 뒤로 스텝할 수 있다). 워터마크(=마지막 요약 `updated_at`)보다 이른 요약은 `updated_at > since`
수집에서 빠져 dream 이 "새 요약 없음" 으로 조용히 끝난다.

코드 확인(2026-09-18): `hermes-dream.py` 는 실시간을 리포트 날짜(`datetime.now()`, 432행)에만 쓴다. 수집·워터마크는 전부
`session_summary.updated_at` 의 대소로만 판정한다 → 시험이 `updated_at` 을 명시하면 벽시계와 완전히 분리된다.
20절 이전에 dream 을 돌리는 절은 없고, 이후 26절은 throttle 마커만 본다 → 합성 시각의 안전 범위에 제약 없음.

## 2. 목표 (What — 검증 가능한 형태)

- [x] 목표 1 — 20·21 절의 요약 삽입이 벽시계를 읽지 않는다(`bump_clock`·`CURRENT_TIMESTAMP` 의존 0)
  — 검증: `grep -c bump_clock tests/hermes-pipeline-test.sh` = 0, `add_summary` 가 `updated_at` 을 인자로 지정
- [x] 목표 2 — 삽입 순서와 `updated_at` 순서가 같음을 시험이 스스로 단언한다(시계 역행이 있어도 픽스처는 단조)
  — 검증: 21절 뒤 자체 단언 1개
- [x] 목표 3 — 시험이 연속 3회 통과하고 20·21 절 소요가 `sleep 3.3s` 만큼 줄어든다 — 검증: 3회 실행 + 소요 비교
