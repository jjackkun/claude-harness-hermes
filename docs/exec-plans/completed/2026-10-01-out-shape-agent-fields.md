# 2026-10-01-out-shape-agent-fields — R-out 이 "무엇이 바이트를 냈나" 와 "누가 불렀나" 를 남긴다

> 작성일: 2026-10-01
> 목적: R-out 이벤트에 명령 모양(묶음·파이프·heredoc)과 에이전트 필드를 더해, 큰 출력의 원천을 가리고 모델 선언 검증(`agent-model-routing-blindspot`)의 선행 조건을 만든다.
> 앞선 계획: `docs/exec-plans/completed/2026-09-08-tool-output-budget.md` — §7-6 정정이 이 계획의 직접 근거다.

## 1. 동기 (Why)

2026-10-01 출력 크기 판정에서 "초과의 36% 가 `cat`" 이라 읽고 규칙을 만들려다, 승격 직전 대화 기록(Bash 4,810건)과 대조해 **해석이 틀렸음**을 잡았다(`tool-output-budget` §7-6 정정):

- R-out 의 `cmd:<머리>` 는 `cd X &&` 를 걷어낸 **첫 단어**다. 한 호출에 여러 명령을 묶으면(전체의 65%) 바이트를 낸 명령이 아니라 맨 앞 단어만 남는다. 머리가 `cat` 인 초과 11건 중 단순 `cat 파일` 은 1건이었다.
- 그래서 지금 데이터로는 "어떤 모양의 호출이 큰 출력을 내는가" 를 **가릴 수 없다**. 대화 기록은 이 컴퓨터·이 프로젝트 것뿐이라 상시 관측이 못 된다.
- 이벤트에는 `ts · rule · verdict · stage · path · detail` 뿐이라 **어느 에이전트가 불렀는지**도 없다. `agent-model-routing-blindspot` 은 이 값이 없어 승격하지 못했다(§7-6).

> 여기까지 다시 읽었다: 이 계획의 산출물은 **관측 필드**이지 절감이 아니다. 필드가 쌓인 뒤에야 "줄일 표적이 있는가" 를 말할 수 있고, 그 판단은 이 계획의 범위 밖이다. 이번에도 요약 한 칸이 아니라 원자료로 판단하려는 것이다.

## 2. 목표 (What — 검증 가능한 형태)

**정의 (모든 목표가 쓴다).**
- `seg` = 최상위 명령 수. 따옴표·heredoc 본문 밖의 `;` `&&` `||` `&` 줄바꿈으로 가른 덩어리. `cd X &&`·`VAR=값` 접두는 세지 않는다. `(…)`·`$(…)`·백틱 안은 가르지 않고 한 덩어리로 본다.
- `pipe` = 따옴표 밖의 `|` 수(`||` 제외). 파이프 단계는 한 `seg` 안이다.
- `hd` = heredoc(`<<`)이 있으면 1. 본문 줄은 명령으로 세지 않고 끝 표시 줄 뒤의 명령은 센다.
- `heads` = 각 명령(파이프 단계 포함)의 머리, 최대 6개. 머리는 첫 단어의 basename. 둘째 단어는 **알려진 부명령**(`git status` 등)이거나 **스크립트 파일 이름**(`python3 x.py`)일 때만 붙인다 — 아무 단어나 붙이면 `python3 <토큰 모양>` 처럼 인자가 샌다(리뷰 지적). **`[A-Za-z0-9_.+-]` 밖의 글자가 든 머리는 `?` 로 쓴다** — 따옴표·치환·괄호가 머리 자리에 와도 값이 새지 않는다.
- `sub` = 서브에이전트가 부른 호출이면 1(페이로드에 `agent_id` 가 있음). `agent` = 페이로드 `agent_type`.

- [x] 목표 1 — **R-out 이벤트가 명령 모양을 남긴다**(`seg`·`pipe`·`hd`·`heads`). 검증: `tests/out-shape-test.sh` — 픽스처가 단일 · 파이프 · `;` 묶음 · `&&` 묶음 · `||` · heredoc(뒤에 명령 있음) · `cat > f <<EOF` · 따옴표 안 구분자 · `cd X &&` 접두 · `VAR=값` 접두 · 인터프리터 · 서브셸/`$(…)` · 6개 초과 · 빈 명령 을 기대 모양으로 낸다.
- [x] 목표 2 — **비밀값이 이벤트에 남지 않는다.** 검증: **속성 시험**(비밀 표지를 머리가 아닌 모든 자리 — 인자·따옴표·heredoc 본문·`$( )`·할당 값·리다이렉트·경로·줄 이음 — 에 넣어 결과에 0건) + 시험 픽스처에 `TOKEN=<가짜값>` · `--password <가짜값>` · `-H "Authorization: Bearer <가짜값>"` (시험 픽스처의 실제 값은 `tests/out-shape-test.sh` 에 있다) · 따옴표로 시작하는 머리 `"secret value" arg` · 치환 머리 `$(cat /etc/secret) x` · 경로 머리 `/home/x/secret-dir/tool` · 백틱 을 넣어 결과에 그 값들이 **0건**(머리는 `?` 또는 basename 만). 훅 전체를 통과시킨 `gate-events.jsonl` 에서도 같은 값이 0건.
- [x] 목표 3 — **에이전트가 남는다.** `agent=<agent_type>`(없거나 정화 후 비면 `-`) · `sub=0|1`. 값은 `[A-Za-z0-9_.:-]` 만 남기고 48자로 자른다. **모델은 기록하지 않는다** — Step 1 실측(2026-10-01)에서 메인·서브에이전트 어느 페이로드에도 모델 키가 없었다. 검증: 픽스처 페이로드(agent_type 있음+agent_id 있음 · 없음 · 이상한 글자 · 비는 값 · 100자).
- [x] 목표 4 — **기존 판정·소비자가 그대로다.** pass/warn/skipped 판정·임계 불변, `gate_report.py` R-out 행 · `out_report.py` 기존 표 숫자 불변, `cmd:` 칸이 오염되지 않는다(필드는 `HEAD` 와 **다른 줄**로 넘긴다 — 한 줄에 붙이면 `read -r … HEAD` 가 줄 나머지를 삼킨다). 검증: `tests/output-budget-test.sh` 전부 통과(착수 때 개수를 재서 적는다) + 새 필드 레코드와 옛 레코드를 섞은 events 파일에서 두 보고서의 숫자가 같다 + 훅 통과 후 `path` 칸이 `cmd:<머리>` 한 토큰 규칙 그대로.
- [x] 목표 5 — **`out_report.py --by shape|agent` 가 새 필드로 분포를 낸다.** 모양별(단일·파이프·묶음·heredoc) · 에이전트별 n · p50 · p90 · max · 초과 · 합계. 새 필드 없는 옛 레코드는 `(기록 이전)` 으로 묶인다. 검증: 픽스처 events 파일 → 표 · 옛 레코드만 → `(기록 이전)` 한 줄.
- [x] 목표 6 — **관측이 조용히 꺼지지 않는다.** `out_shape` 를 못 불러오면 **`shape=err` 표식**을 `detail` 에 남기고 머리는 예전대로 기록한다. 검증: 시험 — 설치된 훅 옆에서 `out_shape.py` 를 치우고 돌리면 `shape=err` 가 보이고 `path` 는 `cmd:<머리>`. 설치 시험 — `out_shape.py` 가 설치본 `scripts/hooks/` 에 복사된다.
- [x] 목표 7 — **훅 비용이 감당할 만하다.** 이 훅은 **세션의 모든 Bash 호출**에 돈다. Step 1 실측: 훅 1회 중앙 **68ms**(p90 74ms, 20회), Bash 호출 시간 중앙 **161ms**(2,744건). 기준: 전 대비 **중앙 +20ms 이하**(중앙 호출의 약 12%) 이고 p90 도 §7 에 적는다. 넘으면 모양 계산을 훅에 인라인한다. 검증: 훅(`bash claude-posttooluse-output-budget.sh`)을 전·후 **번갈아 40회** 돌려 중앙·p90 차이를 잰다 — 순차로 재면 시스템 부하 변동이 한쪽에 몰린다(§7).
- [x] 목표 8 — **전파 뒤 새 필드가 실제로 쌓인다.** 대상은 공장 + 소우주 8곳(`zeroday-frontend` `novel-ab` `novel-bc` `rim-kanban` `jjackkun_bot` `teulankkae` `upbit-ai-trading` `kis-trading`, terminal-shipping 은 사용자 몫). 검증: 공장은 Bash 를 한 번 부른 뒤 `tail -1 .harness/gate-events.jsonl` 에 `seg=` · 각 소우주는 **설치본 `scripts/hooks/` 를 일회용 폴더에 복사**해 합성 페이로드를 훅에 넣으면 `detail` 에 `seg=` 가 있고 `shape=err` 가 없다(파일 존재만이 아니라 동작을 본다).

## 3. 비목표 (Out of Scope)

- **명령 전문 저장** — 비밀값이 든다(목표 2). 모양과 정화된 머리만 남긴다.
- **차단·절감** — 이 계획은 관측이다. 새 필드로 표적이 보이면 그때 별도 계획.
- **모델 선언의 타당성 평가**(`agent-model-routing-blindspot` 본체) — 필드가 쌓인 뒤의 일이다. 이 계획은 선행 조건(에이전트·서브에이전트 구분)까지만. **모델 자체는 페이로드에 없다**(Step 1) — 그 백로그는 모델을 다른 길(에이전트 정의의 선언 모델 ↔ `agent_type` 대조)로 풀어야 한다.
- **대화 기록을 훅에서 읽어 실제 모델 알아내기** — 호출마다 큰 파일을 읽는 비용이 목표 7 을 깬다.
- 기존 `head_of`(`path` 칸의 머리) 규칙 변경 — 이번에는 건드리지 않는다. 다만 새 `heads[0]` 와 같아야 하므로 일치 시험을 둔다(§6).

## 8. 회고

- 잘된 것: **정정에서 출발했다** — 요약 표의 한 칸(`cat` 행)으로 규칙을 만들려다 원자료(대화 기록)로 한 번 더 보고 접었고, 그 빈자리(명령 모양)를 관측 필드로 채웠다. 리뷰를 두 번 돌려(계획 `planner-lite` · 구현 `code-reviewer`) 둘 다 실결함을 잡았다. 변이 검사 3종으로 시험이 실제로 회귀를 잡는지 확인했고, "값 0건" 시험이 빈 출력에서 통과하는 약점도 스스로 찾아 고쳤다.

P9 가 문서의 가짜 값을 잡아 커밋이 막힌 **덕에** 푸시·전파 전에 드러났다 — 우연이었다. 속성 시험(머리가 아닌 모든 자리에 표지)을 처음부터 썼어야 했고, 그 속성 시험이 리뷰가 놓친 누출(줄 이음) 하나를 더 잡았다. 훅 비용을 처음에 순차로 재서 +85ms 노이즈에 속을 뻔했다.
