# 게이트 발화 첫 관측 — R5 과발화 확인

> 작성일: 2026-09-03
> 목적: 계장 직후 한 세션치 실측으로 드러난 게이트 이상을 기록한다.
> 출처 계획: `docs/exec-plans/active/2026-09-03-gate-telemetry.md` (Step 4 의 예비 관측)

## 개요

Step 2a·2b 계장 직후, 이 저장소에서 **한 세션(2026-09-03) 동안** 쌓인 이벤트 69건을
`gate_report.py` 로 집계했다. 1주치가 아니므로 승격·강등 판정은 아직 하지 않는다.
그러나 한 건은 표본 크기와 무관하게 결론이 난다.

## 관측

```
룰            기회  통과  경고  차단  우회  건너뜀  발화율
R5           14   0    14   0    0    0     100.0%
R-iface      2    0    0    2    0    0     100.0%
R-size       26   26   0    0    0    0     0.0%
R-size-resp  25   25   0    0    0    0     0.0%
R-dead-file  1    1    0    0    0    0     0.0%
```

## 발견 1 — R5 는 `-n` 을 쓰는 모든 명령에서 발화한다 (확정)

`claude-pretooluse-bash-guard.sh` 의 탐지 정규식:

```bash
grep -Eq -- '(^|[[:space:]])(-n|--no-verify)([[:space:]]|$)'
```

`-n` 을 단어 단위로 잡으므로 다음이 전부 발화한다(2026-09-03 실측):

| 명령 | 판정 |
|---|---|
| `grep -n foo file` | R5 발화 (오탐) |
| `sort -t'\|' -k1 -n -r` | R5 발화 (오탐) |
| `head -n 5 f` | R5 발화 (오탐) |
| `git commit -n -m x` | R5 발화 (정탐) |
| `git commit --no-verify` | R5 발화 (정탐) |

관측된 14건은 **전부 오탐**이었다 — 이 세션에서 `--no-verify` 는 한 번도 시도되지 않았다.

**왜 지금까지 안 보였나**: 이 훅은 차단하지 않고 컨텍스트만 주입한다. 매 턴 조용히
붙는 텍스트라 사람도 에이전트도 "원래 그런 것" 으로 넘겼다. 발화 횟수를 세기 시작하자
한 번에 드러났다 — 관측 장치를 만든 이유가 이것이다.

**왜 위험한가**: `core-beliefs.md#r-iface` 가 적은 그대로다 —
"과발화하는 차단은 우회를 학습시키며, 그 학습은 되돌리기 어렵다."
R5 는 `--no-verify` 우회를 막는 룰인데, 그 경고가 상시 배경 소음이 되면
정작 진짜 우회 시도가 섞여 들어와도 눈에 띄지 않는다. 경보가 무의미해진다.

**수정 방향(미적용)**: `-n` 은 `git commit` 문맥에서만 `--no-verify` 의 약어다.
`--no-verify` 는 지금처럼 무조건 보되, `-n` 은 명령이 `git commit` 일 때만 본다.
본 계획(`gate-telemetry`)의 §3 비목표가 "기존 게이트 수정 금지" 이므로
**이 문서는 보고까지만 하고 고치지 않는다.** 별도 승인 후 별도 변경으로 처리한다.

## 발견 2 — R-iface 차단 2건은 모두 정탐 (표본 부족)

둘 다 `gate-instrumentation-test.sh` 가 만든 합성 입력이 아니라 실제 세션의
`gate_report.py` 작성 중 발생했다(초안이 공개 심볼 임계에 걸림).
표본 2건으로는 과발화 여부를 말할 수 없다. 1주치 관측 후 재평가한다.

## 발견 3 — R-size / R-size-resp 는 0% (정상 범위)

편집 26건 중 발화 0건. 계장이 죽어 있는 것이 아니라 실제로 한도에 걸린 편집이
없었다는 뜻이다 — `pass` 26건이 분모로 남아 있어 둘을 구분할 수 있다.
분모를 기록하지 않았다면 이 줄은 "게이트가 죽었나?" 와 구분되지 않았다.

## 발견 4 — 테스트가 실제 관측 파일을 오염시켰다 (수정 완료)

`mutation-probe.py` 가 `gate_event.py` 의 경로 판정을 변이시키면
`CLAUDE_PROJECT_DIR` 폴백이 **실제 저장소**로 향해, 픽스처 룰명
(`R-a`·`R-x`·`R-z2` 등) 10건이 `.harness/gate-events.jsonl` 에 쌓였다.

수정: `tests/gate-event-test.sh` 의 모든 emit 호출을 임시 디렉터리를 cwd 로 삼아
실행한다(`emit_at` 헬퍼). 폴백이 git 최상위를 찾아도 저장소에 닿지 못한다.
검증: 수정 후 변이 테스트 재실행 → 재오염 0건. 기존 오염 10건은 제거했다.
