# 2D 에셋은 어떻게 얻나 — 논의 기록 (2026-11-18)

게임회사([2026-11-18-jj-agent-room-game-company.md](2026-11-18-jj-agent-room-game-company.md))에 필요한 그림(캐릭터·동작·타일)을 어떻게 얻을지 나눈 논의다.
근거 표시: **[실측]** 이 컴퓨터에서 돌려 봄 · **[문서]** 저장소·사이트에서 읽음 · **[웹]** 검색 결과(업체·리뷰 글, 검증 안 함) · **[추정]**.

## 한 줄 결론

- Claude 는 그림·영상 파일을 직접 만드는 모델이 아니다. Claude Code 가 그림을 만드는 길은 (1) 글자로 픽셀 격자·코드를 써서 그리기, (2) 다른 회사의 그림·영상 모델을 도구로 부르기 둘뿐이다.
- 맨손으로 코드 그림을 그리면 볼품이 없다. 같은 방식이라도 검사·재시도·후보 고르기를 붙인 **sprite-gen 의 `pixel-draw`** 는 32px 도트를 쓸 만하게 그린다 — Claude 구독만으로.
- 큰 일러스트 그림과 "캐릭터 한 장 → 원하는 동작 스프라이트" 는 **sprite-gen 의 그림·영상 파이프라인**이 한다. 단 그림은 ChatGPT(codex)·xAI(grok)·OpenAI 키, 영상은 xAI 가 맡는다. Claude 로는 안 된다.

## 1. 맨손 코드 그림 — 안 된다

- Claude 가 글자 격자로 16×17 기사·10×7 슬라임을 그렸다 → [code-drawn-knight.svg](assets-2d/code-drawn-knight.svg). **[실측]**
- 사용자 평: "장난아니게 구리네". 형태는 알아보지만 명암·외곽선이 거칠고 애니메이션은 프레임마다 모양을 유지하기 어렵다.
- 영상 3(유니티 공식 스킬)도 코드로 찍은 도트는 "눈이 안 갔다" 고 했다.

## 3. sprite-gen (aldegad/sprite-gen)

- 오픈소스 엔진. Apache-2.0 · 별 4,137 · 마지막 커밋 2026-11-08 · 엔진 v4.3.0(사이트 표기). 만든 사람이 이 도구로 Steam 게임(Dungeon Sookuma)을 개발 중. **[문서]**
- 웹 서비스 spritegen.kumastudio.app(베타) — 같은 엔진을 설치 없이. 가입 300 크레딧 무료(약 9개) · Starter 1,000 $9.68 · Studio 3,000 $26.18(25% 할인가). 결과물 상업 사용 가능·출처 표기 불필요. **[문서]** (사이트는 브라우저에서 그리는 방식이라 헤드리스 브라우저로 그려서 읽었다)
- 웹 MCP: `claude mcp add --transport http --scope user spritegen https://spritegen.kumastudio.app/mcp`, 구글 로그인, API 키 없음. 무료 도구 `get_balance`·`quote`·`get_result`·`list_results`, 유료 도구 `draw_still`·`make_motion`·`make_direction_set`·`flip_left`. 유료는 견적부터, 견적 10분 유효, 연결당 하루 10,000 크레딧. `claude -p` 같은 헤드리스 실행은 승인 창이 없어 유료 도구가 막히므로 웹에서 "모두 허용" 이 필요. **[문서]**

### 엔진이 하는 일

| 파이프라인 | 들어가는 것 → 나오는 것 | 그리는 모델 |
|---|---|---|
| A 아틀라스 행 | 그림 한 장 + 상태 목록 → 투명 스프라이트 시트 + `manifest.json` | ChatGPT 구독(codex) · grok · OpenAI 키 |
| B 영상 → 반복 동작 | 그림 한 장 → 동작별 투명 GIF·WebP·스트립 | 영상: xAI Grok Imagine (`grok` 로그인 또는 `XAI_API_KEY`), ffmpeg 필요 |
| pixel-draw (실험) | 글 설명 → 8~48px 도트 + `grid.txt` | **Claude 구독** (Opus) |
| 후처리·도구 | 색 바꾸기, Aseprite·Phaser·Flame 내보내기, 반복 타일, 그림자 | — |

- README 의 예시 GIF(사무라이 601×380, 성기사 318×240, 슬라임 294×278)는 **B 영상 파이프라인** 결과다: "one still each, Grok Imagine clip" (README 42행). Claude 가 그린 것이 아니다. **[문서]**
- Unity·Godot 전용 내보내기는 README 에 없다.

### 배울 방법론

- 격자 파일(`grid.txt`)이 원본이고 PNG 는 언제든 다시 만든다.
- 크로마 배경(초록·자홍)으로 그린 뒤 섞인 색을 풀어 진짜 투명으로 만든다(`docs/chroma-alpha.md`).
- `manifest.json.frame_layout` 에 프레임 위치·fps·반복 여부를 적어 엔진이 격자를 추측하지 않게 한다.
- 출고 전에 GIF·컨택트 시트로 움직임을 눈으로 검사한다.
- pixel-draw: 팔레트를 정하고 한 줄씩 쓰게 한다 → 코드가 줄마다 검사하고 깨진 줄만 다시 쓰게 한다 → 후보 여러 장 중 그림을 보는 모델이 고른다.

## 4. pixel-draw 시험 — 32px 기사 **[실측]**

- 설치: 세션 임시 폴더의 Python 가상환경에 `pip install -e`. Claude Code 는 Max 구독으로 로그인.
- 요청: "중세 판타지 기사, 횡스크롤 액션용, 빨간 깃털 강철 투구, 파란 겉옷과 사슬갑옷, 오른손에 검, 둥근 나무 방패, 오른쪽을 보는 옆모습, 준비 자세", 32px, 기본값(후보 2장 · 그림 보고 고르기).
- 결과: [후보 A·B](assets-2d/pixel-draw-knight32/pick-sheet.png) → B 선택 → [8배 확대](assets-2d/pixel-draw-knight32/preview-x8.png) · [원본 32px](assets-2d/pixel-draw-knight32/frame-sprite.png) · [grid.txt](assets-2d/pixel-draw-knight32/grid.txt).
- Opus 호출 3번(후보당 약 165초·약 1만 5천 토큰, 고르기 10초), 전체 176초, 구독 처리로 비용 기록 0달러(구독 사용량에서 빠짐). 검사 모두 통과, 안전 영역(26×26) 초과 참고 알림만.
- 맨손 코드 그림(1절)보다 확연히 낫다 — 깃털·검·방패 무늬·명암.

### pixel-draw 의 한계 (문서 `docs/pixel-draw.md`)

- 만든 사람 측정(2026-10-12, claude-opus-5-5, 250장): 32px 이하 쓸 만함 · 48px 은 8장 중 7장 · 48px 이 측정한 끝.
- 걷기는 몸은 유지되지만 다리가 거의 안 바뀌는 초안.
- 프레임은 한 실행 안에서 4장씩 같은 디자인으로 최대 64장. **이미 만든 캐릭터를 넣고 동작만 그리는 옵션은 없다** — 입력은 글 설명뿐. (엔진 안에 "다음 묶음에 앞 프레임을 보여 주는" 장치가 있어, 우리 판에서 덧붙이기 좋은 기능이다 **[추정]**)

## 5. "캐릭터 하나 → 원하는 동작" 은 어떻게 되나

**스프라이트젠으로 된다(영상 파이프라인).** 영화 촬영에 빗대면:

| 영화 | 스프라이트젠 |
|---|---|
| 배우 | 캐릭터 정지 그림 한 장 |
| 감독의 지시 | 동작 설명 — 예: "검을 오른쪽 위로 들었다가 대각선으로 내리벤다" |
| 촬영 | 영상 모델(xAI Grok Imagine)이 그 캐릭터가 그렇게 움직이는 짧은 영상을 만든다(1~3분) |
| 편집 | 스프라이트젠이 프레임을 뽑고 배경을 지우고 쓸 구간만 자른다. 한 번 하는 동작은 대기 → 동작 → 대기 |

- 걷기·달리기는 설명 없이도 된다(가장 잘하는 동작). 공격 등은 짧은 움직임 설명이 필요하고, 목록에 없는 동작은 가장 가까운 동작을 고르고 직접 설명한다. **[문서]**
- 배우처럼 정확히 따르지는 않는다 — 영상 모델이 지시를 해석해 찍으므로 자세가 매번 조금 다르다. 저장소도 방향조차 "요청할 뿐 보장하지 못한다" 고 적는다. 여러 번 찍어 좋은 컷을 고르는 것, 그리고 큐레이션 화면에서 프레임을 비교·제외·미세 조정하는 것까지가 사람(감독)의 일이다.
- 결과: GIF · 스트립 PNG · 격자 시트 PNG · WebP.

## 6. 가져다 쓰기와 라이선스

- 사용자 방향: 저장소를 받아 방법을 배우고, **우리에 맞게 다시 만들어** 우리 구독으로 쓴다.
- Apache-2.0: 고쳐서 팔아도 된다. **남에게 배포할 때** LICENSE·NOTICE 를 남기고 고쳤다고 표시한다. 우리 안에서만 쓰면 지킬 의무가 거의 없다.
- 코드를 베끼지 않고 방법만 배워 처음부터 새로 짜면 그 코드는 우리 것이다(방법·아이디어에는 저작권이 없다). 원본을 옆에 두고 거의 같게 다시 쓰면 옮겨 쓴 것이 될 수 있으므로, 방법을 문서로 정리한 뒤 그 문서만 보고 짜는 쪽이 안전하다. 판매용이면 마지막 판단은 전문가에게. **[추정]** — 법률 자문 아님.
- 웹 서비스 결과물에 대해 사이트도 "나라에 따라 AI 그림은 저작권 보호를 못 받을 수 있다" 고 적는다.

## 7. 아직 모르는 것

- ChatGPT·xAI 구독이 있는지 — 있으면 일러스트 그림체와 "그림 한 장 → 동작" 을 우리 컴퓨터에서 돌릴 수 있다. 이 컴퓨터에는 지금 codex·grok·ffmpeg·img2webp 가 없고 API 키도 없다. **[실측]**
- 영상 파이프라인과 웹 서비스의 실제 품질·크레딧 소모 — 써 보지 않았다.
- jj-agent-room 에이전트(헤드리스)에서 spritegen MCP 유료 도구가 도는지 — 웹 "모두 허용" 이 필요할 것으로 본다. **[추정]**
- pixel-draw 로 걷기·공격 프레임을 그린 결과 — 그려 보지 않았다.
