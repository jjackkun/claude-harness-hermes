# Claude Code 로 게임 만들기 — 논의 정리 (2026-11-18)

영상 3편과 저장소 1개를 보고 나눈 논의를 질문 순서대로 정리한다.
각 답 끝에 근거의 종류를 붙였다: **[문서]** 저장소 파일에서 읽음 · **[영상]** 영상에서 봄 · **[실측]** 이 컴퓨터에서 실행해 봄 · **[지식]** 원래 알던 내용(이번에 다시 확인하지 않음).

## 1. 엔진 없이 게임을 만들 수 있나?

있다. 게임은 세 가지를 반복한다 — 화면 그리기, 입력 받기, 1초에 60번 상태 바꾸기. 웹 브라우저는 이것을 기본 기능으로 가진다.

| 할 일 | 브라우저 기능 |
|---|---|
| 2D 그리기 | Canvas 2D |
| 3D 그리기 | WebGL (보통 three.js 라이브러리로 씀) |
| 입력 | 키보드·마우스 이벤트 |
| 반복 | `requestAnimationFrame` |
| 소리 | Web Audio |

Claude Code 가 HTML·JavaScript 를 쓰면 브라우저에서 두 번 눌러 바로 하는 게임이 된다. **[지식]**

## 2. 두 방식은 어떻게 다른가?

| | Claude Code Game Studios (Donchitos) | 유니티 공식 스킬 (Unity-Technologies/skills) |
|---|---|---|
| 정체 | 게임 개발용 프로젝트 틀. 폴더째 받아서 그 안에서 `claude` 실행 | 유니티 조작 설명서(스킬) 31~33개. 내 프로젝트에 `npx skills add` 로 넣음 |
| 엔진 | 기본은 브라우저(Web). Godot·Unity·Unreal 은 선택 | 유니티 |
| Claude 가 하는 일 | HTML·JS 를 씀. 점검 때만 헤드리스 브라우저로 화면을 찍음 | 유니티 명령창(CLI)과 "명령을 받아 주는 부품"으로 유니티 안에서 코드 실행 |
| 기획 | 질문 → 기획서 한 장 → 게임까지 해 줌 | 해 주지 않음. 게임 규칙은 Claude 가 알아서 짬 |
| 사람 손 | 질문에 답하기, "Build it" | 유니티 로그인, 확인창 OK, 방향 정하기 |
| 시험 상태 | 브라우저 경로만 블라인드 비교로 시험됨. 엔진 경로는 미시험 (README) | 영상 1편의 실연. 빌드 파일이 켜자마자 죽는 문제 미해결 |

근거: **[문서]** README · `/prototype` 스킬, **[영상]** 영상 3.

- 영상 3은 유니티 MCP(실시간 연결 서버)를 **쓰지 않았다**. 유니티 쪽에서 구독이 필요하다고 해서 스킬과 명령창만 썼다(영상 01:00). **[영상]**
- 영상 1(쇼츠)이 말한 "Godot 먼저 설치"는 최신판(1.3.0)과 다르다. 최신판은 엔진 없이 브라우저 게임을 먼저 만들고, 엔진은 해 본 뒤 고른다. **[문서]**

## 3. 아무 게임이나 되나?

장르는 거의 다 받는다. 첫 결과물은 시작부터 끝까지 짧게 하는 **한 판짜리 조각**이다. **[문서]**

- 장르 시트 69개(`.claude/genres/chipsets/`). 없는 장르도 받는다. 두 장르를 섞어도 된다.
- 한 컴퓨터 2~4인은 된다. 온라인 대전·서버는 만들지 않는다(대신 로컬 판을 만들고 그렇다고 알린다).
- 휴대폰·콘솔·VR 은 브라우저 판으로 만든다.
- 기존 게임 그대로 베끼기는 하지 않는다(그 장르의 새 게임 또는 내 방식을 섞은 게임 중 하나를 묻는다).

### 픽셀아트 중세 판타지 · 횡스크롤 격투

- 장르 시트가 있다: `beat-em-up`(길 따라 여러 적, 적 최소 3종) · `fighting`(1대1). **[문서]**
- 픽셀아트 규칙이 있다(정수 배율, 흐림 끔, 픽셀 크기 하나). **[문서]**
- **한계:** 그림을 코드로 그린다. 안내 문서(`art-direction.md`)가 "고해상도 픽셀·손그림·사실적 그림은 코드로 잘 못 그린다"고 적는다. **[문서]**
- 영상 3이 같은 일을 겪었다. 코드로 찍은 도트는 "눈이 안 갔다". 무료 도트 팩을 붙여도 마찬가지였다. 그래서 "파는 게임처럼 보이는 쪽으로" 3D 로 바꾸고 무료 3D 팩(Kenney·Quaternius, CC0)을 썼다. 영상은 3D 판이 더 낫다고 평가하지 않았다 — 방향을 바꿨다는 사실만 있다. **[영상]**
- 해결: 내 그림 파일을 `references/` 에 넣고 `notes.md` 에 `use` 라고 적으면 그 파일을 게임에 그대로 쓴다. **[문서]**

## 4. 한 줄로 만든다는 말은 맞나?

시작은 한 줄이다. 사람은 두 번 더 답한다. **[문서]**

1. `/prototype 중세 판타지 픽셀 횡스크롤 격투`
2. 질문 최대 8개쯤 → "알아서 해" 로 넘겨도 됨
3. 기획서 한 장 확인 → "Build it"
4. 만들기 → 자동 점검(헤드리스 브라우저로 열고, 키 누르고, 찍음) → 한 번 고침 → 결과 카드("아직 사람이 해 보지 않음")

시간·비용은 README 에 없다. 스킬도 일부러 미리 말하지 않는다.

## 5. 이 컴퓨터에서 바로 되나? (WSL 리눅스)

**[실측]** 2026-11-18.

| 필요한 것 | 상태 |
|---|---|
| Git | 있음 (2.43.0) |
| Python 3 | 있음 (3.12.3) |
| Bash | 있음 (5.2) |
| Claude Code | 있음 (2.1.314) |
| Node.js (권장) | 있음 (v24) |
| jq (권장) | 없음 — 없어도 돌아감 |
| 브라우저 | 리눅스 쪽에 없음. 윈도우 쪽에 Chrome·Edge 있음 |

- 저장소의 화면 찍기 스크립트(`.claude/scripts/page-shot.sh`)는 Git Bash 경로(`/c/...`), 맥 경로, PATH 의 `google-chrome`·`chromium` 등을 찾는다. WSL 의 윈도우 경로(`/mnt/c/...`)는 찾지 않는다. 이 컴퓨터는 PATH 에 브라우저가 없어서 그대로는 못 찾는다. **[문서]** **[실측]**
- 대신 다른 도구가 받아 둔 헤드리스 브라우저가 있다: `~/.cache/hyperframes/chrome/chrome-headless-shell/linux-152.0.7977.30/chrome-headless-shell-linux64/chrome-headless-shell`. 스크립트는 `PAGE_SHOT_BROWSER` 환경변수로 이 경로를 받는다. **이 브라우저로 점검이 실제로 되는지는 아직 돌려 보지 않았다.**
- 유니티는 윈도우 쪽에 깔아야 한다. WSL 안의 Claude 가 윈도우 유니티를 조종하는 일은 확인하지 않았다.

## 6. 출시는 되나?

### 게임 스튜디오 틀이 해 주는 것 **[문서]**

- "공유해 줘" → `prototypes/<이름>/dist/` 를 만든다(조정 슬라이더·작업 파일 제외). itch.io 는 이 폴더 안을 zip 으로 묶어 올린다.
- 게임을 "키우기" 하면 Vite·TypeScript 프로젝트가 되고, 빌드 결과는 정적 호스팅에 올릴 수 있다.
- itch.io·Steam 에 직접 올리지는 않는다. `butler push`·`steamcmd` 는 훅이 경고한다.
- 출시 준비 스킬: `/release-checklist` · `/launch-checklist` · `/patch-notes` · `/cut`.

### three.js(웹) 와 유니티의 출시 차이 **[지식]**

| 목표 | 웹 게임 (three.js·Phaser·Canvas) | 유니티 |
|---|---|---|
| 웹 (itch.io·포털·내 사이트) | 가장 쉬움 | WebGL 빌드로 가능 |
| 스팀 (PC) | Electron·Tauri 로 감싸서 가능. 예: 뱀파이어 서바이버즈는 처음에 Phaser(JS)로 스팀에 나왔고 나중에 유니티로 옮김 | 버튼 하나로 빌드 |
| 모바일 | Capacitor 로 감쌀 수 있으나 느려지기 쉽고 손이 더 감 | **유리함** — 광고·앱 안 결제·스토어 도구가 많음 |
| 콘솔 | 사실상 어려움 | 공식 경로 있음 |

- 중간 선택지로 Godot 가 있다. 무료이고 스팀·모바일 출시를 둘 다 지원한다. 게임 스튜디오 틀도 Godot 를 지원하지만 README 에 따르면 그 경로는 아직 시험되지 않았다.
- 정리: **스팀은 웹으로 충분, 모바일은 유니티가 낫다, 콘솔은 유니티.**
